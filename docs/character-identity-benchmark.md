# 캐릭터 정체성 벤치마킹 및 적용 분석

조사일: 2026-09-30. 공개 서비스 문서·공개 코드·연구 논문을 조사했다. 서비스에 로그인해 대화 품질을 비교한 실험은 수행하지 않았다. 아래에서 공개된 사용 방식과 ANPC에 맞춘 설계 판단을 구분한다. 데이터 계약은 [콘텐츠 규격](content-specification.md), 조립 계약은 [프롬프트 명세](prompt-specification.md), 시험은 [개발·검증 계획](development-validation.md)이 기준이다.

## 1. 실제 서비스와 도구에서 확인한 방식

| 대상 | 공개 자료에서 확인한 방식 | ANPC에 적용할 요소 | 확인하지 못한 부분 |
| --- | --- | --- | --- |
| Character.AI | Definition에 자유 설명과 대화 예시를 넣는다. 예시 발화자를 구분하고 중요한 정의를 앞에 배치하도록 안내한다 | 고정 정체성을 우선 보존하고, 상황별 인물 발화 예시를 실제 대화와 구분한다 | 내부 시스템 프롬프트·학습 데이터·검색·기억 구현과 주디/팬앰 재현 품질 |
| Chub AI | Description, Scenario, Example dialogs, Character's Note, Character Book을 구분한다 | 정체성·현재 상황·예시·인물 지식을 별도 데이터로 관리한다 | 해당 서비스가 ANPC의 행동 권한·퀘스트 보호를 충족하는지 |
| Chub AI Lorebooks | 키워드와 최근 메시지 탐색 깊이로 관련 항목을 활성화한다. 토큰 예산·우선순위·인물별 책을 지원한다 | NPC가 알 수 있는 사실을 먼저 제한하고, 관련 지식만 로컬 검색해 전송한다 | 키워드 일치만으로 지식 정확성이나 한국어 의미 검색 품질이 보장되는지 |
| SillyTavern | 캐릭터 설명·성격·시나리오는 매 생성에 포함한다. 예시는 문맥 공간에 따라 삽입하고 Character's Note는 지정한 대화 깊이에 둔다 | 핵심 정체성을 항상 전달하고, 현재 질문 가까이에 짧은 정체성 요약을 둔다 | 이 배치가 현재 사용하는 모델에서 얼마나 개선되는지 |

Character.AI 근거: [공식 Definition 문서](https://book.character.ai/character-guide/character-attributes/definition). 이름만 지정하거나 외부 문서 URL만 적는 것으로 그 내용을 읽게 만들 수 있다는 근거는 없다. 이 문서는 제작자가 입력하는 정의의 계약이며 서비스가 프롬프트만 사용한다는 증거가 아니다.

Chub 근거: [공식 Character Creation](https://docs.chub.ai/docs/the-basics/character-creation), [공식 Lorebooks](https://docs.chub.ai/docs/advanced-setups/lorebooks). 검색용 태그·Creator's Note와 실제 생성에 쓰이는 정의를 구별한다. ANPC도 검수 메타데이터 전체를 모델에 보내지 않고 생성에 필요한 내용만 컴파일한다.

SillyTavern은 캐릭터 채팅 프런트엔드이며 자체 모델 서비스와 구별한다. 근거: [Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/), [World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/).

## 2. 공개 코드 확인

SillyTavern의 공개 `release` 브랜치 [public/scripts/world-info.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)를 확인했다. 원문 열람은 [raw 파일](https://raw.githubusercontent.com/SillyTavern/SillyTavern/release/public/scripts/world-info.js)로 수행했다.

- `getWorldInfoPrompt`: 활성화된 자료를 앞·뒤·예시·대화 깊이 등의 삽입 위치로 나눠 반환한다.
- `checkWorldInfo`: 문맥 크기에 따른 예산과 절대 상한을 계산하고 캐릭터 필터·활성 항목·예산 초과를 처리한다.
- 이 구현에서 가져오는 것은 인물별 필터 → 관련 항목 선별 → 예산 처리 → 위치별 조립이라는 구조다. 소스 코드를 복사하거나 의존성을 추가하지 않았다.
- 조사 대상은 변경 가능한 브랜치다. 함수 확인은 조사일 기준이며 고정 커밋의 호환성 검증이나 라이선스 검토를 완료했다는 뜻은 아니다.

## 3. 프롬프트 외의 실제 접근

| 접근 | 공개 근거 | ANPC에서의 판단 |
| --- | --- | --- |
| 역할극용 모델 + 캐릭터 정의 | Chub은 DeepSeek V3 0324를 조정한 Soji를 발표하고 모델별 설정 사용을 안내했다 | 모델 자체의 역할극 능력도 품질 변수다. 제작자 서버를 운영할 필요가 있다는 뜻은 아니다 |
| 역할 정보·문체 예시 생성 + 역할 조건부 학습 | RoleLLM은 역할 프로필, 역할 지식 추출, RoleGPT, RoCIT를 구성하고 역할 데이터로 공개 모델을 학습했다 | 인물 자료를 먼저 정리하고, 학습이 필요하면 여러 인물을 구별하는 조건부 데이터로 확장할 수 있다 |
| 인물 경험을 학습 | Character-LLM은 프로필·경험·감정과 역할 이탈을 막는 경험을 학습하는 방식을 연구했다 | 단순 성격 형용사보다 사건에서 어떤 반응을 보였는지가 유용한 자료다. 생성한 가상 경험을 원작 사건으로 등록하지 않는다 |

근거: [Chub 0.5.7 발표](https://docs.chub.ai/docs/patch-notes/0.5.7), [RoleLLM 논문](https://arxiv.org/abs/2310.00746), [Character-LLM 논문](https://arxiv.org/abs/2310.10158).

두 논문의 실험은 한국어 사이버펑크 NPC와 현재 API 모델에 대한 검증이 아니다. 논문이 보고한 향상을 주디·팬앰의 원작 재현 성능으로 환산하지 않는다. 서비스 발표에서도 해당 모델의 내부 학습 자료와 모든 캐릭터의 품질을 확인할 수는 없다.

## 4. ANPC 적용 결정

다음은 위 사례를 게임 모드 제약에 맞춰 선택한 설계다. 효과는 품질 비교 전까지 가설이며, 데이터·조립 규칙은 이번 명세에 반영한다.

1. **불변 정체성:** 직업·핵심 가치·금기·판단 기준을 매 요청에 포함한다. 긴 설정문 전체를 필수 문맥으로 만들지 않는다.
2. **상황별 예시:** 동일한 부탁·압력·갈등에 그 인물이 어떻게 반응하는지를 예시로 작성한다. 현재 인물·관계 단계·인지 범위에 맞는 예시만 선택한다.
3. **인물별 지식 검색:** 승인된 자료를 인물별로 묶고, 한국어 용어·별칭과 현재 화제로 필요한 항목을 찾는다. 공개 조건은 검색보다 먼저 적용한다.
4. **짧은 정체성 상기:** 긴 대화 뒤에도 현재 목표·관계·금기를 놓치지 않도록 승인 카드에서만 요약을 만든다. 플레이어 문장이나 생성 기억을 상위 지침으로 올리지 않는다.
5. **관계와 기억의 분리:** 기억은 최근 대화를 이어주는 자료다. 원작 관계·핵심 신념을 바꾸거나 낯선 V를 가족·연인으로 승격하지 않는다.
6. **로컬 선별 + 생성 1회:** 예시와 지식 선택을 매번 별도 LLM에 맡기지 않는다. 인물 자료 작성·검수는 오프라인 준비 단계로 두고 매 턴 비용은 기존 비용 규격을 따른다.

서비스의 자유로운 서술 행동, 캐릭터별 시스템 지침 덮어쓰기, 정체성의 확률적 누락은 ANPC의 실행 계약으로 가져오지 않는다. 실제 행동은 게임이 제공한 허용 행동에서만 선택한다.

## 5. 주디·팬앰 콘텐츠 제작에 적용

현재 근거는 [CDPR 공식 인물 소개](https://www.cyberpunk.net/en/cyberpunk-2077)에 있는 전문 분야·불의에 대한 태도·노마드 배경·자유와 가족 유대 수준이다. 아래는 그 소개를 바탕으로 한 작성 방향이며 원작 대사 인용이나 완성된 카드가 아니다.

| 층 | 주디 작성 방향 | 팬앰 작성 방향 |
| --- | --- | --- |
| 핵심 근거 | BD 기술·편집, 불의에 대한 태도 | 알데칼도 배경, 자유와 가족 유대 |
| 갈등 예시 후보 | 남의 경험을 임의로 가공하는 부탁 | 동료에게 위험을 떠넘기는 부탁 |
| 검수가 필요한 해석 | 어떤 조건에서 항의·거절·협력하는지 | 자율성과 동료 보호가 충돌할 때의 선택 |
| 단계 자료 | 해당 퀘스트 시점의 목표, V와의 실제 관계 | 해당 퀘스트 시점의 목표, V와의 실제 관계 |
| 한국어 문체 자료 | 실제 장면의 호칭·말끝·설명 방식 | 실제 장면의 호칭·말끝·설명 방식 |

원작 성격을 그대로 유지하려면 장면별 근거가 추가로 필요하다. 각 자료에 퀘스트/장면 식별자, 발화 전후 상황, 관계 조건, 대사 또는 검수 요약, 그 장면에서 관찰한 선택을 기록한다. 팬 제작 카드·위키 해석·모델의 기억을 원작 증거로 자동 승인하지 않는다. 원작에 없는 상황의 반응은 작성자의 해석임을 표시하고 검수한다.

게임이 없는 현재 환경에서는 장면 자료와 관계 조건을 완성한 것으로 처리하지 않는다. 주디·팬앰 이름만 넣고 호출하는 카드는 출시용 정체성 카드로 승인하지 않는다.

## 6. 학습 도입 조건

우선 API 모델에 승인 카드·관련 예시·지식 검색·상기 블록을 조합한다. 같은 평가에서 말투와 판단이 반복해서 흐려지고, 자료 누락·조립 오류를 고쳐도 남는 문제일 때 역할 조건부 미세 조정 또는 로컬 모델 어댑터 학습을 비교 후보로 추가한다.

학습 자료는 인물 ID·불변 정체성·상황·관계 조건·플레이어 입력·검수된 응답을 포함한다. 한 인물의 협력·거절·모름·재접촉·압력 상황을 함께 담고 여러 인물의 같은 상황에 대한 차이를 보존한다. 평가에 쓸 장면·질문은 학습 자료와 분리한다. 필요한 자료 수·학습 방식·하드웨어·비용은 실제 후보 모델과 데이터 검토 후 결정한다.

학습 가중치에는 현재 퀘스트 진행·플레이어 장비·관계·새 대화 기억을 고정하지 않는다. 학습 모델도 런타임 지식 필터와 행동 검사를 거친다. 개인 키로 호출할 수 있는 사용자 측 제공자 또는 사용자 PC의 로컬 추론만 기존 운영 범위에 포함한다. 특정 서비스의 미세 조정 지원·요금·가용성은 도입 시 별도로 확인한다.

## 7. 이번 변경의 적용 범위

콘텐츠 필드·예시 승인·선별·정체성 상기·학습 도입 기준을 설계 문서에 적용했다. 2026-09-30 조사 당시 검색기·새 필드 컴파일러·실카드·학습 모델은 연결하지 않았다. 2026-10-01에 주디·팬앰의 초안 정규화·지식·예시 선별을 [개발용 비교 화면](dialogue-prototype.md#인물-설정과-대화-테스트)에 연결했다. 실제 게임·출시 승인 카드·학습 모델은 아직 연결하지 않았다. 문서 링크와 베이스 템플릿 구조 검사는 구현 품질 시험을 대신하지 않는다.

## 8. 대화 평가 연구와 적용 근거

추가 조사일: 2026-10-01. 아래는 논문의 평가 설계에서 참고한 요소다. ANPC의 점수·가중치·합격선은 논문에서 가져온 검증된 수치가 아니라 프로젝트의 초기 제안이다. 계약은 [대화 정체성 평가 규격](dialogue-evaluation-specification.md), 평가 세트 제작·보정·실행은 [개발·검증 계획](development-validation.md)에 둔다.

| 연구·확인 자료 | 확인한 방식 | ANPC에 적용 | 직접 적용하지 않는 것 |
| --- | --- | --- | --- |
| [RoleLLM / RoleBench, ACL Findings 2024](https://aclanthology.org/2024.findings-acl.878/) | 역할 프로필·역할 지식·발화 스타일을 나누어 구성 | 지식 정확성과 말투를 별도 축으로 판정 | 해당 모델 성과를 한국어 원작 NPC 품질로 환산 |

| [CharacterEval, ACL 2024](https://aclanthology.org/2024.acl-long.638/)·[본문](https://aclanthology.org/2024.acl-long.638.pdf) | 4개 차원·13개 지표. 지식 노출·정확성·환각, 행동·발화 일관성, 대화·매력 등을 나누고 사람 주석 기반 평가 모델을 구성 | 말투·판단·인지·연속성·대화성을 분리하고 사람 판정으로 AI 평가자를 보정 | 중국어 보상 모델의 한국어 적용, 공감·매력 점수로 인물의 거절을 감점 |
| [CoSER, 2025 연구의 v3 본문](https://arxiv.org/html/2502.09082v3) | 원작 기준과 자체 대화 품질을 구분하고 평가자에게 원작 대화·줄거리 등 추가 근거 제공. 사람 평가와 길이 편향 보정 포함 | 생성기와 평가자의 자료 범위를 분리. 원작 충실도와 작성 인물 일관성을 구분 | 문학 대화 시뮬레이션의 점수를 게임 퀘스트·행동 권한 평가로 대체 |
| [Judging LLM-as-a-Judge, MT-Bench / Chatbot Arena](https://arxiv.org/abs/2306.05685)·[v4 본문 3절](https://arxiv.org/html/2306.05685v4) | AI 평가의 위치·장문 선호·자기 선호 편향을 분석하고 비교 순서 변경 등의 영향을 시험 | 구성·모델명을 가린 비교, A/B 순서 교환, 근거 있는 축별 판정, 인간 불일치 조정 | AI 채점 하나를 객관적 정답으로 확정하거나 일반 챗봇 선호를 캐릭터 충실도로 취급 |

CharacterEval의 중국어 캐릭터와 InCharacter의 심리 척도 결과는 주디·팬앰의 한국어 재현 기준이 아니다. CoSER의 원작 참조 평가를 가져오더라도 ANPC의 새 상황에는 유일한 원작 대사가 없으므로 허용 선택·주장 범위를 검수해야 한다. 추론 모델에게 원작 정답을 아는지 묻는 것만으로 기준 자료를 만들지 않는다.

논문들이 공통으로 ANPC의 7개 축이나 80점·90% 합격선을 제안했다는 뜻은 아니다. 이 수치는 파일럿에서 사람의 판정과 맞춰 보정한다. 이번 조사는 평가 방법 설계이며 논문 데이터·보상 모델을 설치하거나 서비스 대화를 실제로 비교한 실험은 수행하지 않았다.

## 9. 최신 인터뷰 결정과 벤치마크 적용 경계

설계 검토 갱신: 2026-10-01. 서비스 조사·논문 결과를 다시 실험한 것이 아니라 ANPC 요구사항을 구체화한 것이다. 핵심 성격은 [Big Five 규격](personality-specification.md), 배경·판단·문체·지식은 기존 분리 구조로 유지한다. 전환 전 세 슬롯 자료와 신규 수치를 자동 환산하지 않는다.

AI 캐릭터 서비스의 자유로운 관계 성장·허구 경험을 그대로 채택하지 않는다. ANPC는 대화 내용을 기억하되 기본 태도·호칭을 현재 원작 관계에 맞춘다. 사소한 일상 창작은 [콘텐츠 정책](content-specification.md#91-사소한-일상-창작-정책) 범위에서 허용하고 세계관·전문 경험·게임 사건으로 승격하지 않는다. 캐릭터 정의·예시·지식 검색 구조만 이 경계에 맞춰 사용한다.

복장 관찰·게임 저장 복원·대사 자막·기존 모드 제스처 연동은 게임 시스템 계약이다. 캐릭터 채팅 서비스의 기억 기능·서술 행동이나 연구의 역할 점수로 게임 구현 가능성을 입증하지 않는다. 최신 시험 사례는 [대화 평가 규격](dialogue-evaluation-specification.md#611-인터뷰-요구사항의-평가-사례)과 [개발 계획](development-validation.md#6-인터뷰-반영과-전체-문서-검토)에 연결한다.
