# ANPC 벤치마크 및 구현 가능성 분석

상태: 공개 소스와 문서에 근거한 설계 검토 (2026-09-29). 이 PC에는 사이버펑크 2077이 없어 실제 게임 동작·버전 호환성·성능은 검증하지 못했다. 요구사항은 [전체 스펙](full-specification.md), 시험 방법은 [개발·검증 계획](development-validation.md)을 따른다.

## 기존 모드에서 확인한 구현 방식

| 사례 | 공개 구현에서 확인한 것 | ANPC에 적용할 판단 |
| --- | --- | --- |
| [Real Talk](https://github.com/swillunderscore/realtalk) | 시선 대상 선택과 거리 제한, 군중·비군중 분류, 군중 위치 유지·플레이어 쪽 회전·복구, 게임에서 얻은 이름·소속·지역·활동·일부 대사/소개를 프롬프트에 합성한다. AI 대화, 기억, 선택적 음성도 제공한다. | 길거리 NPC의 대화 진입과 제어는 선행 구현 근거가 있다. 인물 정보 자동 수집은 기초 자료로 사용하고, 콘텐츠 카드·지식 경계·검증된 행동 목록을 별도로 설계한다. |
| [CP77 ai_npc](https://github.com/Sebajuste/CP77_ai_npc) | 특정 인물의 `bio`, 관계, 의도, 말투, 사실, 변형, 퀘스트 맥락을 수작업으로 정의한다. 행동 레지스트리가 모델에 알릴 동작과 실제 실행을 연결한다. | 커뮤니티 인물의 정체성·퀘스트 단계별 지식표, 행동 권한의 단일 목록을 참고한다. 길거리 대면 대화와 군중 NPC는 별도 구현이 필요하다. |
| [Talk to Me](https://github.com/JoeParker/TalkToMe) | 근처 NPC의 군중 여부, 시야, 워크스팟, 차량 등 조건을 검사해 반응을 유도한다. 생성형 대화는 없다. | 간단한 근접 조건과 상황 필터의 실험 참고 자료로 삼는다. |
| [Responsive NPCs](https://www.nexusmods.com/cyberpunk2077/mods/14800) | 공개 설명상 복장·소속·무장·퀘스트 등에 따른 반응을 제공한다. 소스 구현은 확인하지 못했다. | 플레이어 상태에 따른 반응 요구의 참고 사례로만 취급한다. |

이는 공개 코드·설명 분석이다. ANPC 환경에서 재현된 테스트 결과가 아니다. 코드는 그대로 복사하지 않고 개념과 검증 순서만 참고한다. 사용 조건은 각 저장소의 라이선스를 별도 확인해야 한다.

## 기능별 구현 가능성

| 요구 | 현재 판단 | 근거와 남은 실험 |
| --- | --- | --- |
| 걷는 군중 NPC를 선택해 대화 시작 | **선행 구현 있음 / 게임 검증 필요** | Real Talk의 시선 대상·거리 제한과 군중 처리. 대상이 이동하거나 소멸할 때 UI·세션 종료를 ANPC에서 확인해야 한다. |
| NPC를 잠시 멈추게 하고 방향 전환·복구 | **선행 구현 있음 / 상황별 검증 필요** | Real Talk의 위치 유지·회전·해제 사례. 워크스팟, 퀘스트, 전투, 다른 모드와 충돌하는 경우를 따로 시험해야 한다. |
| 텍스트 대화, AI 호출, 자율 후속 질문 | **구현 가능성이 높음** | 선행 AI 모드의 대화 파이프라인과 일반적인 로컬 브리지 설계로 가능하다. 지연·취소·오류 복구는 ANPC에서 구현·측정한다. |
| 장비·레벨·평판·진척도 반영 | **부분적 근거 / 필드별 검증 필요** | 게임에서 읽을 수 있는 값과 NPC가 알 수 있는 값은 다르다. 장비의 가시성, 퀘스트 단계, 관계 정보의 실제 접근 경로를 필드별로 확인한다. |
| 커뮤니티 인물의 정체성 유지 | **콘텐츠 구현 가능 / 품질 검증 필요** | CP77 ai_npc의 수작업 프로필과 퀘스트 맥락이 설계 근거다. 원작과 모순되지 않는 대사, 해당 시점의 지식, 관계 변화는 사례별 리뷰가 필요하다. |
| 군중 인물의 랜덤 특성 유지 | **세션 안은 가능성이 높음** | 생성 특성을 세션과 살아 있는 NPC 인스턴스에 묶는다. 재생성 후 동일 인물 판정은 보장하지 않는다. |
| 종료 후 근거리 재접촉 기억 | **설계 가능 / 인스턴스 동일성 검증 필요** | 최근 대화한 NPC의 살아 있는 참조와 짧은 요약을 보관하고 재접촉 시 확인한다. 거리만으로 식별하지 않는다. 소멸·지역 언로드·저장 로드 시 폐기 규칙을 시험한다. |
| 세계관 사실을 인물답게 말하기 | **콘텐츠 구축 필요** | 단일 NPC 설명 컬럼에 의존할 수 없다. 게임 레코드, 저널, 샤드·메시지·대사 단서와 작성된 캐릭터 카드를 결합한다. 출처와 퀘스트 단계·인지 범위를 관리해야 한다. |
| 대사에 맞춘 새로운 행동 | **허용된 기존 게임 행동의 조합은 후보** | 레지스트리에 등록하고 사전 조건·중단·복구가 검증된 행동만 실행한다. 임의 신규 애니메이션 생성이나 모든 NPC에 대한 동일한 동작은 근거가 없다. |
| 빠른 NPC 음성 출력과 자막 | **후속 실험** | 음성 모델 연결 자체보다 첫 소리까지의 지연, 게임 출력 경로, 자막 동기, 중단 처리와 인물별 음성 일관성을 실측해야 한다. |

## 관련 기준 문서

인물 정체성과 지식의 데이터 계약은 [콘텐츠 규격](content-specification.md), 행동의 의미와 한도는 [행동 명세](npc-action-scope.md), 시험 방법과 진행 상태는 [개발·검증 계획](development-validation.md)에 정의한다.

## 행동 구현 참고 자료

| 자료 | 확인 범위와 제한 |

| [AMM 배포 코드](https://github.com/MaximiliumM/appearancemenumod/blob/main/Release/bin/x64/plugins/cyber_engine_tweaks/mods/AppearanceMenuMod/init.lua) | 차량·동료 제어 참고. 공식 원저장소로 가정하지 않는다. Director 상세 코드는 열리지 않아 근거에서 제외했다. |
| [Codeware 문서](https://github.com/psiberx/cp2077-codeware/wiki) | 수명 이벤트와 관리 엔티티 생성·삭제·식별. 기존 군중의 영속 ID를 보장하지 않는다. |

HTTP·보안 키 저장소의 실제 어댑터와 NPC 필드 매핑은 아직 구현 결정이 없다. [통신 규격](runtime-specification.md)의 실행 구조는 설계 선택이며 공개 도구로 재현 완료한 결과가 아니다. 구현 시 채택한 코드 커밋·도구 버전과 사용 조건을 기록한다.

**판정:** 핵심 흐름에는 공개 선행 구현이 있어 기술적으로 시도할 근거가 충분하다. 다만 ANPC 전체 요구를 현재 PC에서 구현 완료 또는 게임에서 검증 완료라고 판단할 수는 없다. 첫 위험은 NPC 수명·복구와 동일성, 콘텐츠 위험은 퀘스트 시점과 인물 지식의 정확성이다.
