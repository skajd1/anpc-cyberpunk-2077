# 대화 시제품 사용 및 구현 안내

갱신: 2026-10-01. 게임 없이 프롬프트·응답 검사·세션·임시 기억을 실행하는 개발용 프로그램이다. 실제 NPC 제어와 게임 API 연결은 포함하지 않는다.

## 실행

Node.js 22 이상에서 저장소 루트의 터미널로 실행한다. 추가 패키지를 설치하지 않는다.

```text
npm start
```

브라우저에서 http://127.0.0.1:4173 을 연다. 포트가 사용 중이면 PowerShell에서 `$env:ANPC_PORT = '4174'`를 설정하고 실행한다. 종료는 실행 터미널의 Ctrl+C다.

## 사용할 수 있는 기능

기존 창작 인물 대화는 `/`, 조사 인물 선택·설정 시각화·대화 테스트는 `/compare`다. 아래 일반 기능과 별도로 다음 개발용 비교를 제공한다.

### 인물 설정과 대화 테스트

데스크톱 화면은 왼쪽 설정, 중앙 채팅, 오른쪽 인물 특성의 3열로 배치한다. 채팅 입력은 중앙 하단에 유지하고 각 영역은 독립적으로 스크롤한다. 좁은 화면에서는 영역을 순서대로 재배치한다.

1. 실행한 서버의 `/compare`에서 중앙 답변 영역 상단의 인물 드롭다운으로 테스트 인물을 선택한다. 현재 조사 카드 10명을 제공하며 오른쪽 특성이 함께 갱신된다. 두 번째 드롭다운을 비교 안 함으로 설정하면 한 명만 테스트한다. 이 드롭다운은 계속 표시되어 비교 인물을 다시 추가할 수 있다. 같은 인물을 중복 선택할 수 없으며 응답 대기 중에는 선택을 잠근다.
2. 오른쪽에서 선택한 인물별 신념·욕구·두려움·금기·자기 인식 슬롯에 들어간 짧은 특성 요약을 확인한다. 원본 정체성과 생성 프롬프트는 유지한다.
3. 지식 슬롯에는 실무·전문 분야와 미확인 분야를 우선 표시한다. 모든 분야의 깊이는 접힌 목록에서 확인한다. 깊이는 카드의 인지 상한이며 이번 요청에 주입한 사실이나 원작 검수 점수가 아니다. 실제 선별 항목은 채팅의 요청 상세에서 확인한다.
4. 조사 초안으로 테스트를 켠다. 왼쪽의 대화 조건을 펼쳐 프롬프트 구성·선택한 인물별 단계·공통 관계·생존·자유 상태를 지정한다. 허용되지 않은 상태는 모든 선택 인물의 요청 전에 차단한다. 기본값은 모의 응답이다.
5. 입력창 위 질문 프리셋에서 일상·BD 지식 경계·동료 관련 가치 충돌·관계 강요·이름 알리기·재접촉 확인 질문을 불러온다. 선택은 입력문만 교체하며 전송·대화 초기화·조건 변경을 하지 않는다. 입력문은 수정할 수 있다. 이름 알리기의 기본 이름과 채팅 화자 표시는 PLAYER_V의 V를 사용한다. 기억 질문은 안내에 따라 이름을 알리고 사용자가 종료·재접촉한다.
6. 동일 질문을 보내면 선택한 인물별 독립 대화·기억으로 1~2건 요청한다. 요청 중 경과 시간과 완료 수, 인물별 요청 중·취소 중·완료·실패·취소 상태 및 소요 시간을 표시한다. 완료 응답에는 제공자가 반환한 입력·출력 토큰을 표시한다. 미제공 값은 미제공, 실패·취소는 토큰 미확인으로 표시하며 0으로 추정하지 않는다. 모의 응답은 API 사용 없음으로 표시한다. 금액 환산·누적 원장은 포함하지 않는다. 프롬프트·선별 항목·원시/검사 응답·수동 검수는 요청 상세를 펼쳐 확인하며 의견은 실행 중에만 유지한다.
7. 인물·대화 설정 변경과 초기화는 선택한 대화·기억을 폐기한다. 특성·지식·요청 상세의 펼침과 접기는 대화를 유지한다. 종료 후 재접촉은 동일 인물의 유효 기억을 사용한다.

모의 응답은 선별된 사실을 읽거나 대체 대사를 반환하는 배선 확인용이다. 원작 인물의 실제 말투를 생성하지 않는다. OpenAI 모드에서는 개인 키 또는 환경 키로 선택 인물당 1회, 총 1~2회 호출한다. Codex 모드에서는 기존 로컬 로그인·모델 목록·유지 연결을 사용한다. 자동 재시도·유료 요약·LLM 평가 호출은 추가하지 않았다.

`/api/research`는 manifest에 등록된 모든 인물 카드와 조사 지식·예시를 로컬 브라우저에 제공하며 bootstrap 요청 토큰을 요구한다. `research.js`는 자료를 정규화하고 인지·단계·공개 조건을 먼저 확인한 다음 관련 사실 최대 3개·예시 최대 1개를 선별한다. 선택 입력과 최근 발화 2개의 등록 용어를 우선순위로 사용하며 동률은 ID로 정렬한다. 예시의 작성 입력 용어도 보조로 사용한다. 이 선별은 개발용 기본 구현이며 의미 검색·전체 예산 계산기의 완성판이 아니다.

인물별 지식 프로필 적용 체크는 카드의 분야 상한 안에서만 후보를 허용한다. unknown·누락 분야·요구 깊이 초과 항목은 체크로 활성화할 수 없다. 주디의 BD 전문 지식은 제공하고, 팬앰의 미확인 BD 후보는 제외한다. 카드만 구성에도 분야 상한·경험 창작 금지 지침은 유지한다. 화면에서 화제별 깊이와 제외 ID를 확인할 수 있다. 플레이어 고정 신원은 [콘텐츠 규격](content-specification.md#플레이어-고정-신원)에서 읽어 모든 구성에 포함한다. 조사 인물의 가상 안면·협력 설정에서는 이름 인지를 true로 두고, 기존 창작 인물 화면에서는 false로 둔다. 이 값은 실게임 이름 인지 매핑을 검증한 결과가 아니다. 퀘스트 단계별 실제 인지 변화는 구현하지 않았다. 렐릭은 인지와 공개 조건을 모두 켜야 회피 제한을 제공한다. evasive 지식은 공개할 부분이 작성되지 않았으므로 실제 비밀 내용을 보내지 않고 회피·확인 제약만 보낸다. 검색 필터가 모델의 사전 지식 발화를 완전히 막는다는 보장은 없다.

비교 화면은 초안을 명시적으로 시험하는 개발용 예외다. 원본 카드·판단·예시의 draft, runtime_enabled=false와 정체성 구조 1.0은 유지한다. 한국어 말투·게임 키·관계·단계 매핑의 검수를 우회해 출시 승인하지 않는다. 행동 후보는 빈 배열이며 모든 행동 요청은 차단한다. 인물별 반복 해석 문구는 사실마다 재전송하지 않고 핵심 카드에만 포함한다.

입력 총 토큰 계산·비용 원장·프로필별 출력 한도·정식 평가 실행기는 아직 없다. 표시한 토큰은 실제 제공자 응답의 사용량이며 비용을 금액으로 추정하지 않는다. 실제 모델 품질 비교는 [개발 및 검증 계획](development-validation.md), 채점 기준은 [대화 평가 규격](dialogue-evaluation-specification.md)을 따른다.

### 화면의 확장 계약

인물 이름·단계·성격·지식 목록은 화면 코드에 고정하지 않는다. 새 카드와 해당 인물의 지식·예시를 콘텐츠 계약에 맞게 작성하고 manifest.files에 characters/*.json으로 등록한 뒤 서버를 재시작한다. 집계도 갱신하고 콘텐츠 검사를 통과시킨다. 현재 모듈은 커뮤니티 조사 카드의 개발용 어댑터다. 군중 생성기를 이 화면에 연결하는 작업은 별도 구현 대상이다.

분야의 display_name이 있으면 우선 표시하고, 없으면 공통 표시 사전 또는 원래 ID를 사용한다. 새로운 identity 목록 필드도 ID를 제목으로 표시한다. 카드의 선택적인 표시 요약 계약은 [콘텐츠 데이터 규격](content-specification.md)의 presentation을 따른다. 요약이 없는 슬롯은 원래 identity 목록을 표시한다. 표시용 사전은 profile.js, 순수 데이터 계산은 buildCharacterProfile, DOM 표시는 profile-view.js에서 관리한다. 지식의 허용 판정은 research.js의 knowledgeBlockReason을 생성기와 화면이 함께 사용한다. 표시 목적으로 인지 조건·지식 상한을 재정의하지 않는다. 상한은 콘텐츠 규격이 기준이다.

동시 테스트는 최대 2명으로 유지하며 추가 인물 등록이 요청 수를 증가시키지 않는다. 승인 전 카드의 상태와 행동 비활성 정책은 유지한다. 오른쪽 특성·지식 슬롯은 열람 기능이며 성격·지식 값을 편집하지 않는다.

### 기존 창작 인물 화면

- 인물 선택, 대화 시작·전송·취소·종료와 유휴 종료.
- 조심스러운 배달원·직설적인 주민·창작 중개인 카드. 세 인물 모두 원작 캐릭터가 아닌 시제품용 창작이다.
- JSON 카드 교체. 동일 베이스에 신념·목표·말투·금기·대체 대사를 주입한다.
- 보이는 장비·무기·거리·전투·연출·저장 범위의 가상 상태 변경.
- 세션 시작 시 가상 위치 유지, 승인된 시선·제어 해제·대화 종료의 가상 실행.
- 같은 살아 있는 인스턴스에 대한 10분·최대 16명 메모리 보관과 재접촉. 종료 후 대화를 다시 시작해 “아까 한 말 기억해?”라고 입력한다.
- NPC 재생성·저장 로드·범위 전환·기억 삭제와 늦은 응답 폐기.
- 실제 조립된 프롬프트와 검사된 응답 보기. API 키는 이 화면에 포함되지 않는다.

## 모의 응답과 실제 API

기본 모의 응답은 규칙 기반 예시다. 모델을 호출하거나 AI 콘텐츠 품질을 증명하지 않는다. 무기·장비·특정 입력·기억에 따라 작성된 대사를 반환한다.

실제 대화는 실행 모드를 OpenAI로 바꾸고 개인 API 키를 입력한 뒤 모델 드롭다운에서 선택한다. 기본 선택지는 `gpt-4o-mini`, `gpt-4.1-mini`, `gpt-4.1`이며 공식 API 규격상의 선택지다. 개인 키의 모델 접근 권한과 잔액을 조회한 목록은 아니며 실제 호출 시 확인된다. 다른 모델은 “모델 ID 직접 입력”을 선택한다. 모델은 Responses API의 구조화 출력을 지원해야 한다. 키가 없거나 직접 입력한 모델 ID가 비어 있으면 요청하지 않는다. 전송할 때 인물·최근 대화·인지 가능한 가상 상태를 제공자에 보내며 개인 계정에 이용 요금이 적용된다.

키는 비밀번호 입력 필드와 실행 중 메모리에서만 사용하고 설정·로그·브라우저 저장소에 저장하지 않는다. 키 지우기 또는 페이지 종료로 입력 키를 제거한다. 선택적으로 서버 실행 환경의 OPENAI_API_KEY를 사용할 수 있으며 값은 화면에 반환하지 않는다.

OpenAI 연결은 [공식 Responses 전환 안내](https://developers.openai.com/api/docs/guides/migrate-to-responses)와 [구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 따른다. 실제 개인 키로 호출하는 시험은 아직 수행하지 않았다.

## Codex 로그인 연결

개발 시제품에서 실행 모드를 `Codex · 로컬 로그인`으로 선택할 수 있다. 설치된 CLI로 `codex login`을 실행하고 브라우저에서 계정을 인증한 뒤 화면의 “로그인·모델 목록 새로고침” 버튼을 누른다. 공식 app-server의 `initialize`·`initialized`·`model/list` 절차로 현재 로그인 계정의 선택 가능 모델을 조회한다. 목록을 고정해서 저장하지 않으며 숨김 항목은 제외한다. 드롭다운의 “Codex 기본 모델”은 모델 ID를 지정하지 않고 CLI가 결정하도록 한다. 조회 실패 시 기본 모델 선택지는 유지하고 실패 상태를 표시한다. 개인 API 키는 이 경로에 전달하지 않는다.

GPT-4o mini는 Codex 로그인 목록에서 제공하지 않을 경우 이 모드로 선택할 수 없다. OpenAI 개인 API 키 모드의 `gpt-4o-mini`로 사용한다. 이 모델은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4o-mini)에서 Responses API와 구조화 출력 지원을 명시한다. API와 Codex 로그인은 서로 다른 인증·사용량 경로다.

Windows에서는 Codex 앱에 포함된 `codex.exe`를 찾는다. 다른 설치를 사용하려면 서버 실행 전에 `ANPC_CODEX_BIN`에 실행 파일 경로를 지정한다. 브라우저에는 실행 파일 경로나 인증 값을 반환하지 않는다. 인증 저장·갱신은 공식 CLI가 담당하며 ANPC가 로그인 토큰을 읽거나 복사하지 않는다.

인물·최근 대화·인지 가능한 가상 상황은 표준 입력의 JSON-RPC로 로컬 `codex app-server`에 전달한다. 첫 모델 조회나 생성 시 실행기 하나를 시작하고 초기화한 뒤, 다음 요청에도 같은 프로세스·통신 연결을 유지한다. 모델 목록 조회도 이 연결을 공유한다. app-server는 공식 CLI의 사용자 설정을 읽으며, 생성 요청에는 읽기 전용 샌드박스·명령 실행 기능 비활성화·승인 불가 설정을 명시한다. 개발 저장소는 작업 디렉터리로 제공하지 않는다.

공유 대상은 실행기이며 NPC 대화 이력은 아니다. 각 생성 요청은 `thread/start`의 `ephemeral: true`로 별도 임시 컨텍스트를 만들고 `turn/start`에 현재 프롬프트와 `outputSchema`를 전달한다. 기존 엔진이 인물·기억·허용 행동을 결정한다. 완료된 컨텍스트는 구독을 해제한다. 임시 컨텍스트 누적을 제한하기 위해 64회 처리 후 활성 생성이 없을 때 실행기를 비우고, 다음 요청에서 다시 연결한다. 종료·프로세스 장애 시 연결을 정리하며 다음 요청에서 재연결한다. 실패한 대화를 자동 재전송하지 않는다.

작업용 임시 폴더에는 프롬프트나 출력 스키마를 저장하지 않으며 실행기 종료 시 제거한다. 대화 세션은 임시 메모리에 두지만 제공자 측 데이터 취급은 Codex 계정 정책을 따른다. 기존 단발 CLI 함수는 비교·검사용으로 남아 있으며 화면의 기본 Codex 경로는 유지 연결이다.

응답 제한 시간은 120초, 개별 JSON-RPC 요청 제한은 15초다. 취소·대화 종료 시 `turn/interrupt`로 해당 요청만 중단하고 연결은 유지한다. 중단 요청 실패나 실행기 장애에는 프로세스를 종료한다. 다른 요청의 응답·중단 이벤트를 섞지 않고 기존 늦은 응답 폐기 규칙을 적용한다. Codex 최종 메시지도 API 응답과 동일한 형식·금기·행동 검사를 통과해야 한다.

이 경로는 개발용 연결이다. 계정의 Codex 사용 한도와 모델 접근 권한이 적용되며 실시간 게임 대화의 속도를 보장하지 않는다. 배포 모드의 개인 API 키 우선 방침은 유지한다. [공식 인증 안내](https://developers.openai.com/codex/auth/)와 [비대화형 실행·구조화 출력 안내](https://developers.openai.com/codex/noninteractive/)를 따른다.

서버는 로그인한 Windows 사용자 환경에서 실행해야 한다. 별도의 제한된 실행 환경에서는 운영체제 인증 저장소에 접근하지 못해 로그인 상태가 다르게 보일 수 있다. ANPC에 인증 토큰을 복사해 해결하지 않는다.

실제 연결 시험 결과와 지연 측정은 [개발 및 검증 계획](development-validation.md)에 기록한다.

베이스 템플릿은 [프롬프트 명세](prompt-specification.md)의 텍스트 블록을 읽는다. 코드에 별도 베이스 복사본을 두지 않는다. JSON 스키마는 코드의 응답 계약에서 생성한다.

로컬 HTTP 프로세스는 개발용 실행기다. 127.0.0.1에만 바인딩하고 Host·Origin·요청 토큰을 검사한다. 제작자 운영 서버나 배포 모드의 필수 브리지가 아니다. 게임판에서는 해당 어댑터를 게임 실행 계층으로 교체한다.

## 현재 제한

- 실제 연결은 OpenAI API와 로컬 Codex다. 모델별 실제 품질 판정·권장 목록은 없다.
- 게임 정보는 가상 값이며 보호 상태도 사용자 입력이다. 레벨·평판·퀘스트 단계는 인지 규칙이 없어 대사 입력으로 전달하지 않는다.
- 기존 창작 화면의 지식 목록은 비어 있다. 조사 카드 10명·지식은 `/compare`에 개발용으로 연결했다. 실제 퀘스트별 지식·관계·말투 검수는 남아 있다.
- 기억은 마지막 NPC 발화와 플레이어 주장의 제한된 기록이다. 모델 요약·장기 저장은 없다. 새로고침하면 초기화된다.
- 단기·장기 분리·관련 기억 조회·비동기 정리·저장 시점별 연결은 [NPC 기억 규격](memory-specification.md)의 후속 목표이며 현재 화면·서버에는 구현되지 않았다.
- 출력 검사는 형식·허용 행동·정적 금지 표현만 검사한다. 원작 충돌이나 숨은 사실 환각을 완전히 판별하지 못한다.
- 자동 재시도는 하지 않는다. 오류 후 사용자가 재전송할 수 있다. 응답 제한 시간은 API 15초, Codex 120초다.
- 실제 움직임·워크스팟·음성·게임 저장 데이터에는 접근하지 않는다.
