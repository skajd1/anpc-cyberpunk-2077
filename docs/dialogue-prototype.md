# 대화 시제품 사용 및 구현 안내

갱신: 2026-10-03. 게임 없이 프롬프트·응답 검사·세션·임시 기억을 실행하는 개발용 프로그램이다. 실제 NPC 제어와 게임 API 연결은 포함하지 않는다.

[공통 모듈 입출력 계약](module-interface-specification.md)은 다음 구현이 따를 고정 형식이다. 현재 웹의 카드·raw journal·args 사전·instructions/input은 전환 전 형식이며 아직 공통 Envelope/Call/Reply로 전환하지 않았다. 계약 설계만으로 장기 기억·게임 어댑터를 구현 완료로 표시하지 않는다.

## 최신 명세와 현재 구현의 구분

목표 범위는 [초기 명세](initial-design.md)와 [전체 명세](full-specification.md)를 따른다. /compare는 최신 인터뷰 요구를 모의 입력으로 시험하며 실제 게임 수집·저장·모션 실행의 완성을 의미하지 않는다.

| 목표 | 현재 시제품의 경계 |
| --- | --- |
| 추가 대화 선택지 진입 | 질문 전송 시 조건 검사·모의 제어 반환 후 자동 진입. 진입 자체에는 API 호출 없음. 게임 선택지 미연결 |
| NPC 대사 자막 | 검사된 대사 텍스트·화자 표시. 게임 자막/세계 시간·음성 미연결 |
| 실제 복장 텍스트·이전 목격 | 이름/외형 텍스트와 관찰 여부 입력·인물별 목격 사건·최근 두 복장 조회. 실제 아이템 수집 미연결 |
| 진행도·원작 관계 | 12명의 63개 분기에 퀘스트·선택·접촉·장면 조건 적용. 8개 프리셋 및 기억 되돌림/늦은 응답 차단. 실제 게임 매핑 미연결 |
| 저장별 고유 인물 기억 | 브라우저에 NPC별 원문·요약 및 슬롯 A/B 저장/복원. 새로고침 후 유지. 실제 게임 저장 연동 미구현 |
| 공개 평판·일상 창작 | 이름 인지 모의 플래그·배경 안의 자기보고 정책. 공개 행적은 미등록이며 실제 임계·정식 정책 자료/의미 검사 미구현 |
| 추가 행동 선택 | play_gesture 후보 3개 선택만 표시·성공 사건 없음. 기본 제어는 가상 실행. 실제 모드 어댑터 미구현 |
| 신규 Big Five | 인물 12명의 작성 수치·군중 2명의 seed 생성 수치 → 공통 변환 문구 5개 연결. 원작·원형 출시 검수 미완료 |

모의 응답은 배선 확인용이며 원작 말투·모델 품질의 증거가 아니다. 개발용 Codex 연결은 유지하고 배포의 개인 API 키 우선 정책을 바꾸지 않는다.

모델 대사의 쿠션어·말줄임표·문장 분할은 표시와 원문 기억에 그대로 보존한다. 인물별 문체와 베이스 0.10에서 조건부 사용을 지정하며 후처리로 덧붙이지 않는다. 실제 음성의 억양·속도 제어는 미구현이다.

## 실행

Node.js 22 이상에서 저장소 루트의 터미널로 실행한다. 추가 패키지를 설치하지 않는다.

```text
npm start
```

브라우저에서 http://127.0.0.1:4173 을 연다. 포트가 사용 중이면 PowerShell에서 `$env:ANPC_PORT = '4174'`를 설정하고 실행한다. 종료는 실행 터미널의 Ctrl+C다.

## 사용할 수 있는 기능

`/`와 `/compare`는 같은 인물 대화 테스트 화면이다. 중복된 이전 창작 인물 화면으로 가는 링크를 제거했다. 이전 화면의 소스와 엔진 검사는 보관한다.

### 인물 설정과 대화 테스트

기본 화면은 캐릭터 목록·채팅·선택 인물의 특성으로 구성한다. 1100px 이하에서는 인물 정보를 버튼으로 열고, 740px 이하에서는 캐릭터 목록도 선택 창으로 연다. 두 인물의 답변은 넓은 화면에서 나란히, 작은 화면에서 세로로 표시한다.

1. 왼쪽 목록에서 인물을 선택한다. 상단에서 1명 대화/2명 비교를 전환한다. 비교 모드의 첫 번째/두 번째 버튼으로 바꿀 자리를 고른다. 인물끼리 이어 말하는 그룹 대화는 아니다.
2. 메시지를 입력하고 Enter 또는 보내기를 누른다. Shift+Enter는 줄바꿈이다. 시작 화면의 질문과 입력창 아래 질문 예시는 입력만 채우며 자동 호출하지 않는다.
3. 대화는 오래된 메시지부터 시간순으로 이어진다. 인물 정보에는 배경·현재 V와의 관계·다섯 성격·개인 원칙·말투·주요 지식 분야를 표시한다. 2명 비교에서도 특성은 한 명씩 전환해 본다.
4. 연결 설정에서 모의 응답/OpenAI/Codex와 모델을 고른다. 상황 설정 또는 ‘관계 단계 바꾸기’에서 인물별 원작 분기를 선택한다. 연애 자격·선택 조건은 함께 표시한다. 사망·연락 단절 등 대화 불가 분기는 호출 전에 차단한다. 구성·인지 조건·전투·저장/로드·전체 초기화는 고급 시험에 둔다.
5. 응답의 ··· 메뉴 → 응답 기록에서 사용량·수동 판정·메모·선별한 지식·기억·당시 프롬프트를 확인한다. 합산 결과표와 기본 화면의 요청 상세는 제거했다. 원본 복사본과 메모는 페이지 수명 동안 유지한다.
6. 재접촉은 대화를 끝내고 기억을 유지한다. 새 대화는 선택한 인물의 기억을 지우고 화면을 새로 시작하며 다른 인물의 기록은 유지한다. 새로고침은 모든 페이지 결과·메모·모의 저장을 지운다.

완료 응답의 토큰은 제공자가 반환한 값이다. 미제공은 미제공, 실패·취소는 토큰 미확인으로 표시하며 0으로 추정하지 않는다. 모의 응답은 API 사용 없음으로 표시한다. 금액 환산·누적 비용 원장은 포함하지 않는다.

### 모의 상황과 기억 시험

- 복장: 등록된 예시 세 개 또는 직접 입력한 이름/외형 설명을 사용한다. 직접 입력의 빈 값·한도 초과는 관찰 불명이다. 진입/요청 시 관찰 가능하면 인물의 목격 사건으로 기록하며 보지 못한 중간 복장은 기록하지 않는다. 모델에는 아이템 식별자·능력치·원시 평판 수치를 보내지 않는다.
- 과거 관찰: 현재 복장과 같은 NPC의 최근 복장 관찰 두 개를 전달한다. 반응 지시·changed 플래그·전달 후 소비는 없으며 언급 여부는 모델이 판단한다. 같은 이름의 옷도 원본 외형 설명을 보존한다. 변경만으로 추가 API를 호출하지 않는다. 현재값과 중복된 관찰의 제거·이전 만남 기준·외형/무장·장기 검색은 [기억 규격 1.3](memory-specification.md)의 목표 정책이며 현재 웹의 완성 기능이 아니다.
- 관계·단계: 현재 선택 값에서 관계·목표를 재계산한다. 플레이어의 연인 주장·모델 자기보고를 원작 관계로 반영하지 않는다. 원작 과거 사건 매핑은 없어 known_past_events는 빈 배열이다.
- 공개 평판: 이름 인지 확인 플래그만 모의한다. 임의 수치 임계를 만들지 않으며 공개 행적은 미등록이다. 군중 예시에서 플래그를 끄면 자기소개 전 이름을 모르는 조건을 시험한다. 자기소개는 player_claim으로 남긴다.
- 일상 창작: 배경·현재 목표 안의 사소한 자기보고 허용 여부와 금지 범위를 제공한다. NPC 발화는 npc_statement이며 원작 사실·새 경력·전문 경험·실제 게임 결과로 승격하지 않는다. 모델의 의미적 준수는 수동 검수 대상이다.
- 행동: 기본 시선·제어 해제·종료는 가상 제어다. test_nod/test_shrug/test_wave는 고개 끄덕임/어깨 으쓱임/손 흔들기의 개발용 의미 참조이며 실제 자산이 아니다. play_gesture는 별도 ‘행동 선택 · 실행 안 함’ 표시만 만들며 실행 성공·last_action_result를 만들지 않는다.
- 저장: 슬롯 A/B는 페이지 메모리에만 존재한다. 저장 시 완료된 커뮤니티 사건·현재 상황을 복사하고 로드 시 이후 기억·대기 응답을 폐기한다. 군중 인스턴스·개인 기억은 승계하지 않는다. 선택 변경으로 화면에서 빠진 고유 인물 기록도 저장 대상이다.
- 기억: 원문 시험 저장소는 인물당 최대 512개 사건이다. 최근 발화 6개와 최근 두 복장 관찰을 요청에 선별한다. memory_view_version=1.2의 일부 조회 형태를 사용하지만 long_term은 비어 있다. GC/비동기 요약·장기 검색·정식 용량 정책은 미구현이다. 추가 요약/평가 호출 비용은 없다. 군중은 종료 후 10분·재생성·로드 경계에서 기억을 폐기한다.

모의 응답은 선별된 사실을 읽거나 대체 대사를 반환하는 배선 확인용이다. 원작 인물의 실제 말투를 생성하지 않는다. OpenAI 모드에서는 개인 키 또는 환경 키로 선택 인물당 1회, 총 1~2회 호출한다. Codex 모드에서는 기존 로컬 로그인·모델 목록·유지 연결을 사용한다. 자동 재시도·유료 요약·LLM 평가 호출은 추가하지 않았다.

`/api/research`는 manifest에 등록된 모든 인물 카드와 조사 지식·예시를 로컬 브라우저에 제공하며 bootstrap 요청 토큰을 요구한다. `research.js`는 자료를 정규화하고 인지·단계·공개 조건을 먼저 확인한 다음 관련 사실 최대 3개·예시 최대 1개를 선별한다. 선택 입력과 최근 발화 2개의 등록 용어를 우선순위로 사용하며 동률은 ID로 정렬한다. 예시의 작성 입력 용어도 보조로 사용한다. 이 선별은 개발용 기본 구현이며 의미 검색·전체 예산 계산기의 완성판이 아니다.

인물별 지식 프로필 적용 체크는 카드의 분야 상한 안에서만 후보를 허용한다. unknown·누락 분야·요구 깊이 초과 항목은 체크로 활성화할 수 없다. 주디의 BD 전문 지식은 제공하고, 팬앰의 미확인 BD 후보는 제외한다. 카드만 구성에도 분야 상한·경험 창작 금지 지침은 유지한다. 응답 기록에서 화제별 깊이와 제외 ID를 확인할 수 있다. 플레이어 고정 신원은 [콘텐츠 규격](content-specification.md#플레이어-고정-신원)에서 읽어 모든 구성에 포함한다. 조사 인물의 가상 안면·협력 설정에서는 이름 인지를 true로 두고, 기존 창작 인물 화면에서는 false로 둔다. 이 값은 실게임 이름 인지 매핑을 검증한 결과가 아니다. 퀘스트 단계별 실제 인지 변화는 구현하지 않았다. 렐릭은 인지와 공개 조건을 모두 켜야 회피 제한을 제공한다. evasive 지식은 공개할 부분이 작성되지 않았으므로 실제 비밀 내용을 보내지 않고 회피·확인 제약만 보낸다. 검색 필터가 모델의 사전 지식 발화를 완전히 막는다는 보장은 없다.

비교 화면은 초안을 명시적으로 시험하는 개발용 예외다. 원본 카드·판단·예시의 draft, runtime_enabled=false와 정체성 구조 1.0은 유지한다. 한국어 말투·게임 키·관계·단계 매핑의 검수를 우회해 출시 승인하지 않는다. 기존 createResearchEngine의 행동 차단은 유지하고 ScenarioEngine만 명시한 시험 행동 후보를 제공한다. 인물별 반복 해석 문구는 사실마다 재전송하지 않고 핵심 카드에만 포함한다.

입력 총 토큰 계산·비용 원장·프로필별 출력 한도·정식 평가 실행기는 아직 없다. 표시한 토큰은 실제 제공자 응답의 사용량이며 비용을 금액으로 추정하지 않는다. 실제 모델 품질 비교는 [개발 및 검증 계획](development-validation.md), 채점 기준은 [대화 평가 규격](dialogue-evaluation-specification.md)을 따른다.

### 화면의 확장 계약

인물 이름·단계·성격·지식 목록은 화면 코드에 고정하지 않는다. 새 카드와 해당 인물의 지식·예시를 콘텐츠 계약에 맞게 작성하고 manifest.files에 characters/*.json으로 등록한 뒤 서버를 재시작한다. 집계도 갱신하고 콘텐츠 검사를 통과시킨다. 기존 prototype/personas.json의 군중 2명은 withTestCrowds로 개발용 조사 형식에 연결한다. Big Five 수치는 원형별 가중치·금지 조합·유효 기본값과 seed로 로컬 생성한다. 같은 인스턴스에서 고정하며 모델에는 숫자·추첨 자료를 보내지 않는다. 생활 관심사는 별도로 유지한다. 군중 지식 배분과 실제 NPC 매핑은 미연결이다.

분야의 display_name이 있으면 우선 표시하고, 없으면 공통 표시 사전 또는 원래 ID를 사용한다. 핵심 성격은 고정된 다섯 축의 실제 수준을 막대와 짧은 설명으로 표시하고, 전체 지침은 도움말로 제공한다. 개인 원칙·말투·전문/실무 분야만 기본 표시하며 목표·전체 지식 목록·프롬프트 메타데이터는 기본 화면에서 제외한다. 군중은 진입 전 대화 시 생성으로 표시하고 진입 후 실제 인스턴스 수치를 표시한다. presentation은 역할 요약에만 사용한다. 기존 identity 슬롯은 표시·전송하지 않는다. 표시용 사전은 profile.js, 순수 데이터 계산은 buildCharacterProfile, DOM 표시는 profile-view.js에서 관리한다. 지식의 허용 판정은 research.js의 knowledgeBlockReason을 생성기와 화면이 함께 사용한다. 표시 목적으로 인지 조건·지식 상한을 재정의하지 않는다. 상한은 콘텐츠 규격이 기준이다.

동시 테스트는 최대 2명으로 유지하며 추가 인물 등록이 요청 수를 증가시키지 않는다. 승인 전 카드의 상태를 유지한다. 오른쪽 특성·지식 슬롯은 열람 기능이며 성격·지식 값을 편집하지 않는다.

### 이전 화면의 보관 범위

이전 index.html·app.js와 창작 인물 엔진은 회귀 검사를 위해 남긴다. 사용자 화면은 위 테스트 흐름으로 통합했다. 원작 어댑터·영구 기억·실제 자막과 모션 실행은 추가하지 않았다.

## 모의 응답과 실제 API

기본 모의 응답은 규칙 기반 예시다. 모델을 호출하거나 AI 콘텐츠 품질을 증명하지 않는다. 무기·장비·특정 입력·기억에 따라 작성된 대사를 반환한다.

실제 대화는 실행 모드를 OpenAI로 바꾸고 모델을 선택한다. 기본 모델은 `gpt-4.1-mini`다. 선택지는 [모델 등록표](../prototype/public/api-models.js)의 8개와 “모델 ID 직접 입력”이다. 계정별 접근 권한·잔액은 조회하지 않으며 직접 입력한 모델의 구조화 출력·추론 지원은 별도 확인한다. 저장된 키나 입력한 키가 없거나 직접 입력한 모델 ID가 비어 있으면 요청하지 않는다. 인물·최근 대화·인지 가능한 가상 상태를 제공자에 보내며 개인 계정에 이용 요금이 적용된다.

OpenAI 추론 설정은 `none`이 기본이며 모델별로 지원하는 `none`, `low`, `medium`, `high`, `xhigh`, `max`를 선택한다. 비추론 모델은 `none`으로 고정하고 API의 `reasoning` 필드를 생략한다. `none` 미지원 모델을 직접 입력하면 지원하는 값을 선택해야 한다. 설정은 요청 시점에 고정하며 응답 기록에 모델·설정·제공된 추론 토큰 수를 표시한다. Codex 설정에는 적용하지 않는다. [추론 API 규격](https://developers.openai.com/api/docs/guides/reasoning).

`none`과 비추론 모델은 최대 출력 512토큰·대기 15초, 나머지는 최대 출력 8,192토큰·대기 60초다. 출력 한도는 내부 추론 토큰도 포함한다. 모델·추론 설정은 대사 길이·응답 계약·프롬프트 본문을 변경하지 않는다.

조립기 0.16는 반복 지침을 통합하고 전체 응답 스키마를 제공자의 구조화 출력 설정에만 둔다. 본문에는 출력 필드의 의미·값을 안내한다. 대체 대사·미사용 행동 선호·revision·미선별 예시·시험 저장소 정보·배경의 작성 검수 provenance·전체 지식 분야표는 로컬에 보존하고 전송에서 제외한다. 성격·말투·현재 관계·화제별 지식 상한/응답 제한·선별 사실·기억·관찰·행동 후보는 유지한다. 웹 저장 형태는 유지하며 목표 공통 계약으로의 전체 전환은 미완료다.

서버 실행 시 저장소 루트의 `.env`를 자동으로 읽는다. 로컬 파일에 `OPENAI_API_KEY`를 설정하면 웹에 매번 입력하지 않아도 사용하며, 변경은 서버 재시작 후 반영한다. 기존 실행 환경의 `OPENAI_API_KEY`가 있으면 그 값을 우선한다. `.env`는 Git에서 제외하고 `.env.example`에는 빈 형식만 보관한다. 키 값은 웹 응답·로그·브라우저 저장소에 넣지 않는다.

브라우저 입력 키는 실행 중 메모리에만 보관하며 해당 요청에서 서버 키보다 우선한다. 키 지우기 또는 페이지 종료는 입력 키만 제거하고 `.env`의 키는 삭제하지 않는다. 저장된 키가 있으면 입력 필드를 비워 두면 된다.

키 저장 여부는 연결 성공 여부와 다르다. 서버를 외부 통신이 제한된 실행 환경에서 시작하면 키가 있어도 요청이 차단된다. 이 경우 키를 다시 저장하는 대신 외부 연결이 허용된 터미널에서 서버를 실행한다. 연결 권한 차단은 별도 안내하며 인증 실패·일반 연결 실패와 구별한다. 서버 재시작 후에는 페이지를 새로고침해 요청 토큰을 갱신해야 한다. 새로고침 전 보관할 테스트 결과는 복사한다.

OpenAI 연결은 [공식 Responses 전환 안내](https://developers.openai.com/api/docs/guides/migrate-to-responses)와 [구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 따른다. 2026-10-02에 저장된 개인 키의 모델 목록 조회 인증을 확인했다. 실제 유료 대화 생성 시험은 수행하지 않았다.

## Codex 로그인 연결

개발 시제품에서 실행 모드를 `Codex · 로컬 로그인`으로 선택할 수 있다. 설치된 CLI로 `codex login`을 실행하고 브라우저에서 계정을 인증한 뒤 화면의 “로그인·모델 목록 새로고침” 버튼을 누른다. 공식 app-server의 `initialize`·`initialized`·`model/list` 절차로 현재 로그인 계정의 선택 가능 모델을 조회한다. 목록을 고정해서 저장하지 않으며 숨김 항목은 제외한다. 드롭다운의 “Codex 기본 모델”은 모델 ID를 지정하지 않고 CLI가 결정하도록 한다. 조회 실패 시 기본 모델 선택지는 유지하고 실패 상태를 표시한다. 개인 API 키는 이 경로에 전달하지 않는다.

GPT-4o mini는 Codex 로그인 목록에서 제공하지 않을 경우 이 모드로 선택할 수 없다. OpenAI 개인 API 키 모드의 `gpt-4o-mini`로 사용한다. 이 모델은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4o-mini)에서 Responses API와 구조화 출력 지원을 명시한다. API와 Codex 로그인은 서로 다른 인증·사용량 경로다.

Windows에서는 Codex 앱에 포함된 `codex.exe`를 찾는다. 다른 설치를 사용하려면 서버 실행 전에 `ANPC_CODEX_BIN`에 실행 파일 경로를 지정한다. 브라우저에는 실행 파일 경로나 인증 값을 반환하지 않는다. 인증 저장·갱신은 공식 CLI가 담당하며 ANPC가 로그인 토큰을 읽거나 복사하지 않는다.

인물·최근 대화·인지 가능한 가상 상황은 표준 입력의 JSON-RPC로 로컬 `codex app-server`에 전달한다. 첫 모델 조회나 생성 시 실행기 하나를 시작하고 초기화한 뒤, 다음 요청에도 같은 프로세스·통신 연결을 유지한다. 모델 목록 조회도 이 연결을 공유한다. app-server는 공식 CLI의 사용자 설정을 읽으며, 생성 요청에는 읽기 전용 샌드박스·명령 실행 기능 비활성화·승인 불가 설정을 명시한다. 개발 저장소는 작업 디렉터리로 제공하지 않는다.

공유 대상은 실행기이며 NPC 대화 이력은 아니다. 각 생성 요청은 `thread/start`의 `ephemeral: true`로 별도 임시 컨텍스트를 만들고 `turn/start`에 현재 프롬프트와 `outputSchema`를 전달한다. 기존 엔진이 인물·기억·허용 행동을 결정한다. 완료된 컨텍스트는 구독을 해제한다. 임시 컨텍스트 누적을 제한하기 위해 64회 처리 후 활성 생성이 없을 때 실행기를 비우고, 다음 요청에서 다시 연결한다. 종료·프로세스 장애 시 연결을 정리하며 다음 요청에서 재연결한다. 실패한 대화를 자동 재전송하지 않는다.

작업용 임시 폴더에는 프롬프트나 출력 스키마를 저장하지 않으며 실행기 종료 시 제거한다. 대화 세션은 임시 메모리에 두지만 제공자 측 데이터 취급은 Codex 계정 정책을 따른다. 기존 단발 CLI 함수는 비교·검사용으로 남아 있으며 화면의 기본 Codex 경로는 유지 연결이다.

응답 제한 시간은 120초, 개별 JSON-RPC 요청 제한은 15초다. 취소·대화 종료 시 `turn/interrupt`로 해당 요청만 중단하고 연결은 유지한다. 중단 요청 실패나 실행기 장애에는 프로세스를 종료한다. 다른 요청의 응답·중단 이벤트를 섞지 않고 기존 늦은 응답 폐기 규칙을 적용한다. Codex 최종 메시지도 API 응답과 동일한 형식·금기·행동 검사를 통과해야 한다.

이 경로는 개발용 연결이다. 계정의 Codex 사용 한도와 모델 접근 권한이 적용되며 실시간 게임 대화의 속도를 보장하지 않는다. 배포 모드의 개인 API 키 우선 방침은 유지한다. [공식 인증 안내](https://developers.openai.com/codex/auth/)와 [비대화형 실행·구조화 출력 안내](https://developers.openai.com/codex/noninteractive/)를 따른다.

서버는 로그인한 Windows 사용자 환경에서 실행해야 한다. 별도의 제한된 실행 환경에서는 운영체제 인증 저장소에 접근하지 못해 로그인 상태가 다르게 보일 수 있다. ANPC에 인증 토큰을 복사해 해결하지 않는다.

실제 연결 시험 결과와 지연 측정은 [개발 및 검증 계획](development-validation.md)에 기록한다.

## 현재 제한

- 실제 연결은 OpenAI API와 로컬 Codex다. 모델별 실제 품질 판정·권장 목록은 없다.
- 게임 정보는 가상 값이며 보호 상태도 사용자 입력이다. 원시 레벨·평판 수치는 전달하지 않는다. /compare는 이름 인지 모의 판정과 선택 단계의 작성 목표·관계를 전달한다.
- 기존 창작 화면의 지식 목록은 비어 있다. 조사 카드 12명·지식은 `/compare`에 개발용으로 연결했다. 실제 퀘스트별 지식·관계·말투 검수는 남아 있다.
- 비교 화면은 최근 6개 발화, 선별한 장기기억, 과거 복장 관찰을 전달한다. OpenAI 모드의 이전 대화는 모델로 요약하며 브라우저에 원문·기억·모의 저장 슬롯을 보관한다. 모의 응답에서는 원문 추출을 사용한다.
- 전체 단기/장기 조회·비동기 정리·실게임 저장 연결은 [NPC 기억 규격](memory-specification.md)의 첫 게임판 목표다. 모의 슬롯 복원과 일부 조회 모양이 정식 워커·저장소 구현을 대신하지 않는다.
- 출력 검사는 형식·허용 행동·정적 금지 표현만 검사한다. 원작 충돌이나 숨은 사실 환각을 완전히 판별하지 못한다.
- 자동 재시도는 하지 않는다. 오류 후 사용자가 재전송할 수 있다. 응답 제한 시간은 API 15초, Codex 120초다.
- 실제 움직임·워크스팟·음성·게임 저장 데이터에는 접근하지 않는다.

## Big Five 조립과 전달 (2026-10-02)

인물 12명의 core_personality와 personal_principles는 원작 수치가 아닌 독립적인 작성 초안이다. 숫자 다섯 개를 personality-prompt-1.0의 문구 다섯 개로 로컬 변환한다. 변환표는 Big Five 규격 4절과 정확히 일치하는지 자동 검사한다. 누락·범위 밖·실수·추가 축은 context_unavailable로 차단하며 기존 identity나 중간값으로 대신하지 않는다.

조립 순서는 공통 베이스 → 인물(성격 문구·개인 원칙·말투·목표·관계·지식 상한) → 선택 예시 → 현재 상황·관련 지식·기억 → 개인 원칙/금기/목표/관계 상기 → 최근 user/assistant 발화 → 현재 질문이다. OpenAI는 instructions와 input을 분리한다. 현재 웹의 Codex app-server는 베이스를 thread/start.developerInstructions에, 인물·상황·질문을 turn/start.input에 둔다. 과거 일회성 CLI 실행 소스는 호환 검사만 보존하며 현재 웹 생성 경로로 사용하지 않는다. [공식 app-server 문서](https://learn.chatgpt.com/docs/app-server)의 입력·출력 스키마와 로컬 실행기 계약을 따른다.

요청 상세의 실제 전송 프롬프트에는 instructions·input만 표시한다. 수치·표 버전·프롬프트 버전은 로컬 성격·버전 정보로 따로 표시한다. 원본 수치·기존 identity·seed·가중치·전체 25문구는 모델에 전달하지 않는다. 성격 문구를 identity_reminder에 중복하지 않는다.

실제 토큰 총예산 적용·게임 상태 매핑·게임 행동 실행은 후속 작업이다. 기억 요약/검색과 원작 관계 사건의 테스트 웹 적용은 아래 절을 따른다. 이번 변경은 실제 모델 품질이나 인물 수치의 원작 적합성을 검수한 결과가 아니다.

## 최근 대화·장기기억·세계관 적용

- 최근 대화: 시간순 user/assistant 메시지. context에 중복 전달하지 않음. 베이스·조립기 0.16.
- 기억: 8회 성공 대화마다 이전 발화를 정리하고 질문에 관련된 요약/원문을 전달. 상세 설정의 기억·저장 시험에서 상태·요약 사용량·수동 정리 확인.
- 저장: community 기억과 모의 슬롯은 같은 브라우저·같은 주소에서 유지. 군중 기억·진행 호출·키는 저장하지 않음.
- 조니: 렐릭 인격·6개 원작 관계 분기·개인 지식·작성 문체. 독립된 육체의 제스처/물리 행동 없음. 출시용 렐릭 어댑터 미구현.
- 세계관: 11개 범주의 공통 핵심 상식 일괄 주입 + 관련 세부 사실 최대 3개. 비공개·단계·전문성 필터 적용.

## 퀘스트 진행 시험

상황 설정의 기본값은 퀘스트 진행과 접촉 상태 확인이다. 본편 진행 상황을 고른 뒤 선택 인물의 관계 단계와 현재 접촉을 확인한다. 세부 퀘스트·원작 선택을 따로 변경할 수 있다. 인물 정보에 지원 여부와 차단 이유가 표시된다. 관계 카드만 따로 시험하면 퀘스트 판정 없이 기존 초안 말투를 비교한다. 모드 전환·진행 되돌림·확정 분기 변경은 기억을 지운다. 모의 저장은 진행 조건도 함께 복원한다.

지원 범위·게임 연결의 미검증 사항은 [진행도 분석](story-progression-analysis.md)을 따른다. 정책 무결성 검사는 `npm run check:story`다.
