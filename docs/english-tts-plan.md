# 영어 NPC 음성 생성·모델 학습 계획

작성: 2026-10-20

## 1. 목표와 전제

현재 제품 계약은 한국어 자막 + 일본어 음성이고 `voice_language=ja`가 고정이다. 영어는 이 계약을 대체하지 않는 선택 확장안이다. 아래 단계는 미구현 계획이며, 영어 음성의 출력 언어·배포 요건은 구현 전에 UF-73의 언어 선택 반응과 필요 시 새 UF ID, 음성 출력·프롬프트·콘텐츠·공통 계약·DIST-23/24에 확정한다. 한국어 자막과 기존 대화·기억·행동 계약은 그대로 사용한다. 영어를 선택한 요청에만 영어 `speech_text`를 만들고, 언어 변경은 현재 대사가 끝나거나 중단된 뒤 다음 요청부터 적용한다.

## 2. 단계별 계획

| 단계 | 작업과 산출물 | 통과 조건 |
| --- | --- | --- |
| E0. 재현 환경·가능성 | 저장소 밖에 있는 GPT-SoVITS 기본/v1 가중치·학습 자료·Genie 변환기·개발 TTS 보조 프로세스의 위치와 버전을 확인한다. 영어 원작 참조 WAV·같은 `string_id`의 영어 대본으로 기본 모델과 일본어 v1의 짧은 제로샷 합성을 비교한다. Genie의 영어 텍스트 처리·ONNX 변환·스트리밍이 실제로 되는지 확인한다 | 영어 참조와 대본이 맞고 3명 이상에서 합성·청취가 가능하다. 불가능하면 학습을 시작하기 전에 엔진/언어 지원 문제를 해결한다 |
| E1. 영어 대사 생성 | 언어 선택을 요청 문맥에 넣고 영어 구어 `speech_text`를 한국어 `dialogue`·`follow_up`보다 먼저 생성한다. 영어판 원작에서 인물별 호칭·축약·욕설 강도·말투와 짧은 예시를 검수하고, 고유명사 발음표를 별도로 만든다. 일본어 `ja_voice`·`ja_readings`는 영어 요청에 전달하지 않는다 | 주디·빅터·로그 각 20개 같은 상황에서 영어 자연스러움·인물 말투·한국어 자막과의 사실/부정/질문/약속 일치가 블라인드 검수에 통과한다. 초안 프로필·읽기 항목은 실행하지 않는다 |
| E2. 자료·참조 준비 | 영어 음성이 설치된 게임에서 영어 음성/자막을 같은 `string_id`로 연결한다. 화자 단독 3~10초·무전/필터/효과음 없는 참조를 인물·감정별로 승인한다. 학습용 대사는 별도 정제하고 언어·화자·원본 ID·분할을 기록한다 | 참조와 학습 음성이 영어이며 대본과 일치한다. 설치 파일에서 추출·처리한 오디오와 대본은 로컬/허용된 학습 작업 폴더에만 존재한다 |
| E3. 영어 모델 | v2ProPlus 공개 기본 가중치에서 영어 다화자 모델을 별도 파인튜닝한다. 일본어 v1에 이어 학습하거나 두 언어를 섞는 방식은 비교 자료 없이 채택하지 않는다. 기존 주디·빅터·로그부터 화자별 최대 20분, 인물별 5~10줄 평가용 제외, SoVITS 8~10·GPT 10~15 epoch를 시범값으로 시작한다 | 고정 평가 문장과 미학습 군중 참조에서 기본 모델 대비 발음·인물 유사도·음색 혼입을 블라인드 청취한다. 음질이 나빠지면 데이터/체크포인트를 수정하고 배포 후보로 승격하지 않는다 |
| E4. 변환·게임 연결 | 영어 모델을 Genie ONNX로 변환하고 기존 방식대로 GPT 디코더만 int8 양자화한다. `(language, voice_profile_id)`로 영어/일본어 참조를 구분하고 모델·참조·발음표·합성 캐시 키에 언어/모델 버전을 넣는다. CET↔보조 프로세스 요청에 언어를 명시하고, 영어 구두점·약어/소수점에 맞는 문장 분할과 영어 길이 기반 버퍼링 값을 계측한다. 두 모델의 동시 상주 메모리를 재고 필요하면 선택 언어만 로드한다 | ja/en 전환 뒤 이전 언어 음성·캐시가 섞이지 않는다. 새 모델 로드 중이거나 참조가 없거나 로드에 실패하면 해당 대사는 자막만 내고, 취소·대상 변경·로드 뒤 늦은 음성은 재생하지 않는다 |
| E5. 수용·배포 | 동일 대사/참조/대본으로 기본 모델과 영어 후보를 비교하고, 게임 중 CPU RTF·첫 음성 지연·재생 끊김·FPS·메모리를 일본어 v1과 같은 조건에서 기록한다. 영어/일본어 각각 인물·감정·군중·언어 전환을 실게임에서 확인한다 | 영어 음질이 기본 모델보다 나쁘지 않고 일본어 회귀가 없다. 자막 대기 상한 3초 이내에 조각이 없으면 자막만 표시한다. 모델 배포 권리·패키지 용량·설치/복원 조건(DIST-21/23/24)을 확인한 뒤 공개판에 포함한다 |

## 3. 학습 자료와 평가 분리

영어 학습의 세부 순서는 [파인튜닝 작업 절차 3절](voice-model-finetuning-guide.md#3-절차)을 언어별로 반복한다. 목록 형식의 언어 칸은 `en`, 화자 ID·모델 버전은 일본어와 구분한다. 대본은 같은 `string_id`의 영어판 자막 원문을 쓰되 실제 발화와 맞지 않는 대사는 학습·참조에서 제외한다. 동일 장면의 여러 구간이나 중복 음성이 학습과 평가에 동시에 들어가지 않게 `string_id`/장면 단위로 분리한다. 일본어 v1의 11분 학습 시간과 RTF는 영어 결과의 보증치가 아니므로 영어 학습/실행 값을 따로 잰다. 원작 음성의 서버 반출과 모델 배포 권리는 [파인튜닝 작업 절차 1절](voice-model-finetuning-guide.md#1-지킬-것) 및 [DIST-21](mod-distribution-specification.md#4-패키지-수용과-공개-배포) 판정에 따른다.

## 4. 언어별 처리와 발음

영어 검사의 핵심은 일본어 전용 처리를 언어별로 분기하는 것이다. `prototype/public/core.js`, `prototype/public/speech.js`, `game/cet/anpc/bridge.lua`의 프롬프트·응답 검사는 현재 일본어를 가정한다. 영어 `speech_text`에서는 한글·지문 등을 거르되 정상 영어 구두점·축약형·고유명사를 허용하고, `V`는 현재 Genie가 `five`로 읽은 실측([개발·검증 계획 8.1](development-validation.md#81-npc-음성-tts-로컬-실측-2026-10-06))을 기준으로 합성 직전에 단독 이름일 때만 `Vee` 읽기를 적용·청취 확인한다. 일본어의 `V`→`ヴィー` 변환은 일본어 경로에만 둔다. `speech_text`와 한국어 자막의 언어별 길이 관계, 첫 음성 지연, `sec_per_char`는 영어 실측으로 다시 정한다.

## 5. 진행 순서와 현재 상태

작업 순서는 E0 확인 → 영어 텍스트/발음 기준(E1) → 참조·학습 자료(E2) → 기본 모델과 파인튜닝 비교(E3) → 계약·런타임·웹/CET 연결(E4) → 실제 API/실게임·배포 판정(E5)이다. E0의 가중치·보조 프로세스 소스와 영어 음성/대본이 이 저장소에 없으므로 접근을 먼저 확인한다. 영어 학습, 실측, 품질 통과는 미수행이다. 언어 선택과 학습 완료, `voice_profile` 승인, 공개 배포는 각각 별도로 판정한다.
