# 게임 정보 수집 및 NPC 인지 규격

규격 버전: 0.3 (2026-10-01). 필드명은 내부 데이터 계약이다. 실제 게임 API 매핑과 접근 가능성은 [참고 분석](benchmark-analysis.md)에 기록한다.

## 1. 상태 스냅샷

대화 시작과 플레이어 입력 전송 때 스냅샷을 만든다. 필수 메타데이터는 snapshot_id, save_scope, world_epoch, npc_instance_key, observed_at_ms, dialogue_context_revision이다. observed_at_ms는 현재 실행의 단조 증가 시간이다. dialogue_context_revision의 갱신·수용 조건은 4절을 따른다.

모든 관찰 필드는 value, status, source, observed_at_ms, visibility를 포함한다. status는 known, unknown, unavailable 중 하나다. unknown·unavailable이면 value는 null이며 기본값 0·false로 치환하지 않는다. source는 실제 어댑터 접근 경로 ID 또는 미수집 사유다. visibility는 public, character_known, internal 중 하나다.

## 2. 수집 필드

| 필드 | 형식 | 사실의 기준 | 모델 전달 방식 |
| --- | --- | --- | --- |
| player.visible_equipment | 장비 목록 | 현재 외부에 노출된 무장 등 장착 상태 | 관찰 가능한 종류·외형만 전달 |
| player.visible_outfit | 복장 항목 목록 | 외형 덮어쓰기를 반영한 현재 표시 복장 | 아이템 이름·외형 텍스트. 3.1절 계약 적용 |
| npc.can_observe_outfit | 불리언 또는 null | 대상의 거리·시야·관찰 가능 상태 | true인 관찰만 이전 복장 기억으로 등록 |
| player.public_reputation | 인지 결과 객체 또는 null | 승인 평판 임계·지역/대상·공개 행적 규칙 | 이름 인지와 허용된 공개 평판만 전달 |
| player.weapon_drawn | 불리언 | 현재 무기를 꺼낸 상태 | 알려진 경우 경계 반응에 사용 |
| player.level | 정수 | 게임 레벨 | internal. 원시 숫자 전달 금지 |
| player.street_cred | 정수 | 게임 평판 수치 | internal. 카드 규칙으로 인지 수준 변환 |
| player.name_known_by_npc | 불리언 또는 null | 확인된 만남·소개·원작 관계 또는 승인 공개 평판 규칙 | true일 때만 고정 신원의 이름으로 호칭 |
| quests | 관련 퀘스트 ID·단계 목록 | 게임이 확인한 진행 상태 | 인물 지식 필터 후 관련 사실만 전달 |
| relationship | 원작 관계 상태 또는 null | 게임·작성된 단계 규칙 | 현재 관계·호칭·기본 태도. AI 누적 호감 필드 없음 |
| location | 지역·하위 지역 ID | 현재 위치 조회 | 인물이 알 법한 지역명만 전달 |
| game_time | 게임 날짜·시간 또는 null | 게임 시간 조회 | 시간대 표현으로 변환 |
| npc.activity | 활동 열거값 | 현재 AI·워크스팟 상태 | 관찰 가능한 활동만 전달 |
| nearby_events | 제한된 관찰 이벤트 목록 | 실행 중 실제 수집한 사건 | 참여·거리·인지 규칙 통과 후 전달 |
| safety | 전투·연출·퀘스트 제어·탑승·참조 유효성 | 게임 실행 계층 | internal. 행동·대화 권한 판정에만 사용 |

가방 전체, 보이지 않는 장비, 관련 없는 퀘스트, 전체 NPC 목록은 외부 모델에 보내지 않는다. nearby_events는 빈 목록과 수집 불가 상태를 구분한다. NPC가 보았다는 근거가 없으면 플레이어의 범죄·사건 참여를 아는 것으로 만들지 않는다.

## 3. 인지 변환

레벨 숫자는 모델에 보내지 않고 승인 규칙으로 장비·행적에 따른 인상으로 변환한다. 평판은 [콘텐츠 규격의 공개 평판 규칙](content-specification.md#53-관계-기준과-공개-평판-반응)에 따라 충분히 유명한 V를 처음 만난 시민도 알아보게 할 수 있다. 변환 규칙이나 필수 상태가 없으면 이름 인지·공개 행적을 확정하지 않는다. 원작 관계·기본 태도는 현재 게임과 승인 단계에서 계산하며 대화 기억으로 누적 호감·불신을 만들지 않는다. 현재 감정과 장비·상황에 대한 일시 반응은 관계 상태와 구별한다.

플레이어 이름의 기준은 [콘텐츠 규격의 고정 신원](content-specification.md#플레이어-고정-신원)을 참조한다. 이름 인지가 unknown이면 고정 이름을 안다는 호칭 근거로 사용하지 않는다. 시제품의 가상 이름 인지 설정은 실제 게임 확인 상태와 구별한다.

퀘스트 단계가 unknown이면 그 단계에 의존하는 사실을 제거한다. 대화 가능 조건에 해당 단계가 필수이면 세션을 시작하지 않는다. 서로 충돌하는 관찰은 최근 게임 관찰을 우선하고 이전 기억으로 덮어쓰지 않는다.

### 3.1. 복장 텍스트와 관찰 기록

복장 인식은 게임의 아이템 이름·설명 텍스트를 사용한다. 화면 이미지·비전 모델 호출은 요구하지 않는다. visible_outfit 항목은 slot, item_ref, display_name, appearance_text, description_source를 가진다. item_ref는 로컬 식별/중복 제거용이며 모델에는 슬롯·이름·외형 텍스트만 제공한다. 관찰 필드의 status/source/observed_at_ms/visibility 계약을 그대로 적용한다.

장비 성능 슬롯과 실제 표시 복장이 다르면 외형 덮어쓰기·의상 시스템의 표시 결과를 기준으로 삼는다. 이를 확인할 수 없는 슬롯은 unavailable로 둔다. 아이템 이름·설명에서 확인된 색·형태·화려함 등 외형 표현만 선별하며 스탯·희귀도·제작 이력·비밀 설명을 외관으로 읽지 않는다. 정확한 외형 텍스트가 없으면 색·소재를 만들어내지 않고 확인된 이름·종류까지만 제공한다. 작성된 외형 표현 매핑은 출처·콘텐츠 버전을 가진다.

NPC의 관찰은 active 진입과 입력 요청 수용 시점에 can_observe_outfit=true이고 현재 대상·거리·시야·필수 보호 상태가 유효할 때만 확정한다. 당시 슬롯별 알려진 외형과 관찰 시점을 outfit_observation 사건으로 해당 NPC 소유자에 기록한다. 같은 복장 서명은 세션 내 중복 저장하지 않고 다른 NPC가 보았다는 이유로 공유하지 않는다. 수집만 했거나 기본 반응만 보였거나 관찰 가능 여부가 unknown이면 이전 만남의 목격 근거로 등록하지 않는다. 요청이 나중에 실패해도 이미 확정된 실제 관찰과 생성 대사는 별도 사건이다.

can_observe_outfit이 true가 아니면 현재 복장도 해당 NPC의 관찰 입력으로 제공하지 않고 수집 불가 제약만 전달한다. 대화 자체가 안전하면 세션은 유지할 수 있지만 현재 옷을 봤다는 평가는 생성하지 않는다. 과거 관찰은 유효 범위에서 당시 모습에 대해서만 사용할 수 있다.

복장 비교에는 현재 알려진 복장과 유효한 같은 NPC의 이전 관찰이 필요하다. 과거 기록이 없으면 현재 옷에 대해서만 말한다. 옷을 더 좋아한다는 취향·평가는 인물 성격·현재 원작 관계에 맞게 생성할 수 있지만 낯선 인물의 연인 말투나 실제로 보지 않은 “지난번 옷”을 만들지 않는다. 보존·조회·로드 복원은 [기억 규격](memory-specification.md#43-복장-관찰과-생성-일상-기억)을 따른다.

### 3.2. 진행도에 따른 원작 맥락

현재 게임의 승인된 단계·관계·인지 매핑에서 인물의 과거 사건 요약, 현재 목표·호칭·공개 지식을 선택한다. 이것은 canon_context이며 ANPC 대화로 발생한 기억과 분리한다. 원작 대사 전체를 recent_turns에 복사하거나 플레이어의 설명으로 퀘스트를 진행시키지 않는다. 단계가 변하면 관련 맥락을 다시 계산하고 미래 사건·다른 분기·현재 인물이 알 수 없는 내용은 제외한다. 저장 로드 후에도 복원한 ANPC 기억보다 현재 게임 단계가 우선한다.

## 4. 갱신과 무효화

대사 표시 직전과 행동 실행 직전에 게임 보호 상태·대상 유효성을 재조회한다. 일반 관찰은 요청 시점 스냅샷을 사용하되 지식·관계·공개·원작 단계와 행동 권한은 아래 버전 검사로 유효성을 확인한다. 세계 세대가 바뀐 스냅샷은 즉시 무효다.

dialogue_context_revision은 세션별 1에서 시작하는 로컬 증가 번호다. 요청에 적용한 NPC 인지·지식 공개 조건, 이름 인지·원작 관계·단계별 목표, 대화 가능 조건, 허용 행동 집합 중 하나가 바뀌면 증가한다. 관련 필드가 known에서 unknown/unavailable로 바뀐 경우도 변경이다. 복장 질문·복장 반응 규칙을 사용하는 진행 중 요청에서는 표시 복장이나 관찰 가능 상태가 바뀐 경우도 증가시킨다. 단순 시간 경과·진단 값 갱신·관련 없는 퀘스트 변경은 증가 사유가 아니다. 정리 워커가 새 기억을 반영하는 것만으로 진행 중 대사의 버전을 바꾸지 않는다.

퀘스트·관계·공개 조건 변경 이벤트는 즉시 위 계약을 재계산하게 한다. 대사 표시 직전에도 해당 입력 조건을 재조회·계산해 이벤트 누락을 보완한다. 요청 버전과 현재 버전이 다르면 이전 응답 전체를 폐기하고 대사·행동·기억으로 등록하지 않는다. 일부 문장만 제거해 사용하는 방식은 허용하지 않는다. 대화 조건이 계속 유효하면 세션을 active로 돌리고 사용자 재전송을 제공하며 자동 유료 재생성은 하지 않는다. 대화 금지·필수 보호 상태 불명은 세션을 종료한다. 최신 판정을 확인할 수 없으면 이전 응답을 수용하지 않는다.

필드 수집 실패는 해당 필드에만 반영한다. 필수 보호 상태 수집 실패는 세션 시작 거부 또는 진행 중 세션 종료로 처리한다. 모델이 보충한 게임 상태를 관찰 값으로 저장하지 않는다.
