# NPC 음성 출력 지연 참고 분석

확인일: 2026-10-06. 범위는 후속 기능인 NPC 음성(TTS) 출력이다. 첫 게임판의 자막 출력 계약은 바꾸지 않는다. 아래 방안은 명세에 반영하기 전의 후보다. 기능을 바꿀 때는 먼저 [게임 기능 명세](gameplay-functional-specification.md)의 UF ID를, 설치물을 바꿀 때는 먼저 [배포 규격](mod-distribution-specification.md)의 DIST ID를 지정한다. 실측 기록은 [개발·검증 계획](development-validation.md#11-npc-음성-tts-로컬-실측-2026-10-06)에 둔다.

## 1. 결정 사항과 전제

| 항목 | 내용 |
| --- | --- |
| 음성 언어 | 일본어 또는 영어 음성 + 한국어 자막. 한국어 음성은 청취 비교 결과 제외 |
| 대사 생성 | 플레이어 API 키로 직접 호출. `gpt-6-luna`, `reasoning.effort=none`, 비스트리밍 구조화 응답(현행 [CET 설정](../game/cet/anpc/config.lua)) |
| TTS 후보 | GPT-SoVITS v2ProPlus 제로샷을 Genie-TTS(ONNX)로 CPU에서 실행. Irodori-TTS는 일본어 전용이고 GPU가 필요해 예비 후보 |
| 기준 PC | Ryzen 5 7500F, RAM 32GB, RX 9060 XT 8GB. 게임이 VRAM을 쓰므로 CPU 추론을 전제 |
| Codex 브리지 | 개발 시험용이며 게임 지연 판정에 쓰지 않음. 로그인 모델은 `gpt-5.6-sol/terra/luna`이고 최소 추론은 `low`. `gpt-6-luna`·`none`은 없음. 현재 브리지는 model·effort를 지정하지 않아 CLI 사용자 설정(`gpt-6.1-sol`·`medium`)을 따름 |

## 2. Enter → 첫 음성 지연 구성

| 단계 | 값 | 근거 |
| --- | --- | --- |
| 입력 처리 → 요청 전송 | 약 0.05초 | 로컬 처리 |
| LLM 응답 완료 | 1.5~4초 | 미측정 추정. Codex 브리지 실측 9.1~11.5초는 다른 모델·추론 설정이라 적용하지 않음 |
| 음성용 대사 추가 출력 | +0.2~1.0초 | 추정. 일본어가 영어보다 출력 토큰이 많음 |
| 응답 검증·해석 | 0.1초 미만 | 로컬 처리 |
| TTS 첫 음성 (Genie 4스레드, 문장 단위) | 1.0~1.8초 | 게임을 끈 상태의 실측 |
| 게임 실행 중 CPU 경쟁 | +0.3~0.7초 | 미측정 추정 |
| 합계 | 약 3~7.5초 | LLM 응답 완료가 가장 큰 비중 |

## 3. 응답 최적화 방안

| 순위 | 방안 | 기대 효과 | 영향 문서·계약 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 직접 API 경로 유지 (`gpt-6-luna`, `none`) | Codex 브리지보다 수 초 단축 | 현행 설정 | 채택. 지연 실측 필요 |
| 2 | 음성 대사 선행 생성: 응답 스키마의 음성용 대사 필드를 맨 앞에 두고 스트리밍으로 받는다. 이 필드가 완성되면 TTS를 시작하고, 전체 응답이 검증을 통과한 뒤에만 재생한다. 검증 실패·취소·늦은 응답이면 오디오를 버린다 | TTS 1~2초를 LLM 대기 시간에 겹침. Enter → 음성 약 2~5초(추정) | [런타임 규격](runtime-specification.md)의 비스트리밍 기본, 응답 계약 필드, 취소·폐기 규칙 | 후보 |
| 3 | 첫 문장을 짧게 쓰도록 유도 | 첫 음성 단축. 영어 "Hey, V." 대사는 1.0초 | [프롬프트 명세](prompt-specification.md) | 후보 |
| 4 | 문장 단위 합성·재생 큐 | RTF가 1 미만이면 첫 문장 이후 끊김 없이 재생 | TTS 모듈 | 후보. Genie 4스레드 RTF 0.71~0.75 |
| 5 | 사전 로드·예열: 게임 시작 시 모델을 불러오고, "V"가 든 문장으로 예열하고, 인물별 참조 음성 처리 결과를 캐시 | 첫 대사 지연 제거. 예열하지 않으면 첫 줄이 3.4초 늘어난 사례 있음 | TTS 모듈 | 후보. Genie 모델 로드 약 7~8초 |
| 6 | CPU 자원 제한: 4스레드, 낮은 프로세스 우선순위 | CPU 점유 약 48% → 약 33%. 속도는 12~15% 감소 | TTS 모듈 설정 | 후보. 게임 FPS 영향 미측정 |
| 7 | 자막·음성 동기: 음성 시작에 맞춰 자막 표시. 대기 상한(약 3초)을 넘기거나 TTS가 실패하면 자막만 표시 | 자막과 음성 일치 | 게임 기능 명세(UF) | 후보 |
| 8 | 같은 문장 음성 캐시 | 반복 대사의 TTS 시간 제거 | TTS 모듈 | 후보 |
| 9 | 읽기 보정: 일본어 다의 한자는 가나로 쓰고 고유명사 표기표를 둔다. 영어 "V" 표기를 고정 | 오독과 재생성 방지. 金→キン 오독, Genie의 V→five 오독 확인 | 프롬프트 명세, TTS 전처리 | 후보 |
| 10 | 출력 앞뒤 여백 보정 | Genie 출력은 앞뒤 무음이 0~0.06초라 끝 음절이 잘렸을 수 있음 | TTS 모듈 | 무음 추가(앞 0.15초, 뒤 0.25초) 시험. 잘림 자체는 청취 확인 필요 |
| 11 | 음색 후처리: 엔진·언어별 고정 EQ(선형 위상 FIR 511탭, 32kHz, 지연 약 8ms)와 음량 맞춤(원본 약 -25 LUFS, 피크 -1dBFS 제한) | 클론이 얇게 들리는 문제 완화. 파일당 처리 약 13ms | TTS 모듈 후처리 설정 | 시험. 스트리밍 재생에서는 문장 전체 기준 음량 계산 대신 고정 이득(+2.3~+6dB)과 피크 제한을 쓴다. 여러 줄 평균으로 EQ 재설계 필요 |

## 4. 명세 반영 전 확인 항목

- 직접 API(`gpt-6-luna`·`none`)의 완료 지연 p50/p95를 잰다. 음성용 대사 필드를 넣은 경우와 뺀 경우를 비교한다.
- 게임을 실행한 상태에서 Genie 4스레드의 RTF, 첫 음성 지연, 게임 FPS 변화를 잰다.
- 일본어와 영어 중 최종 음성 언어를 고르고, Genie 출력 끝 잘림을 청취로 확인한다.
- 배포: Genie 런타임(약 200MB), ONNX 모델(약 230MB), GenieData(약 410MB)의 설치·삭제 경로는 DIST ID를 지정한 뒤 정의한다. 원작 음성으로 만든 참조 클립과 생성 음성은 배포하지 않는다.
- 원작 성우 음성 클로닝은 사용자 PC에서만 생성하고 배포하지 않는 방식만 검토 대상으로 둔다. 권리 문제는 출시 전 별도로 확인한다.
- 배포판에서 쓸 수 있는 음색 개선은 후처리 보정(11번)과 참조 대사 선택(대사 경로 목록만 배포)이다. 인물별 파인튜닝은 학습 결과가 원작 음성의 복제본이라 배포판에 넣지 않는다. 개인 시험으로 검토할 때 RTX 5080 기준 소요 시간은 데이터 준비·학습·변환을 합쳐 약 30~50분으로 추정한다(대사 5~10분 분량, 미측정).
