# NPC 세계관 지식 부여 및 프롬프트 주입 규격

규격 버전: 1.1 (2026-10-01). 세계관 지식의 인물별 배분 기준이다. 사실·인지·깊이 객체의 형식은 [콘텐츠 규격](content-specification.md#41-인물별-분야와-지식-깊이), 턴별 검색·토큰 예산은 [프롬프트 명세](prompt-specification.md), 유지·무효화는 [NPC 식별 규격](npc-identity-specification.md)이 기준이다.

## 1. 저장 위치와 구분

초기 자료는 `content/cyberpunk2077/`에 저장한다. 원작 사실은 `world-facts.json`, 인물의 인지·공개 조건은 `knowledge.json`, 인물 정체성은 `characters/*.json`, 대화 예시는 `dialogue-examples.json`, 출처는 `sources.json`이다. 같은 사실은 ID로 참조하고 인물별로 원작 진술을 복제하지 않는다. `manifest.json`은 묶음 버전·상태·파일 목록을 기록한다.

플레이어 이름은 [콘텐츠 규격의 고정 신원](content-specification.md#플레이어-고정-신원)을 참조한다. 이름 기준은 무작위 지식 배분 대상이 아니며 NPC의 이름 인지 조건은 별도로 적용한다.

현재 묶음은 조사·작성 후보다. source_checked는 해당 진술의 출처를 읽었다는 뜻이며 출시 승인 approved와 구별한다. 캐릭터·인지 조건·대사 예시의 draft는 출시용 생성기에 제공하지 않는다. 명세나 파일이 있다는 이유로 게임 NPC에 자동 적용하지 않는다. 초안의 개발용 비교 예외와 표시·차단 조건은 [시제품 안내](dialogue-prototype.md#인물-설정과-대화-테스트)에 둔다.

## 2. 지식의 층

| knowledge_layer | 의미 | 군중 배분 | 커뮤니티 배분 |
| --- | --- | --- | --- |
| common | 통화·임플란트·도시 서비스 등의 상식 | 승인된 기본 목록. 인지 예외 프로필에서는 제외 | 작성된 기본 지식 목록 |
| regional | 동네·시설·지역 집단에 대한 생활 지식 | 승인된 거주·활동 배경 조건으로 부여 | 인물의 생활·활동 근거로 작성 |
| profession | 기술·의료·경비 등 전문 지식 | 승인된 업무 배경의 필수 지식과 선택 후보 | 원작의 전문 분야를 근거로 작성 |
| optional | 음악·위험 집단 등의 선택 관심 지식 | 인지 가능한 후보 중 제한 추첨 | 필요하면 카드에 명시적으로 작성 |
| personal | 개인 배경·관계·사적 경험 | 임의 배분 금지. 생성 배경은 창작으로 별도 보관 | 해당 인물·관계·공개 조건에 따라 제공 |
| quest | 사건 진행·비밀·렐릭·분기 결과 | 추첨 금지. 실제 인지 근거가 있는 별도 프로필만 허용 | 인물별 인지·진행·공개 조건으로 제공 |

성격과 지식량은 독립이다. 경계심이 강하다고 비밀을 알게 하거나, 사교적이라고 모든 사람의 관계를 알게 하지 않는다. 현재 지역에 서 있다는 사실만으로 그 지역의 주민·갱 내부자·전문가라고 가정하지 않는다. 기본 시민에게는 관찰에 없는 직업·거주 이력을 만들어 전문 지식을 부여하지 않는다.

## 3. 군중 배분 순서

1. 정체성 생성 시 승인된 원형·배경으로 지식 프로필을 고정한다. 공통 목록과 조건에 맞는 지역·직업 필수 지식을 부여한다.
2. 선택 후보는 승인 상태·시대·인지 조건을 먼저 통과시킨다. 개인·퀘스트 층은 추첨 후보에서 제외한다.
3. 선택 지식은 최대 2개를 추첨한다. 후보가 적으면 가능한 개수만 부여하고 필수 상식·핵심 업무 지식을 무작위로 빼지 않는다. 정체성 seed에서 별도 knowledge 하위 seed를 파생하고 정체성 추첨에 영향을 주지 않는다.
4. 선택한 knowledge_id와 certainty, 지식 프로필 버전을 같은 인스턴스에 저장한다. 대화·유효 재접촉 동안 유지하고 매 턴 재추첨하지 않는다.
5. 새 정보를 플레이어가 말하면 player_claim으로 기억한다. 그것을 새 원작 지식·직접 목격 경험으로 바꾸지 않는다. 게임 또는 검수된 이벤트가 확인한 사실만 별도 인지 갱신 규칙으로 반영한다.

무작위 대상은 **인물이 어떤 사실을 알고 있는가**다. 사실의 내용·참/거짓·사건 발생 여부·경험 여부는 추첨하지 않는다. 소문을 추가할 때는 출처가 있는 소문과 certainty=suspects를 별도 작성한다. 사실 문장을 무작위로 변형해 소문을 만들지 않는다.

13개 지식 묶음의 초기 후보는 [배분 데이터](../content/cyberpunk2077/crowd-knowledge-policy.json)에 둔다. 묶음 내용은 후보 상태이고 실제 군중 원형·슬롯 후보 풀 제작은 다음 단계다.

## 4. 커뮤니티 배분

각 카드의 knowledge_ids를 기준으로 삼는다. 핵심 직업·정체성에 필요한 지식을 무작위로 부여하거나 제거하지 않는다. 같은 인물이 대화마다 BD 기술자 또는 의료 비전문가로 바뀌어서는 안 된다. 작성된 인지 조건은 사실을 아는지, 공개 조건은 플레이어에게 말할 수 있는지를 각각 결정한다.

knowledge_ids에 등록된 항목도 카드 knowledge_profile의 분야 상한을 넘어서는 경우 제공하지 않는다. common 층에 있다는 이유로 모든 인물에게 부여하지 않는다. 출신·직업·생활권·소속·취미·실제 사건 노출을 개별 근거로 작성하며, 같은 출신 집단에서도 서로 다른 경험을 가질 수 있다. 커뮤니티의 지식 깊이는 무작위로 바꾸지 않는다.

주디는 공식 소개에 BD 제작·편집 업무가 명시돼 있으므로 해당 분야의 전문 프로필 작성 근거가 있다. 팬앰은 노마드·용병 배경이 확인되지만 이번 자료에서는 BD 전문성·직접 이용 경험을 확인하지 못했다. 현재 팬앰의 BD는 unverified/unknown으로 보류하고, BD 개요를 시민 공통 상식으로 자동 부여하지 않는다. 이는 팬앰이 원작에서 BD를 전혀 모른다는 확정이 아니다. 확인된 인지 장면이 생기면 해당 깊이·사실을 근거와 함께 작성한다.

같은 분야에서 이름은 알지만 절차는 모르는 인물은 awareness 항목만 제공한다. 개인 경험을 확인하지 못한 경우 “내가 해봤는데”, “누구에게 배웠다” 같은 일화를 생성하지 않는다. 의료 종사자에게 넷러닝, 경호원에게 기업 네트워크 기술, 음악가에게 BD 편집 지식을 직업 연상만으로 추가하지 않는다.

인지 갱신에는 해당 인물이 노출된 게임 이벤트·대화 장면과 단계 조건이 필요하다. 플레이어가 기술을 설명한 대화는 player_claim으로 기억하며 분야 상한·원작 경력을 자동 승격하지 않는다. 작성 프로필의 변경은 콘텐츠 개정으로 관리하고 유효 세션 중 몰래 교체하지 않는다.

원작을 아는 플레이어와 NPC의 인지는 다르다. 공식 소개·위키에 공개된 비밀도 해당 NPC가 현재 단계에 아는 것으로 간주하지 않는다. 특히 렐릭과 V의 상태는 인물의 인지 확인과 V의 공개 허용을 함께 요구한다. 인물이 모르는 비밀의 실제 내용은 프롬프트에서 제거한다.

원작 관계·사망·언어적 반응 가능 여부는 현재 게임이 확정해야 한다. 재키·에블린은 이후 사건을 웹에서 알고 있더라도 그 사건 이후 살아서 대화할 수 있는 인물로 구성하지 않는다. 타케무라·리버의 현재 소속·재직 상태, 주디·팬앰의 현재 위치·관계도 웹 소개로 고정하지 않는다.

## 5. 현재 묶음의 논리 조건 필드

다음은 ANPC 콘텐츠 어댑터가 제공할 논리 필드다. 게임 내부 레코드·퀘스트 플래그 이름이 아니다. 실제 매핑 전에는 unknown으로 둔다. 등록·값 검증·매핑 책임은 게임 정보 수집 계층에 있고 문자열이나 플레이어 주장으로 값을 채우지 않는다.

| 필드 | 형식 | 승인 값의 의미 |
| --- | --- | --- |
| content.era | 문자열 | 해당 자료의 시대. 현재 묶음은 2077 |
| content.npc_key | 문자열 | 승인된 실제 인물 매핑 |
| content.npc_alive_confirmed | 불리언 | 현재 게임에서 살아 있고 대화 가능한 존재로 확인 |
| content.npc_free_confirmed | 불리언 | 원작 대화·시네마틱·전투·퀘스트 제어 등 대화 금지 상태가 아님 |
| content.relationship_confirmed | 불리언 | 원작의 관계 단계와 호칭 정책을 판정 가능 |
| content.phase | 문자열 | 카드의 phase_labels 중 매핑·검수된 현재 단계 |
| content.grants.<fact_id> | 불리언 | 해당 인물의 승인 인지 조건을 현재 단계에서 충족 |
| content.player_disclosure.relic | 불리언 | V의 상태를 이 인물에게 공개할 조건이 충족됨 |

카드의 phase_labels는 의미를 표현한 단계 이름이며 원작 퀘스트 ID가 아니다. 캐릭터 이름, 기본 소개, 사용자 입력만으로 relationship_confirmed·grants를 true로 만들지 않는다. 출시 승인 전의 draft 자료를 필드 값만으로 활성화하지 않는다.

## 6. 매 턴 프롬프트 주입

승인 카드 → 현재 인지·단계·공개 조건 → 인물의 고정 지식 집합 → 분야 깊이 상한 → 현재 화제 관련 항목 → 최소 진술·확실성·해석·주장 한도 순서로 조립한다. 프롬프트에는 전체 백과사전·출처 원문·다른 인물의 비밀을 넣지 않는다. 정확한 선별·정렬·절감은 프롬프트 명세를 따른다.

현재 알아두는 지식과 이번 요청에 보내는 지식을 구별한다. NPC가 에디와 경찰을 알고 있어도 BD 편집 질문에는 관련 전문 지식만 보낼 수 있다. 대화 종료 후 주제를 바꿔 돌아왔을 때도 보유 지식 집합은 유지된다.

세계관 이름을 억지로 반복하지 않는다. 같은 기업 사실에도 직업·가치·상황에 따라 다른 반응을 작성할 수 있지만 그 해석을 새 사실로 저장하지 않는다. 알아도 말하지 않는 경우는 disclosure 정책으로 처리하고 내용을 숨긴 채 회피 지침만 전달한다.

## 7. 자료 확장 기준

새 사실은 출처·시대·스포일러·인지 가능한 대상·주장 한도를 함께 등록한다. 2020·2045년의 제도·가격·지역·기술을 2077의 현재 상태로 복사하지 않는다. 광고·샤드·인물 회고는 객관적 사실, 광고 주장, 회고의 신뢰도와 시점을 구별한다. 원작 자료 간 충돌은 보류 항목으로 남기고 모델에게 임의 선택을 맡기지 않는다.

이번 자료는 대표 10명과 기본 세계관의 초기 묶음이다. 전체 게임의 모든 대사·샤드·퀘스트 분기를 수록한 자료가 아니다. 완전한 원작 재현을 위해 추가할 장면 근거와 게임 상태 매핑은 [개발·검증 계획](development-validation.md)에 기록한다.
