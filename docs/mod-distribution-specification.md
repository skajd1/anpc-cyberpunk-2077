# 모드 패키지·설치·백업·복원 규격

규격 버전: 1.1 (2026-10-07). [플레이어 기능 명세](gameplay-functional-specification.md)의 UF-01/02/54/55/60/61/67에 적용한다. 구현 상태/출시 공백은 [개발·검증 계획](development-validation.md#2-출시-전-남은-결함), 실제 배포 기록은 [배포 변경 이력](game-mod-validation.md)에 둔다.

## 1. 배포 범위와 소유권

| ID | 규칙 |
| --- | --- |
| DIST-01 | 개발 시험 패키지와 공개 배포를 구분한다. 개발 ZIP 생성은 기능·콘텐츠·호환성 출시 승인이 아니다. |
| DIST-02 | ZIP은 게임 루트 기준 상대 경로의 ANPC 소유 파일, 패키지 목록/해시, 설치/제거 안내와 라이선스 고지만 포함한다. |
| DIST-03 | 게임 실행 파일·원본 archive/final.redscripts·세이브·캐시·.env·개인 경로/설정·로그·키·백업·개발 서버/테스트·조사 원문을 포함하지 않는다. |
| DIST-04 | RED4ext/redscript/CET/Codeware는 별도 필수 의존성이다. 제작자 승인 없이 코어 도구를 ANPC ZIP에 묶거나 설치/제거하지 않는다. |
| DIST-05 | 매 빌드에서 최신 생성 프롬프트 일치, 파일 SHA-256, 포함/제외 목록, 패키지 버전·지원 프로필·의존성·콘텐츠 승인 상태를 검사한다. |
| DIST-06 | 공개 채널은 미검수 콘텐츠/필수 기능·실게임 지원 검사·라이선스가 미완이면 빌드를 거부한다. 개발 초안 예외를 공개판에 승계하지 않는다. |
| DIST-23 | NPC 음성 구성은 ANPC 소유 파일로 포함한다: Python·CUDA 설치가 필요 없는 TTS 런타임, 주요 인물 음성으로 파인튜닝한 ANPC 음성 모델의 ONNX 변환본(GPT 디코더 int8, 나머지 fp32)과 학습 목록, voice_profile·string_id 참조 목록. 원작/참조/학습 오디오·대본·추출물·참조 처리 결과·생성 음성·학습 체크포인트는 포함하지 않는다. 엔진·기반 가중치 라이선스 고지를 함께 넣는다. 원작 음성으로 학습한 모델의 배포 권리 확인은 DIST-21 검토 항목이며, 확인 전에는 공개 빌드를 거부한다(DIST-06). 모델 업데이트는 DIST-09 업데이트로 처리한다. 세부 계약은 [음성 출력 규격](npc-voice-output-specification.md#31-음성-모델과-학습-자료). |
| DIST-24 | 음성 캐시(추출 참조 오디오·참조 처리 결과·합성 결과)는 설치 후 사용자 PC가 만드는 재생성 가능 파생물이다. 설치 목록에 ANPC 소유 생성 디렉터리로 기록하고 제거 시 함께 삭제한다. 업데이트로 engine_profile 버전·content_version이 바뀌면 무효화한다. 패키지·백업·배포 이력에 내용을 넣지 않는다. |

게임 설치 대응은 다음 세 ANPC 디렉터리다. 새 자산은 실제 사용/필요성이 검증된 경우에만 소유 목록에 추가한다. 현재 사용하지 않는 장면 interaction 연구 자산을 자동 포함하지 않는다.

| 구성 | 설치 상대 경로 |
| --- | --- |
| CET Lua·생성 콘텐츠·키 없는 기본 설정 | bin/x64/plugins/cyber_engine_tweaks/mods/anpc/ |
| redscript | r6/scripts/ANPC/ |
| 제품 Native 플러그인 | red4ext/plugins/ANPC/ANPC.Native.dll |
| TTS 런타임·ANPC 음성 모델·참조 목록 (DIST-23) | red4ext/plugins/ANPC/tts/ |
| 음성 캐시, 설치 후 생성 (DIST-24) | red4ext/plugins/ANPC/tts-cache/ |

CET 디렉터리 안에서 승인 콘텐츠·공통 계약 검사 자료는 `content/`·`contracts/`, 지원 매핑·모듈 구성은 `profiles/` 아래에 둔다. 사용자 설정·비용 원장은 게임 폴더 밖 `%LOCALAPPDATA%/ANPC/Cyberpunk2077/`에 두며 패키지·제거 대상에 넣지 않는다(DIST-16). 신규 자산이 필요해지면 `archive/pc/mod` 또는 REDmod 중 실제 사용 방식을 정해 소유 목록에 추가한다.

Node.js·WolvenKit·빌드 도구는 제작/개발 의존성이다. 제품 Native 대화의 플레이어 실행 필수 의존성으로 요구하지 않는다. 개발 파일 브리지는 공개 패키지의 기본 대화 경로가 아니다. REDmod·ArchiveXL·TweakXL·AMM은 필수 의존성이 아니다. AMM 제스처처럼 선택 연동은 설치·호환이 확인될 때만 활성화한다.

## 2. 최초 설치와 업데이트

| ID | 상황 | 필수 처리 |
| --- | --- | --- |
| DIST-07 | 설치 시작 | 게임 루트/패치/필수 도구·게임 종료·경로 경계·파일 목록/해시·디스크 쓰기 가능 여부를 변경 전에 확인한다. |
| DIST-25 | redscript가 바뀐 설치·패키지 빌드 전 | `scripts/check-redscript.ps1`로 시험 컴파일한다. 대상 게임의 `engine\tools\scc.exe`와 원본 `r6\cache\final.redscripts`를 읽기만 하고, 설치된 다른 스크립트·RED4ext 플러그인 스크립트·저장소 ANPC 스크립트를 임시 폴더에 모아 컴파일한다. 선택 의존성(`@if(ModuleExists(...))` 분기)은 있음·없음을 모두 검사한다. 하나라도 ERROR가 있으면 설치·빌드를 중단한다. `.reds`는 BOM 없는 UTF-8로 저장한다. |
| DIST-26 | 개발 게임 배포 | 저장소 소스만 고치고 `scripts/deploy-game-dev.ps1`로 게임 폴더에 동기화한다. 게임 폴더의 ANPC 파일을 직접 고치거나 배포마다 별도 복사 스크립트를 만들지 않는다. 대응: `game/cet/anpc`→CET 모드 폴더, `game/redscript/ANPC`→`r6/scripts/ANPC`, `game/audioware/ANPC`→`r6/audioware/ANPC`, Native DLL은 `-NativeDll`로 지정할 때만. 해시가 다른 파일만 추가·수정하고, 마지막 배포의 소유 목록에 있으나 소스에서 사라진 파일은 삭제한다. 소스에 없고 소유 목록에도 없는 파일(로그·DB·TTS 교환 파일)은 건드리지 않는다. Audioware 슬롯 wav는 실행 중 TTS가 덮어쓰므로 없을 때만 설치한다. 마지막 배포 뒤 게임 쪽에서 바뀐 소유 파일은 충돌로 중단한다(DIST-14). 변경 전 생성 프롬프트 최신 여부(DIST-05)와 redscript 시험 컴파일(DIST-25)을 검사하고, DIST-10~12 순서로 백업·교체·되돌림·해시 검사를 한다. 기록은 배포마다 `config.local.backups/<배포 ID>/`의 manifest(기준 커밋·미커밋 파일·검사 결과·변경 전/후 SHA-256·백업 경로)와 배포 이력 초안이다. `-Plan`은 변경 계획만 출력하고, `-Restore <배포 ID>`는 DIST-13 되돌리기를 새 배포 항목으로 기록한다. 작업 절차는 [게임 배포 절차](deploy.md). |
| DIST-08 | 새 설치의 동일 경로에 기존 파일 존재 | 이전 ANPC 소유/상태를 확인하지 못하면 충돌로 중단한다. ‘ANPC 이름의 폴더’만으로 삭제/덮어쓰기 권한을 추정하지 않는다. |
| DIST-09 | 확인된 ANPC 업데이트 | 기존 설치 목록과 실제 해시를 비교한다. 기본 설정과 사용자 설정을 분리하고 사용자 설정을 보존한다. 누락/추가된 소유 파일도 기록한다. |
| DIST-10 | 파일 변경 전 | 기존 파일과 설치 목록을 게임 밖의 영구 백업에 복사하고 해시를 확인한다. 새 파일은 기존 파일 없음으로 기록한다. 임시 폴더만을 유일한 복구본으로 사용하지 않는다. |
| DIST-11 | 설치 도중 실패 | 변경 목록을 기준으로 이번 작업을 되돌리고 성공한 단계/미복구 항목을 명시한다. 부분 설치를 성공으로 표시하지 않는다. |
| DIST-12 | 설치 완료 | 설치 파일 해시 재검사·설치 이력 보관·재시작 안내. 파일 복사 성공과 실제 게임 컴파일/대화 성공을 구분한다. |

백업/설치 이력에는 패키지 버전·작업 시각·대상 상대 경로·변경 전/후 SHA-256·이전 파일 유무·백업 상대 경로·작업 결과를 남긴다. 백업은 개인 로컬 자료이며 Git/배포 ZIP에 포함하지 않는다. 게임 세이브 백업은 별도 기능이며 모드 파일 백업 성공으로 세이브까지 백업했다고 표시하지 않는다.

## 3. 되돌리기·제거·설정과 키

| ID | 상황 | 필수 처리 |
| --- | --- | --- |
| DIST-13 | 되돌리기 | 게임 종료 후 선택한 설치 이력·백업 해시·현재 설치 해시를 검사한다. 변경 전 있던 파일은 복원, 없던 파일은 이번 설치가 만든 해시와 일치할 때만 제거한다. |
| DIST-14 | 사용자가 파일 수정/다른 모드가 덮어씀 | 해당 파일은 자동 복원/삭제하지 않고 충돌 목록을 제공한다. 전체 재귀 삭제나 무조건 덮어쓰기 금지. |
| DIST-15 | ANPC 제거 | 설치 소유 목록의 검증된 파일만 제거/원복한다. 다른 모드·코어 도구·오리지널·세이브·키·설정을 기본 보존한다. |
| DIST-16 | 키/기억/사용량 초기화 | 제거와 분리된 사용자 명시 동작으로 처리한다. 오리지널 진행·세이브를 변경하지 않는다. |
| DIST-17 | 백업 없음/해시 불일치 | 복원 불가 이유와 안전하게 가능한 작업을 알린다. 다른 버전 파일을 원본으로 추정하거나 빈 파일을 대신 만들지 않는다. |

파일을 복원해도 과거 게임 진행이나 이미 청구된 API 사용을 되돌리지 않는다. 사용자가 저장한 키는 Windows 자격 증명 관리자에 있으며 ZIP/설치 이력으로 복사하지 않는다.

## 4. 패키지 수용과 공개 배포

| ID | 검사 | 통과 기준 |
| --- | --- | --- |
| DIST-18 | 깨끗한 시험 설치 | 지원 게임/도구에서 목록과 실제 파일 동일, Node 서버 없이 Native 대화 가능 |
| DIST-19 | 버전 업데이트/충돌 | 사용자 설정·다른 모드 보존, 변경 파일/해시 정확, 충돌 시 변경 전 중단 |
| DIST-20 | 중간 실패/복원/제거 | 장애를 넣은 검사에서 변경 전 상태 복원. 새 파일 제거와 이전 파일 복원을 각각 확인 |
| DIST-21 | 보안/저작물 포함 범위 | 키·개인 파일·게임 원본·조사 원문/코어 도구 제외. 자체 소스와 동봉 라이브러리의 라이선스/고지 검토 완료. 원작 음성으로 학습한 ANPC 음성 모델의 배포 권리 확인 완료 |
| DIST-22 | 실제 게임 회귀 | 시작/종료·기존 저장·진입/대화/중단·실행 가능한 행동·설치/제거 실증 완료. 모의 검사나 CLI 컴파일만으로 통과 처리하지 않음 |

출시 버전은 지원 NPC·허용 진행 구간·모델·콘텐츠·행동·플랫폼/패치/의존성 조합을 명시한다. 미지원 인물을 자료 개수만으로 지원 목록에 넣지 않는다. 출시 차단 항목은 개발 ZIP 생성으로 해제하지 않는다.
