# ANPC 전체 스펙

상태: 초안 (2026-09-29). 이 문서는 목표 제품의 요구사항이다. 모든 기능이 현재 모딩 API로 구현 가능하다고 가정하지 않는다. 첫 개발 범위와 검증 순서는 [초기 설계](initial-design.md)를 따른다.

## 1. 제품 정의

ANPC(Autonomous Non-Player Character)는 사이버펑크 2077에서 플레이어가 NPC에게 먼저 말을 걸어 텍스트로 대화하는 모드다. 세션이 시작되면 NPC는 플레이어의 질문에 답하고, 되묻거나 스스로 반응하며, 게임에서 검증된 행동을 취할 수 있다. 플레이어 장비, 레벨, 길거리 평판, 퀘스트 진척도, 관계, 장소와 이전 대화가 반응에 영향을 준다.

길거리 **군중 NPC**와 기존 **커뮤니티 NPC**를 모두 대상으로 한다. 군중 NPC에게는 생성된 특성을 부여한다. 커뮤니티 NPC는 기존 캐릭터의 성격·관계·지식·퀘스트 역할을 보존한다. 플레이어 입력은 채팅이다.

### 초기 범위에 포함

- NPC 선택, 텍스트 대화, 응답 대기·취소·종료 UI.
- 확인된 게임 상태를 반영하는 대사와 NPC의 후속 질문·반응.
- 대상과 상황에 맞게 허용된 움직임·제스처·애니메이션 등 행동.
- 군중 NPC의 세션별 특성, 커뮤니티 NPC의 수작업 캐릭터 프로필.
- 대화 중 기억과 식별 가능한 NPC에 한정한 선택적 장기 기억.

### 초기 범위에서 제외

- 플레이어 음성 입력·음성 인식. NPC 음성 출력도 별도 후속 결정이다.
- AI가 임의 코드를 실행하거나 새 애니메이션을 즉석에서 만드는 기능.
- 원작 퀘스트 대사·진행을 대체하거나 모든 NPC와 즉시 대화하는 보장.
- 군중 NPC의 재생성 이후 동일 인물 여부가 확인되기 전의 개인별 장기 기억.

## 2. NPC 유형 및 특성

### 군중 NPC

평범하게 거리를 걷는 NPC를 포함한다. 대화 시작 시 확인 가능한 지역·외형·현재 활동에 기질, 말투, 현재 목적, 플레이어에 대한 태도를 조합해 특성을 생성한다. 생성 결과는 세션 동안 고정한다. 개인적 배경은 세계관에 맞게 창작할 수 있으나 원작의 확정 사실이나 미공개 퀘스트 내용을 만들어내지 않는다.

군중 시스템의 NPC가 사라졌다 다시 나타났을 때 동일 인물인지 알 수 없다면 기억은 세션 종료와 함께 끝낸다. 지역·유형에 대한 일반적 연속성은 나중에 지원할 수 있지만 다른 NPC를 같은 인물이라고 표시해서는 안 된다.

### 커뮤니티 NPC

상인, 적대 NPC, 지인, 퀘스트 인물 등 군중 외 NPC를 포함한다. 지원 대상은 프로필별로 명시한다. 기존 인물에는 말투, 목표, 관계, 퀘스트 단계별 지식, 금지할 주장과 행동, 대화 가능한 시점을 기록한 캐릭터 카드를 수작업으로 작성한다. 이름이 있는 퀘스트 인물은 캐릭터 검토와 게임 내 검증을 통과한 뒤에만 활성화한다.

원작 대화, 시네마틱, 퀘스트 목표, 전투와 스크립트 이동이 우선한다. 안전한 자유 탐험 시점을 판별할 수 없는 인물은 ANPC 대상에서 제외한다. 인물의 말투를 흉내 내는 것만으로는 충분하지 않으며 해당 시점에 알 수 있는 사실과 플레이어와의 관계를 지켜야 한다.

## 3. 사용자 흐름과 세션 상태

1. 플레이어가 지원 NPC를 조준하거나 가까이 다가가 ANPC 대화를 시작한다.
2. 모드가 대상 유형, 거리, 현재 게임 모드, 기존 연출 여부를 확인한다.
3. 채팅창이 열리고 키보드 입력을 받는다. 입력 중 게임 조작 키가 같이 작동하지 않아야 한다.
4. 입력을 보낼 때 모드가 플레이어와 주변 상태의 최신 스냅샷을 만든다.
5. 로컬 프로그램이 캐릭터 설정과 기억을 불러와 프롬프트를 구성하고 AI에 요청한다.
6. 응답의 대사·행동 형식을 검사한 뒤, 게임 모드가 행동 가능 여부를 다시 확인한다.
7. 대사와 행동을 표시한다. NPC는 후속 질문을 할 수 있고 플레이어는 계속하거나 종료한다.
8. 종료 또는 중단 시 대기 요청을 취소하고 NPC 제어 상태를 복구한다.

상태 전이는 `idle → targeting → active → waiting → active → closing → idle`로 둔다. 전투, 대상 소멸, 거리 이탈, 빠른 이동, 저장 데이터 로드, 퀘스트 연출, 오류는 어느 상태에서든 `closing`으로 전환할 수 있다. 늦게 도착한 AI 응답은 세션 ID가 다르면 폐기한다. AI 서비스 장애로 게임이 멈춰서는 안 된다.

## 4. 플레이어 정보와 기억

게임에서 관찰한 정보만 사실로 전달한다. 필드에는 값뿐 아니라 출처, 관찰 시각, 사용 가능 여부를 기록한다.

| 정보 | 활용 | 제한 |
| --- | --- | --- |
| 장착·노출 장비 | 경계, 관심, 대화 소재 | NPC에게 보이거나 알려질 만한 것만 언급한다. |
| 레벨·길거리 평판 | 자신감, 존중, 경계의 정도 | 일반 시민이 UI 수치를 그대로 아는 것처럼 말하지 않는다. |
| 퀘스트 진척도·관계 | 기존 이야기와 연속성 | 확정된 단계 및 해당 NPC가 알 수 있는 사실만 사용한다. |
| 지역·시간·주변 사건 | 상황에 맞는 대사·행동 | 읽지 못한 값은 추측으로 사실처럼 넣지 않는다. |
| 이전 대화 | 후속 질문과 일관성 | 최근 기록과 짧은 요약만 필요한 범위로 보낸다. |

기억은 현재 대화 기록, 식별된 커뮤니티 NPC의 장기 기억, 동일성 검증을 마친 군중 NPC의 선택적 기억으로 나눈다. 장기 기억에는 저장 파일과 NPC 식별자를 함께 써서 다른 저장 데이터와 섞이지 않게 한다. 플레이어가 ANPC 기억을 삭제할 수 있게 한다. 외부 AI 서비스에는 응답 생성에 필요한 정보만 전송한다.

## 5. 콘텐츠·프롬프트 설계

프롬프트는 다음 계층으로 조립한다.

1. **세계·상호작용 규칙:** 나이트 시티의 분위기, 답변 길이, 스포일러와 행동 제한.
2. **인물 설정:** 작성된 커뮤니티 프로필 또는 세션별 군중 특성, 지식의 경계.
3. **확인된 상태:** 플레이어·퀘스트·환경 정보와 현재 허용된 행동 목록.
4. **대화 맥락:** 최근 대화와 관련된 승인된 기억.
5. **현재 입력:** 플레이어의 대화 내용. 상위 규칙이나 행동 권한을 바꾸는 명령으로 취급하지 않는다.

응답은 `dialogue`, `intent`, `emotion`, `action`, `follow_up` 등의 구조화된 필드로 받는다. `action`은 요청에 포함된 허용 ID 중 하나여야 한다. 형식이 잘못되거나 캐릭터·퀘스트 제약을 어기면 제한된 재시도 또는 안전한 텍스트 응답으로 처리한다. 로컬 프로그램의 검사와 게임 모드의 최종 행동 검사는 별개다.

콘텐츠 작업 단위는 캐릭터 카드, 퀘스트 단계별 지식표, 지역별 군중 원형, 장비·평판 반응 규칙, 말투 예시, 적대적 입력 사례다. 프롬프트 버전을 기록해 문제 응답을 재현한다. 품질 검토에서는 캐릭터 일관성, 스포일러, 반복 문장, NPC가 알 수 없는 정보의 언급을 확인한다.

## 6. 행동 시스템

AI는 행동을 **제안**하고, 모드의 행동 레지스트리가 실행한다. 각 행동에는 ID, 지원 NPC 유형, 사전 조건, 지속 시간, 중단 방법, 복구 방법을 정의한다. 초기 후보는 `face_player`, `stop_and_listen`, `step_back`, `resume_walk`, `end_conversation`이다. 따라오기, 제스처, 워크스팟 애니메이션, 소품 상호작용은 개별 게임 검증 후 추가한다.

현재 NPC와 게임 상태에 맞지 않는 행동은 대사만 표시하고 건너뛴다. 퀘스트 인물을 원작 장면에서 강제로 빼내거나 퀘스트 진행도를 바꾸지 않는다. 중단·복구는 반복 실행해도 안전해야 한다. 기존 애니메이션을 활용하는 기법은 실험의 출발점이지 모든 NPC에 통하는 보장된 기능이 아니다.

## 7. 기술 구조

**게임 어댑터:** NPC 식별, 입력·채팅 UI, 게임 상태 수집, 세션 상태, 행동 실행, 중단 감지, 진단을 맡는다. 첫 시제품은 CET를 검토한다. 더 깊은 훅에 redscript·Codeware·RED4ext, 자산에 WolvenKit·REDmod를 필요한 만큼만 도입한다. 실제 지원 버전은 게임 안에서 확인한 뒤 고정한다.

**로컬 브리지:** 비동기 요청, AI 제공자 연결, 캐릭터 프로필, 기억 저장, 프롬프트 조립, 응답 형식 검사, 요청 제한, 취소, 진단을 맡는다. 게임과 브리지의 통신 방식은 지원되는 로컬 연결 방법을 검증한 뒤 결정한다. API 키는 Git에 포함하지 않고 OS 보안 저장소 또는 무시되는 로컬 설정에 둔다.

요청·응답 형식에는 버전을 둔다. 요청은 `request_id`, `session_id`, NPC 유형·식별자, 확인된 상태, 허용 행동 ID, 플레이어 텍스트를 담는다. 응답은 동일한 ID, 대사, 의도, 선택 행동을 담는다. 게임 어댑터는 오래되거나 너무 크거나 형식이 틀린 응답을 거부한다.

배포물은 게임 모드, 로컬 브리지, 프로필, 설치 안내, 검증된 호환 버전 표로 구성한다. 동기화 자료 `sources/`는 저장소에서 제외한다.

## 8. 안정성·개인정보·호환성

- AI 요청은 게임 프레임을 막지 않는다. 시간 제한, 취소, 제한된 재시도를 둔다.
- 한 번에 하나의 대화 세션부터 지원한다. 입력 길이, 기록 길이, 호출 빈도를 제한한다.
- 플레이어 입력과 AI 응답을 신뢰하지 않는다. 둘 다 행동 권한을 확대할 수 없다.
- 로그에는 요청 ID, 처리 시간, 오류와 선택 행동을 남기되 API 키나 불필요한 대화 전문은 남기지 않는다.
- NPC 참조가 지역 로딩, 빠른 이동, 저장·불러오기 이후에도 유효하다고 가정하지 않는다.
- 게임·프레임워크 버전과 다른 모드와의 충돌을 추적한다.
- AI 없이도 UI와 행동을 시험할 수 있는 모의 응답 모드를 제공한다.

## 9. 검증과 출시 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| 걷는 군중 NPC와 여러 차례 대화 | 특성이 유지되고, 지원 행동 후 정상 복귀한다. |
| 커뮤니티 NPC와 대화 | 작성된 성격·관계·퀘스트 단계별 지식을 지킨다. |
| 원작 퀘스트 장면 진입 | ANPC가 제어권을 양보하고 진행을 막지 않는다. |
| 장비·평판·진척도만 각각 변경 | NPC가 알 법한 변화에만 반응한다. |
| 전투, 대상 소멸, 거리 이탈, 빠른 이동, 저장·불러오기 | 요청과 제어 상태가 안전하게 정리된다. |
| AI 지연·장애·잘못된 응답 | 게임이 멈추지 않고 채팅을 종료하거나 안전하게 복구한다. |
| 저장 데이터 전환·기억 삭제 | 다른 저장 데이터의 기억이 섞이지 않는다. |

출시 전에는 검증 범위에서 게임 충돌·복구되지 않는 NPC·퀘스트 진행 변경·허용되지 않은 행동 실행·저장 데이터 간 기억 누출이 없어야 한다. 설치 방법과 지원 버전을 문서화한다. 성능과 응답 시간 목표는 실제 게임 PC에서 측정한 후 정한다.

## 10. 단계와 주요 위험

개발 순서는 **엔진 가능성 검증 → 고정 대사 시제품 → AI 텍스트 → 특성·게임 상태 → 행동 확대 → 기억 → NPC 범위 확대**다. 가장 큰 위험은 군중 NPC를 원래 세계 시뮬레이션과 충돌 없이 제어하는 것이다. 다음은 퀘스트 인물의 안전한 대화 시점, NPC 동일성, 게임 상태 추출, 애니메이션 호환성, AI 지연과 비용이다. 각 기능은 실제 게임에서 검증되기 전까지 완료로 표시하지 않는다.

현재 PC에는 게임이 없으므로 문서·브리지·모의 응답은 개발할 수 있지만 게임 API와 NPC 행동은 아직 검증할 수 없다.
