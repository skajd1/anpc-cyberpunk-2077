# API 비용 및 응답 효율 규격

설계 버전: 0.2 (2026-10-01). 개인 API 키 연결의 호출 수·토큰·사용 한도를 관리한다. 아래 예산은 초기 설계값이며 현재 시제품에 구현된 비용 제한 기능은 아니다. 응답 필드는 [통신 규격](runtime-specification.md), 인물·지식의 의미는 [콘텐츠 규격](content-specification.md)에 둔다.

## 1. 비용 결정과 기본 정책

- 승인된 플레이어 입력 한 건에 대사·의도·감정·행동을 한 번의 생성 요청으로 받는다. 화제 분류·지식 검색·군중 특성 선택은 로컬 규칙으로 수행한다.
- 기본 텍스트 후보는 `gpt-4o-mini`다. 캐릭터별 품질 검사를 통과한 모델만 지원 프로필에 등록한다. 유명 인물이라는 이유만으로 비싼 모델을 자동 호출하지 않는다.
- 모델 변경·상위 모델 전환·백그라운드 생성·유료 기억 요약은 사용자가 명시적으로 활성화한 설정 안에서만 한다.
- 인물 정체성·금기·현재 입력·인지 제한·행동 권한·출력 스키마는 토큰 절감을 위해 제거하지 않는다. 필수 정보가 예산을 넘으면 요청 전 `context_unavailable`로 종료한다.
- 시선·듣기 자세·전투 중단·거리 이탈 같은 게임 제어는 로컬에서 처리한다. 모델을 기다리는 중의 반응은 실행 가능하고 입력 의미와 독립적인 동작으로 제한한다.

## 2. 요청 토큰 예산

토큰은 글자 수가 아니다. 해당 모델의 토크나이저로 메시지·스키마·직렬화의 입력량을 계산한다. 아래 입력 한도에는 베이스·인물·현재 입력·출력 스키마를 모두 포함한다. 지원 토크나이저가 없으면 추정임을 표시하며 정확한 비용 제한을 보장하지 않는다.

| 프로필 | 선택 조건 | 입력 총 한도 | 출력 상한 | 대사 목표 | 지식/예시 선택 한도 |
| --- | --- | ---: | ---: | --- | --- |
| 일상 대화 | 일반 인사·근황·길거리 대화 | 3500 | 256 | 1~2문장 | 사실 3개, 예시 1개 |
| 관계·사건 대화 | 이미 아는 인물·확인된 사건을 구체적으로 질문 | 5500 | 384 | 1~3문장 | 사실 5개, 예시 2개 |
| 자세한 설명 | 사용자가 자세한 설명을 요청하고 긴 응답을 허용 | 7000 | 512 | 카드 문체의 짧은 문단 | 사실 6개, 예시 3개 |

프로필은 로컬 입력·현재 화제·작성된 콘텐츠 태그로 선택한다. 확실하지 않으면 일상 대화를 사용하고 필요한 내용을 인물다운 질문으로 확인한다. 출력 상한은 인물별 말 길이를 대신하지 않으며, JSON을 중간에 자르는 방식으로 짧게 만들지 않는다. 제공자가 불완전한 출력을 반환하면 표시·행동 실행을 하지 않는다.

## 3. 지식·대화·기억 선택

실제 출력 한도는 위 프로필 상한과 연결 설정 output_token_limit 중 작은 값이다. 정체성·권한·출력 스키마의 최소 크기가 측정 예산을 넘는 콘텐츠는 임의 확대하지 않고 지원 프로필·예산을 명시적으로 조정한다.

선택 순서는 현재 게임 관찰 → 적용되는 정체성·금기·관계 → 인지·공개 조건을 통과한 관련 사실 → 유효 기억 → 관련 최근 대화 → 문체 예시다.

- 사실 검색은 승인된 로컬 콘텐츠 색인에서만 한다. 상위 검색 결과라도 인지·공개·퀘스트 조건을 통과해야 전송한다. 웹 검색 호출은 일반 대화에 넣지 않는다.
- 핵심 인물 정보와 현재 상태를 넣은 뒤 남은 예산에 최근 발화 최대 6개를 최신순으로 선택하고, 선택한 발화는 원래 시간순으로 전달한다. 주장이 잘못된 지시로 승격되지 않게 발화자·출처를 보존한다.
- 기억 선별·단기 상태·장기 조회 상한은 [NPC 기억 규격](memory-specification.md)을 따른다. 전체 기억은 전송하지 않으며 기억별 상한이 전체 입력 예산을 늘리지 않는다. 재접촉 시간·인원 한도는 [NPC 식별 규격](npc-identity-specification.md)이 기준이다.
- 초과 시 관련성 낮은 예시 → 관련성 낮은 사실 → 오래된 발화 순으로 제외한다. 현재 질문에 답하는 필수 사실과 비공개 제한은 제외하지 않는다.
- 같은 NPC 특성과 기본 세계관 묶음은 로컬에 재사용한다. 매 턴 특성 생성·AI 요약을 실행하지 않는다. 정리 조건·로컬 추출·요약 어댑터는 [기억 규격](memory-specification.md)을 따르며 유료 요약은 후속 선택 기능으로 기본 비활성화다.

## 4. 프롬프트 캐시

제공자의 프롬프트 캐시는 입력 처리 재사용이며 생성 대사를 재사용하는 기능이 아니다. 연결 유지·대화 ID 재사용만으로 캐시 적중을 보장하지 않는다.

베이스·출력 계약 → 검수된 인물 핵심·고정 문체 → 관련 사실·관찰·기억·최근 발화 → 현재 입력 순으로 배치한다. 앞부분의 문구·필드 순서·직렬화를 버전별로 고정하고 시각·거리·요청 ID 같은 변동값은 뒤로 보낸다. 사실 인지나 캐릭터 단계가 바뀌면 캐시보다 올바른 새 프롬프트를 우선한다.

`gpt-4o-mini`는 해당 모델의 암묵적 캐시 정책을 따른다. GPT-5.6 이후 전용 캐시 옵션·사전 준비 기능을 이 모델에 적용하지 않는다. 캐시를 만들 목적으로 불필요한 텍스트를 추가하거나 빈 유료 요청을 보내지 않는다. 적중 여부는 제공자 `cached_tokens` 등 실제 사용량에서 확인한다. 최소 길이·유지 시간은 모델·요청 설정에 따라 달라지므로 고정 보장하지 않는다. [공식 프롬프트 캐시 안내](https://developers.openai.com/api/docs/guides/prompt-caching)

## 5. 호출 중복·재시도·취소

| 경우 | 계약 |
| --- | --- |
| 같은 request_id의 중복 전송 | 진행 중 요청에 합류하거나 이미 처리된 결과 반환. 행동은 한 번만 실행 |
| 같은 문장을 새로 입력 | 새 턴으로 처리. 이전 턴 대사를 무조건 재사용하지 않음 |
| 인증·한도·불완전 출력·형식 오류 | 기본 자동 재시도 0회. 사용자에게 오류·재전송 안내 |
| 네트워크 오류 | 기본 자동 재시도 0회. 선택 설정으로 요청당 최대 1회, 예산·전체 제한 시간 내 허용 |
| 취소·대상 변경·게임 중단 | 통신 중단 및 결과 폐기. 이미 생성한 토큰이 청구될 수 있음을 비용 원장에 반영 |
| 종료·거리 이탈·전투 | 로컬 세션 제어. 확인용 추가 모델 호출 없음 |

생성 대사의 의미 캐시는 초기 기능에서 제외한다. 동일 입력이어도 NPC·관계·장비·퀘스트·기억·행동 결과가 달라질 수 있기 때문이다. 작성된 안전 대체 대사와 명백한 종료 처리만 로컬 재사용한다. 일반 인사를 로컬 고정문으로 바꾸는 기능은 사용자가 선택하는 콘텐츠 정책이다.

## 6. 예산·비용 원장

설정에는 `session_budget_usd`, `daily_budget_usd`를 두며 기본은 미설정이다. USD 이외의 통화 표시에는 사용자가 지정한 환율과 기준 날짜를 표시한다. 미설정일 때 임의 금액을 소비 한도로 만들지 않는다.

한도가 설정되면 요청 전에 미사용 입력 단가·최대 출력량·토큰 추정 여유분으로 예상 상한을 예약한다. 진행 중 예약까지 합쳐 한도를 넘으면 새 요청을 보내지 않고, 문맥 절감이나 낮은 비용의 지원 모델을 사용자에게 제시한다. 설정 한도의 80%에서 한 번 안내하고 100%에 도달하면 다음 요청을 차단한다. 모든 UI·백그라운드 요청은 같은 로컬 원장을 사용한다.

완료 후 실제 입력·캐시 읽기·캐시 쓰기·출력 사용량으로 추정액을 정산한다. 사용량을 받지 못한 실패·취소 요청은 0원으로 보지 않고 예약액을 미확정 비용으로 남긴다. 앱 재시작 이후에도 원장은 이어지되 대화·키는 저장하지 않는다. 원장 날짜는 사용자 시간대 기준이며 API 대시보드의 집계 경계와 다를 수 있다.

원장은 공식 청구서가 아니다. 다른 프로그램의 사용·가격 변경·제공자 측 집계 오차는 포함하지 못하므로 실제 청구 한도를 보장하지 않는다. UI에는 실제 반환 토큰과 단가로 계산한 비용 추정치를 구분한다. Codex 계정 한도는 별도이며 API 단가로 환산하지 않는다.

비용 진단에는 모델·프로필·버전·지연·입출력/캐시 토큰·재시도 횟수·예약/정산액만 남긴다. 대화 원문·개인 키·전체 인물·게임 상태는 기록하지 않는다.

### 비동기 기억 정리 예산

`memory_consolidation` 요청은 대사와 같은 원장·일일 총 한도를 사용하며 추가로 `memory_daily_budget_usd`를 적용한다. 기본값은 0이며 유료 요약 활성화와 양수 한도를 모두 설정해야 모델 호출을 허용한다. `session_budget_usd`가 설정됐으면 해당 원문을 만든 세션에 귀속하며 여러 세션 원문은 먼저 세션별로 분리한다. 앱 재시작으로 한도가 초기화되지 않는다.

초기 요약 프로필의 한 요청 입력 상한은 4000토큰, 출력 상한은 1200토큰이다. 입력에는 정리기 베이스·출력 스키마·기존 관련 기억·선택 원문을 모두 포함한다. 최대 호출 빈도는 소유자별 60초에 1회이며 비활성화·취소도 이미 시작한 호출 횟수로 계산한다. 실패·충돌·취소의 자동 유료 재시도는 기본 0회다. 재예약은 즉시 새 호출 승인이 아니며 다음 호출도 빈도·예산·원문 조건을 통과해야 한다.

토큰 계측·모델 단가가 없어 상한을 예약할 수 없으면 유료 정리를 연기하고 로컬 추출을 유지한다. 한도 부족·제공자 장애 때 대사를 위해 상위 모델로 요약하지 않는다. 취소·실패 비용은 미확정 예약으로 남긴다. 지연·사용량·원장에서는 대사와 요약을 따로 집계하고 전체 비용도 함께 표시한다. 위 수치는 초기 설계 정책이며 실제 요약 품질·속도 측정 결과가 아니다.

## 7. 단가와 계산 예시

요청 비용 추정 = 각 입력 과금 범주의 토큰 × 해당 단가 + 출력 토큰 × 출력 단가. 캐시 읽기와 쓰기는 제공자가 구분할 때만 별도 계산하며 같은 토큰을 일반 입력에도 중복 과금하지 않는다.

2026-09-30 확인한 GPT-4o mini 단가는 100만 토큰당 일반 입력 $0.15, 캐시 입력 $0.075, 출력 $0.60이다. 가격표에는 확인 날짜를 저장하고 실제 설정 시 현재 단가를 다시 확인한다. [공식 모델 가격](https://developers.openai.com/api/docs/models/gpt-4o-mini)

캐시 없이 입력 2500·출력 160토큰이면 한 요청은 약 $0.000471, 같은 요청 1000건은 약 $0.471이다. 이는 순수 텍스트의 계산 예시이며 실제 토큰량·실패/재시도·세금·환율·기타 기능 비용을 포함한 청구 예측이 아니다. 출력 예산을 낮추는 것과 실제 출력이 짧아지는 것은 구분한다.

## 8. 구현 단계

현재 시제품은 한 턴 한 번의 API 생성과 실제 사용량 일부 표시를 제공한다. 요청 예산 예약·프로필별 토큰 계측·캐시 토큰 표시·원장·자동 문맥 절감은 아직 없다. 구현과 측정 기준은 [개발 및 검증 계획](development-validation.md)에 둔다. 스트리밍은 대기 체감을 줄일 수 있지만 같은 출력량의 토큰 비용을 자동으로 줄이지 않는다. [공식 지연 최적화 안내](https://developers.openai.com/api/docs/guides/latency-optimization)
