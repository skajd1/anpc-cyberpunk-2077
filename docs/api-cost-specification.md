# API 비용 및 응답 효율 규격

설계 버전: 0.5 (2026-10-02). 설계 기본값. 입출력: [공통 규격](module-interface-specification.md)의 SelectionQuery/ModelInput/ProviderResult. 원장·요금은 로컬 정책. 구현 상태: [개발·검증 계획](development-validation.md).

## 1. 비용 결정과 기본 정책

- 승인 입력 1건당 대사/의도/감정/행동 생성 1회. 분류·검색·군중 특성·기본 제어는 로컬 처리.
- 기본 후보 gpt-6-luna, 추론 none. 인물별 품질을 통과한 지원 프로필만 활성화. 자동 상위 모델 전환 없음.
- 모델 변경·백그라운드/유료 요약은 사용자 활성 설정 내에서만 수행.
- 핵심 인물·금기·현재 입력·인지/행동 제한·출력 계약 보존. 필수 예산 초과는 context_unavailable.
- 모델 대기 중 제어는 허용된 입력 의미 독립 동작만 수행.

## 2. 요청 토큰 예산

베이스·인물·입력·메시지·스키마·직렬화를 포함하여 해당 모델 토크나이저로 계산. 미지원은 추정 표시.

| 프로필 | 선택 조건 | 입력 총 한도 | 출력 상한 | 대사 목표 | 지식/예시 선택 한도 |
| --- | --- | ---: | ---: | --- | --- |
| 일상 대화 | 일반 인사·근황·길거리 대화 | 3500 | 256 | 1~2문장 | 사실 3개, 예시 1개 |
| 관계·사건 대화 | 이미 아는 인물·확인된 사건을 구체적으로 질문 | 5500 | 384 | 1~3문장 | 사실 5개, 예시 2개 |
| 자세한 설명 | 사용자가 자세한 설명을 요청하고 긴 응답을 허용 | 7000 | 512 | 카드 문체의 짧은 문단 | 사실 6개, 예시 3개 |

프로필은 로컬 입력/화제/콘텐츠 태그로 선택. 불명은 일상 대화. 실제 출력 한도=min(프로필, 연결 output_token_limit). 불완전 JSON은 표시/실행 금지. 콘텐츠의 필수 크기는 임의 확장하지 않고 지원 프로필/예산 명시 변경.

## 3. 지식·대화·기억 선택

1. 현재 관찰·정체성/관계/금기·입력·인지/행동 제한·공통 핵심 상식·필수 사실/기억 근거 우선 확보.
2. 잔여 총 예산에 선택 지식·기억·예시·최근 발화 배정. 최근 최대 6발화를 최신순 선택 후 원래 시간순 user/assistant 메시지로 전달. context JSON 중복 금지.
3. 초과 시 낮은 관련 예시 → 사실 → 조회 기억/과거 발췌 → 오래된 최근 발화 순 제외. 필수 근거/비공개 제한 제외 금지.

승인 로컬 색인만 검색. 인지/공개/단계 조건 선필터. 일반 대화 웹 검색 없음. 원문 화자/출처 보존. 기억 한도·중복 제거: [기억 규격](memory-specification.md). 기억 한도는 총 예산의 추가분 아님. 필수 기억을 지식 개수 충족 때문에 제외 금지.

### 3.1. 인터뷰 기능의 비용 경계

진입·평판·단계 선택·기본 제어·저장/로드는 로컬. 복장/외형/무장은 텍스트 수집. 이미지 분석·변화 확인·실시간 평가·모션 생성 추가 호출 없음.

현재/과거 관찰은 같은 입력/조회 예산 사용. 과거 배정: [기억 정책](memory-specification.md#52-질문-없이도-제공하는-이전-관찰). 일상/감정/행동은 같은 생성 요청. 관련 승인 후보만 전송.

유료 요약 기본 비활성. 저장/로드로 요약 호출·지출 초기화 금지. 후속 음성은 별도 요청 종류/비용 프로필.

## 4. 프롬프트 캐시

- 고정 베이스/출력 계약 → 고정 PersonaView → 현재 지식/관찰/기억/발화 → 입력. 버전별 직렬화/필드 순서 고정. 동적 값은 뒤에 배치.
- 사실/단계 변경은 캐시보다 우선. 최종 전송 뷰/중복 제거: [프롬프트 규격](prompt-specification.md#41-기억-조회부터-전송까지의-목표-조립-과정).
- 확인된 모델 옵션만 사용. 캐시용 불필요 텍스트/유료 빈 요청 금지. 연결/대화 ID로 적중 보장 금지.
- 적중은 실제 cached_tokens 등으로 기록. 입력 토큰·적중·지연은 구현 후 측정. 생성 대사 재사용과 분리.

## 5. 호출 중복·재시도·취소

| 경우 | 계약 |
| --- | --- |
| 같은 request_id의 중복 전송 | 진행 중 요청에 합류하거나 이미 처리된 결과 반환. 행동은 한 번만 실행 |
| 같은 문장을 새로 입력 | 새 턴으로 처리. 이전 턴 대사를 무조건 재사용하지 않음 |
| 인증·한도·불완전 출력·형식 오류 | 기본 자동 재시도 0회. 사용자에게 오류·재전송 안내 |
| 네트워크 오류 | 기본 자동 재시도 0회. 선택 설정으로 요청당 최대 1회, 예산·전체 제한 시간 내 허용 |
| 취소·대상 변경·게임 중단 | 통신 중단 및 결과 폐기. 이미 생성한 토큰이 청구될 수 있음을 비용 원장에 반영 |
| 종료·거리 이탈·전투 | 로컬 세션 제어. 확인용 추가 모델 호출 없음 |

의미 기반 생성 대사 캐시 없음. 안전 대체 대사/명시 종료만 로컬 재사용. 일반 인사 고정문은 선택 콘텐츠 정책.

## 6. 예산·비용 원장

| 항목 | 규칙 |
| --- | --- |
| session_budget_usd / daily_budget_usd | 기본 미설정. 임의 소비 한도 부여 금지 |
| 타 통화 | 사용자 환율/기준 날짜 표시 |
| 요청 예약 | 비캐시 입력 단가·최대 출력·추정 여유분으로 상한 예약. 진행 예약 포함 초과 시 차단 |
| 안내/차단 | 한도 80%에서 한 번 안내, 100%에서 다음 요청 차단. 절감/지원 저비용 모델 제시 |
| 정산 | 실제 입력/캐시 읽기/쓰기/출력 사용량 적용. 미제공 실패/취소는 예약액을 미확정으로 유지 |
| 수명 | 모든 UI/백그라운드 공통 원장. 재시작 유지, 게임 로드로 지출/호출/예약 복원 금지 |
| 날짜 | 사용자 시간대 |
| 표시 | 반환 토큰과 단가 기반 추정액 구분. 공식 청구 한도 보장 없음. Codex 계정 한도 API 환산 금지 |
| 진단 | 모델·프로필·버전·지연·토큰·재시도·예약/정산액만. 원문·키·전체 상태 제외 |

### 비동기 기억 정리 예산

| 항목 | 값/조건 |
| --- | --- |
| request_kind | memory_consolidation. 대사와 별도 집계+전체 합계 |
| memory_daily_budget_usd | 기본 0. 유료 활성+양수 한도 필수. 공통 일일 한도도 적용 |
| 세션 귀속 | 설정된 session_budget_usd 적용. 여러 세션 원문은 먼저 분리 |
| 입력/출력 상한 | 4000/1200토큰. 베이스·스키마·기존 기억·원문 포함 |
| 호출 빈도 | 소유자별 60초당 1회. 시작 후 취소/비활성도 호출로 계산 |
| 자동 유료 재시도 | 실패·충돌·취소 기본 0회. 재예약에도 빈도/예산/원문 조건 재검사 |
| 예약 불가/장애 | 로컬 추출 유지, 유료 정리 연기. 상위 모델 자동 전환 금지 |

## 7. 단가와 계산

비용 추정=Σ(입력 과금 범주 토큰×단가)+(출력 토큰×단가). 캐시 읽기/쓰기는 제공자 구분 시만 분리하며 일반 입력과 중복 계산 금지.

단가는 확인 날짜와 함께 로컬 요금 설정에 저장하고 설정 시 재확인한다. 규격에 특정 가격/환율 고정 없음.

## 8. 구현 단계

구현/측정 상태는 개발·검증 계획에서 관리한다.

## 현재 웹의 기억 요약 비용

- 대사와 분리해 요약 호출 수·입출력 토큰 표시. 실제 응답 usage만 계측. 기억 로드로 호출 원장을 되돌리지 않음.
- 저장·로드·새로고침 복원은 로컬. 자동 정리는 8회 성공 대화마다, 수동 정리도 가능. 추가 API 요금 발생.
- 공통 핵심은 매 요청 제공. 상세 자료는 최대 3개. 공통 자료의 직렬화 3000자 상한은 실제 토큰 한도와 다름.
