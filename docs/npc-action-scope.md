# NPC 행동 범위 명세

규격 버전: 0.2 (2026-10-01). 이 문서는 ANPC가 제공할 행동의 의미·인수·권한·결과를 정의한다. 현재 게임 동작이 확인됐다는 의미는 아니다. 구현 근거는 [참고 분석](benchmark-analysis.md), 시험 절차는 [개발·검증 계획](development-validation.md)에 둔다.

## 1. 범위와 권한

행동은 기본 범위와 확장 범위로 구분한다. 기본 범위는 텍스트 대화에 필요한 제어·시선·짧은 이동이다. 확장 범위는 동행·제스처·표정·생활 동작·자산 연출·차량·거래다. 실행 모드에서는 배포 프로필의 등록 실행기·대상 기능·카드·현재 상태가 허용한 행동만 요청 목록에 포함한다. 선택 전용 모드는 승인된 행동 설명과 인수 후보를 제공하되 실행 지원과 별도로 표시한다.

실제 실행 허용 목록은 배포 실행 지원 목록 ∩ NPC 기능 ∩ 캐릭터 카드 ∩ 현재 게임 상태다. 선택 전용 목록도 배포의 승인 선택 목록·카드·대상 조건으로 제한하며 임의 행동을 생성하지 않는다. 커뮤니티는 원작 역할과 금기를 유지한다. 군중은 현재 살아 있는 인스턴스에만 명령을 실행한다. AI는 요청당 행동 하나를 제안하며 코드를 실행하거나 게임 자산 경로를 지정할 수 없다.

위치·차량·워크스팟·소품·제스처는 모드가 발급한 후보 ID로 지정한다. AI가 원시 좌표·엔티티 ID·파일 경로·아이템 ID를 새로 만들 수 없다. 모든 단위는 미터·초이며 아래 수치는 초기 제품 정책 기본값이다.

### 1.1. 행동 선택과 실행 모드

기본 세션 제어는 stop_and_listen, face_player, resume_walk, end_conversation이다. 첫 게임판에서는 세션용 멈춤·V 시선·정리·종료를 실제 실행한다. 추가 이동·제스처·표정·생활 동작은 우선 selection_only로 선택 결과를 보여주고 후속 execute 모드에서 지원 어댑터를 통해 실행한다. 현재 웹 시제품의 기본 제어는 가상 실행이며 비교 화면은 개발용 제스처 후보 3개를 선택만 표시한다. 실제 게임 모션·외부 모드 연동은 미구현이며 [시제품 안내](dialogue-prototype.md)를 따른다.

로컬 action_mode는 추가 행동의 기본 모드를 나타낸다. allowed_actions 항목은 action_id, 설명, 인수 후보, execution_mode(selection_only/execute)를 가진다. 기본 세션 제어의 execute 권한과 추가 행동의 selection_only 권한은 혼합할 수 있으며 각 항목의 모드를 최종 권한으로 사용한다. 실행 가능 목록은 반드시 현재 어댑터 상태를 반영한다. 모델 출력은 기존 action_id/args이며 권한·모드를 모델이 바꾸지 않는다.

선택 전용은 인수·카드·콘텐츠 검사를 통과한 제안을 selection_state=selected로 표시한다. 실행 상태는 proposed에 머물고 게임 명령·실행 성공 효과·action_result 성공 기억을 만들지 않는다. 캐릭터 자막에 “손을 흔들었다” 같은 실행 서술을 추가하지 않는다. action_catalog_version이 바뀌면 다시 검증하며 선택 전용 결과가 뒤늦게 자동 실행되지 않게 한다. execute로 바꾸면 새 요청과 현재 권한 검사가 필요하다.

대사와 행동은 한 생성 요청에서 함께 선택한다. 감정·화제·인물 선호에 맞는 행동 후보가 없으면 null이 정상이다. 제스처를 넣기 위해 원작 관계나 대사 의미를 바꾸지 않고 매 턴 동작을 강제하지 않는다.

## 2. 공통 행동 계약

입력은 action_request_id, session_id, request_id, npc_instance_key, action_id, args다. 동일 action_request_id의 재전달은 원래 결과를 반환하고 중복 실행하지 않는다.

상태는 proposed → accepted → running → succeeded/failed/cancelled다. 조건 거부는 rejected로 끝낸다. 반환 필드는 action_request_id, status, reason_code, started_at, ended_at, observed_effect다. succeeded는 실제 완료 조건을 만족했을 때만 사용한다.

거부·실패 사유는 unsupported, forbidden, invalid_args, stale_target, unsafe_state, unreachable, occupied, timeout, interrupted, adapter_error다. 행동 거부만으로 유효한 대사를 삭제하지 않는다. 완료 전에는 행동을 이미 수행했다는 대사를 확정하지 않는다.

동시에 이동 또는 전신 연출 하나만 실행한다. 새 명령은 기존 ANPC 명령을 정리한 뒤 시작한다. 시선은 실행기가 허용하는 경우에만 병행한다. 원작 명령을 일괄 취소하지 않는다.

이동 목적지는 같은 높이·길찾기 가능 공간이어야 한다. 차도·낙차·닫힌 장애물·점유 위치는 제외한다. 판정 정보가 없으면 실행을 거부한다. 이동 실패 시 ANPC 제어를 해제하며 일반 행동으로 순간이동하지 않는다.

stop_and_listen은 모델 응답을 기다리기 위해 세션 관리자가 실행할 수 있다. 위치 유지와 대화의 전체 수명은 세션 관리자에 귀속되며 행동 완료 이후에도 종료 정리 대상으로 기록한다.

군중의 차량 운전·무장 변경·보상 지급은 기본 금지다. 퀘스트 장비와 원작 경제 데이터를 덮어쓰지 않는다. 지급 동작은 손으로 건네는 애니메이션을 포함하지 않는다. 실패 또는 취소 후 완료 여부가 불명확한 거래는 재실행하지 않고 오류를 반환한다. 운전은 별도 후속 이동 세션에만 허용하며 초기 대화 세션에서는 실행하지 않는다.

## 7. 콘텐츠 조합

react_to_other_npc와 greet_on_recontact는 실행 행동 ID가 아니라 콘텐츠 의도다. 전자는 look_at_target 또는 play_gesture와 대사를, 후자는 유효 기억과 face_player 또는 대사를 조합한다. 모델 응답의 action_id에 이 의도를 넣으면 거부한다. 실제 실행 목록은 앞 절의 27개 ID로 한정한다.

## 8. 중단·복구 의무

세션 종료·전투·퀘스트 제어·세계 전환·대상 소멸은 실행 중 행동을 취소한다. ANPC 소유 명령·시선·장비 변경·임시 소품·엔티티만 정리한다. 이전 상태를 복구할 때 현재 원작 상태와 충돌하면 복구 덮어쓰기를 생략하고 원작 제어를 우선한다. 대상이 소멸하면 객체 호출 없이 내부 참조만 폐기한다. 정리는 반복해도 같은 결과여야 한다.

## 9. 범위 밖

임의 퀘스트 변경, 도망·엄폐·항복·공격 명령, 임의 문·터미널 조작, 악수 등 동시 배우 동작, 실시간 립싱크 생성, 자율 생활 일정, 군중 영속화는 현재 행동 계약에서 제외한다. 확장 범위의 정의는 지원 완료 선언이 아니며 배포 프로필의 지원 여부가 실행 권한을 결정한다.

## 10. 기존 게임·모드 행동 연동

후속 행동은 기존 게임 모션·워크스팟 또는 기존 모드가 제공하는 동작을 재사용하는 것이 기본이다. 신규 모션 직접 제작이나 런타임 생성은 요구하지 않는다. 특정 모드 설치를 현재 필수 의존성으로 고정하지 않으며 실제 공개 호출·취소 인터페이스와 사용 조건을 확인한 어댑터만 활성화한다.

모드 어댑터는 공통 action_id를 외부 모드의 호출 방식으로 변환한다. AI에는 의미·현재 인수 후보·실행 모드만 제공하고 외부 함수명·자산 경로·원시 객체 ID·코드는 제공하지 않는다. 행동 자산 목록은 candidate_ref, 의미/화제 태그, 호환 인물/골격, 점유 슬롯, 길이/종료 조건, adapter_id/version, 취소·복구 정책을 가진다. 외부 모드가 임의 등록한 자산을 검수 없이 실행 후보로 올리지 않는다.

| 인터페이스 | 입력 → 결과 | 계약 |
| --- | --- | --- |
| ActionAdapter.describeCapabilities | 설치·버전·NPC·현재 상태 → 지원 후보 | 미설치·버전 미지원·호환 실패 후보는 execute 목록에서 제외 |
| ActionAdapter.validate | 세션·후보·인수·현재 보호 상태 → 허용/거부 | 실행 직전 권한·인물·점유·제어권 재확인 |
| ActionAdapter.execute | 승인 요청 → 실행 handle·진행 이벤트 | 외부 모드 명령은 등록된 매핑만 사용. 중복 실행 차단 |
| ActionAdapter.cancel | handle·사유 → 취소/실패 결과 | 전투·퀘스트·종료·소멸·시간 초과에 대응 |
| ActionAdapter.release | handle → 제어/임시 자산 정리 결과 | ANPC가 소유한 범위만 반복 안전하게 해제 |

대사 의도·감정·화제와 승인 태그로 후보를 로컬 선별한 뒤 AI가 최대 하나를 선택한다. “동의”에 맞는 끄덕임, “거절”에 맞는 손짓 등은 작성 후보 예시이며 실제 지원 모션을 확인한 뒤 등록한다. 공개 UI에서 수동 재생할 수 있다는 사실만으로 프로그램 호출·취소가 지원된다고 간주하지 않는다.

다른 모드나 원작이 NPC를 제어하면 occupied/unsafe_state로 거부한다. 외부 모드 상태가 변경·소실되면 새 실행을 막고 지원된 취소·복구 경로를 사용한다. 확실한 취소·제어 반환을 제공하지 못하는 전신/생활 동작은 실시간 대화의 execute 지원에서 제외한다. 타임아웃만으로 성공 처리하지 않는다. 실패해도 독립적인 유효 대사는 자막으로 유지하고 서비스·연동 오류는 별도 UI에서 표시한다.
