# 개발 및 검증 계획

갱신: 2026-10-01. 이 문서에 구현 순서·시험 절차·현재 검증 상태를 모은다. 제품 동작의 기준은 [전체 명세](full-specification.md)와 분야별 규격이다.

## 1. 현재 상태

[API 비용 규격](api-cost-specification.md)의 프로필·토큰 한도·원장과 [프롬프트 명세](prompt-specification.md)의 생활 대사 규칙을 설계했다. 현재 시제품의 `/compare`에서 10명 초안 카드·lived_context·지식·관련 예시·상기를 조립할 수 있다. 실제 게임 키·단계·관계·한국어 말투와 출시 승인 카드, 전체 비용 예산 계산은 미완성이다. 문서의 공식 근거와 대사 예시는 모델 품질 검증 결과가 아니다. 베이스 템플릿 변경은 서버가 문서를 다시 읽을 때 적용된다.

Codex 유지 연결로 전환한 시험에서는 모델 조회 후 같은 실행기에서 생성한 두 요청이 각각 11.5초·9.1초였다. 두 응답 모두 엔진 검사를 통과했다. 앞선 단발 실행 10.4초·10.6초와 비교해 뚜렷한 속도 개선은 확인되지 않았다. 동일 모델·입력·캐시 조건의 반복 비교는 아니므로 원인이나 개선율을 확정하지 않는다. 연결 공유·동시 요청 격리·취소 후 늦은 응답 폐기·프로세스 종료 후 재연결을 포함한 자동 검사 19개가 통과했다. 유지 연결의 실제 취소 경로는 프로토콜 가짜 실행기로 검사했으며, 실제 모델에서 취소 지연은 추가 측정 대상이다.

설계와 공개 자료 분석에 이어 [게임 없는 대화 시제품](dialogue-prototype.md)을 구현했다. 현재 PC에는 게임이 없으며 ANPC의 게임 API·행동·버전 호환성·성능은 검증하지 않았다. 기본값은 설계 정책이며 실측으로 확인된 권장 수치가 아니다. 게임판 HTTP 어댑터·키 저장소·실제 객체 매핑은 구현 시 확정할 항목이다. OpenAI API의 실제 키 호출과 모델 간 품질 비교는 수행하지 않았다.

2026-09-30에 Codex CLI의 실제 ChatGPT 로그인 연결을 확인했다. 배달원 대사 두 건이 응답·행동 검사를 통과했고 직접 실행은 약 10.4초, 로컬 HTTP 경로는 약 10.6초가 걸렸다. 무기를 꺼낸 상황에서는 무기를 내려달라는 대사, 일반 인사에서는 배달 중이라는 대사와 2초간 플레이어를 바라보는 가상 행동이 생성됐다. 단 두 요청이므로 응답 속도·인물 일관성의 일반적인 품질 판정은 아니다. 자동 검사 15개는 모두 통과했으며 실제 자식 프로세스 취소·시간 제한도 확인했다.

2026-10-01에 주디·팬앰 비교 화면과 조건·지식·예시 선별을 연결했다. 브라우저 모의 시험에서 BD 편집 전문 지식은 주디에게만 전달되고 두 대화가 나란히 표시되는 것을 확인했다. 원시/표시 응답과 프롬프트·선별 자료를 볼 수 있으며 수동 검수 의견은 실행 중에만 유지한다. 개인 API/Codex로 두 인물의 실제 대사를 호출하거나 자동 채점을 수행하지 않았다. 모델 품질 시험 전의 기능 검증이다. 기존 19개와 새 조사 비교 7개를 합친 `npm test` 26개, `node scripts/validate-content.mjs`의 콘텐츠 검사가 통과했다. 새 검사는 초안·단계 차단, 인물별 전문 지식 분리, 렐릭의 회피 제한과 내용 제외, 구성별 주입, 기억 격리·무단 행동 차단·취소, 로컬 자료 경로 보호를 포함한다.

2026-10-01에 출신·직업·생활 경험별 지식 깊이를 보완했다. 기본 지식 체크가 팬앰에게 BD 개요를 일괄 부여하던 문제를 수정했다. 10개 카드에 분야별 상한·근거 상태를 작성하고 154개 항목에 분야·요구 깊이를 연결했다. 초안이며 실제 원작 인지 장면을 전부 검수한 결과는 아니다. 자동 검사에 체크 우회 차단, 카드만 구성의 경계 유지, 낮은 깊이에서 전문 예시 제외를 추가했다. 팬앰의 BD 무지를 원작 사실로 확정하지 않는다. 처음에는 전문 예시가 필수 지식 참조 없이 선택되는 검사가 실패했고, 주디 BD 예시의 필수 사실과 분석 별칭을 보완한 뒤 26개 검사가 모두 통과했다. 콘텐츠 검사와 문서 링크 131개도 통과했다. 서버 4174를 재시작해 새 자료를 반영했으나 이번 변경의 브라우저 재확인은 연결 시간 초과로 완료하지 못했다. 실제 모델 품질 평가는 수행하지 않았다.

2026-10-01에 인물 선택·설정 시각화를 추가했다. manifest에서 10명을 로드하고 단독 또는 2명 비교를 선택한다. 신념·목표·두려움·금기·생활 경험·말투, 분야별 깊이·근거 상태와 후보 표를 표시한다. 화면과 생성기가 같은 지식 허용 판정을 사용한다. 자동 검사 29개와 콘텐츠 검사, 신규 브라우저 스크립트 구문 검사가 통과했다. 브라우저에서 팬앰 BD 미확인/미주입 이유, 지식 검색, 빅터 단독 모의 요청 1건과 의료 지식 주입 표시를 확인했다. 실제 모델 호출·인물 품질 판정은 수행하지 않았다.

같은 날 비교 화면을 왼쪽 설정·중앙 채팅·오른쪽 특성의 3열로 단순화했다. 10명 카드의 화면 전용 요약은 원본 정체성·생성 입력을 바꾸지 않는다. 자동 검사 30개·콘텐츠 검사·스크립트 구문 검사·수정 문서 링크 검사가 통과했다. 실제 브라우저에서 3열 배치, 2명 모의 응답, 단독 인물 전환, API 설정 표시와 접힌 요청 상세를 확인했다. 이 변경의 확인에는 유료 모델 호출을 사용하지 않았다.

질문 프리셋 6개와 요청 상태·경과 시간·인물별 입력/출력 토큰 표시를 추가했다. 별도 로컬 테스트 제공자로 대기·완료·취소 및 토큰 표시를 확인했으며 외부 모델은 호출하지 않았다. 제공자가 사용량을 반환하지 않으면 0으로 표시하지 않는다. 공식 게임 소개를 확인해 PLAYER_V를 공통 신원 사실로 추가하고 프리셋·화면 화자·모델 문맥의 이름을 같은 데이터에서 읽도록 했다. 자동 검사 34개, 콘텐츠·구문·문서 링크 검사가 통과했고 브라우저에서 V 표시와 프리셋 불러오기를 확인했다. 이름 V만 맞히는 응답은 대화 기억의 증거가 아니므로 기억 품질 평가는 별도의 대화 내용으로 확인해야 한다.

## 2. 개발 순서

### 단기·장기 기억의 후속 적용 순서

2026-10-01에 [NPC 기억 규격 1.0](memory-specification.md)을 작성했다. 단기 문맥·장기 기록·지식 캐시의 구분, 출처 보존, 비동기 정리, 저장 시점 검사, 용량과 전용 요약 계약을 확정했다. 규격 작성이며 코드·DB·워커·유료 요약을 구현하거나 실행한 상태는 아니다. 기존 시제품은 이전 임시 memory 형식을 사용한다.

이번 문서 변경의 로컬 링크 168개·제목 앵커 14개·JSON 예시 1개와 코드 블록 짝 검사가 통과했다. 기존 시제품 자동 검사 34개도 통과했다. 기억 규격의 새 워커·영구 저장·요약 품질·전경 지연을 검증한 결과는 아니며 외부 유료 모델 호출은 하지 않았다.

1. MemoryStore·확정 사건·세대·버전 계약을 시제품에 연결하고 기존 임시 기억에서 새 읽기 뷰로 변환하는 어댑터를 만든다. 기존 기억에 원문 근거가 없으면 확인된 장기 사실로 승격하지 않는다.
2. 로컬 태그 검색·단기 상태·장기 조회·중복 제거·토큰 예산을 연결한다. 최근 원문과 미해결 항목을 보존하는 local_extract를 먼저 구현한다.
3. 가짜 정리기로 큐·범위 병합·원자적 커밋·대사 우선·실패 복구·삭제 세대·강제 용량을 검사한다. 이 단계에는 실제 유료 요약이 필요 없다.
4. 개인 키 요약 어댑터를 선택 설정으로 연결한다. 실제 실행 전에 기억 일일 한도·단가·토큰 계측·지원 프로필을 설정한다. 동일 대화 자료로 local_extract와 llm_consolidate의 보존 품질·전체 비용·전경 지연을 비교한다.
5. 게임 대상 키·저장 체크포인트·분기 검증 후 커뮤니티의 영구 저장을 연결한다. 게임 저장 매핑이 없는 동안 영구 기억을 활성화하지 않는다.

이 작업은 기존 게임 통합 순서의 후속 기억 단계에서 적용한다. 첫 배포 범위나 유료 호출 기본값을 확대하지 않는다.

### 기억 구조 확인 시나리오

| 시나리오 | 확인할 결과 |
| --- | --- |
| 오래된 사건의 재질문 | 관련 장기 항목만 조회, 전체 기억 재전송 없음 |
| 자주 쓰는 기억·지식 | 단기 사본·조회 캐시 재사용, 출처·인지 상한 유지 |
| 약속·갈등·미해결 질문 | 오래돼도 보호, 명시적 해결 근거 전까지 삭제·해결 없음 |
| 플레이어 주장·허위 세계관 | player_claim 유지, 승인 사실·고정 정체성 변경 없음 |
| 행동 제안·실패·완료 | 성공 기억은 실행기가 확인한 completed 효과만 |
| 요약 중 다음 입력 | 대사가 요약 완료를 기다리지 않고 정상 스냅샷 사용 |
| 요약 뒤에 새 발화 추가 | 정리 범위 뒤 기록 보존, 다음 범위로 정리 |
| 중복·동시 커밋 | 같은 작업 한 번 반영, revision 충돌은 덮어쓰기 없음 |
| 삭제·NPC 소멸·로드 중 늦은 응답 | 이전 세대·world_epoch 작업이 기억을 복구하지 않음 |
| 게임의 과거 저장·다른 분기 | 미래 기억·다른 분기 제외, 불명확한 매핑은 연결 거부 |
| 다른 NPC·저장 계보·군중 재생성 | 기억 누출·승계 없음 |
| 요약 거짓 근거·누락·잘못된 형식 | 후보 차단·원문 유지, 기존 정상 기억 보존 |
| 원자적 반영 중 종료 | 이전 정상 상태 또는 완료된 새 상태로 복구 |
| 큐·원문·요약 용량 초과 | 표식 재예약·보호 항목 유지·명시적 입력 차단, 조용한 손실 없음 |
| 요약 한도 0·실패·취소·가격 미확인 | 무단 호출 없음, 실제·미확정 비용 기록, 전경과 별도 집계 |

요약 품질은 근거 없는 추가, 주장 유형 변경, 중요한 항목 누락, 잘못된 약속 해결, 재조회 정확도를 사람 검수 자료와 비교한다. 구조 검사만으로 의미적 정확성을 보장했다고 보고하지 않는다. 기억 평가는 사전에 없는 새 대화 내용을 사용하며 공통 사실인 V의 이름을 맞히는 것만으로 통과하지 않는다. 임계값과 품질 합격선은 파일럿 결과를 근거로 정하고 문서의 설계 수치를 실측으로 표기하지 않는다.

### 비용·콘텐츠 설계의 확인 기준

- 일상·관계·긴 설명 입력의 실제 토큰을 측정해 설정 예산 안에서 정체성·현재 질문·인지 제한이 유지되는지 확인한다.
- 같은 시나리오를 기존/최적화 입력으로 비교해 정상 응답당 비용, 입력/출력/캐시 토큰, 첫 생성 조각·검증 완료 시간, 실패·재시도 비율을 기록한다. 가격표·모델·버전·조건을 함께 고정한다.
- 무기·기업·BD·동료를 버리는 제안·유명세 주장·재접촉·숨은 퀘스트 질문을 여러 카드에 제시한다. 말투뿐 아니라 선택·거절 이유가 달라지는지 확인한다.
- 원작 사실과 창작 생활 설정을 뒤섞거나, 모르는 플레이어를 가족·연인으로 취급하거나, 모든 군중이 유명 인물의 비밀을 아는 응답은 비용이 낮아도 탈락시킨다.
- 예산 차단·미확정 취소 비용·앱 재시작·캐시 미적중·중복 요청에서 추가 호출과 행동 중복이 없는지 확인한다. 실제 유료 시험은 설정된 사용 한도 안에서 수행한다.

### 게임 통합 순서

1. 규격 데이터와 모의 게임 상태로 콘텐츠 로드·요청 조립·응답 검사·기억 분리를 구현한다.
2. 게임 PC에서 대상 조회·NPC 분류·보호 상태·키·비동기 통신 어댑터의 연결 가능성을 확인한다.
3. AI 없이 고정 대사로 군중 1명과 자유 상태 커뮤니티 1명의 시작·정지·시선·해제를 구현한다.
4. API 연결·콘텐츠·근거리 재접촉 기억을 통합한다.
5. 초기 버전 출시 조건을 충족한 뒤 이동·자산 연출·차량·거래를 각각 확대한다.
6. 장기 기억과 NPC 음성·자막은 별도 단계로 진행한다.

군중 대상 성공을 전용 생성 NPC의 성공으로 대체하지 않는다. 특정 기능 실패 시 제품 범위를 바꾸기 전에 실패 원인과 영향 대상을 기록한다.

## 3. 규격 검사

### 조사 콘텐츠 묶음

`content/cyberpunk2077/`에 인물 10명·사실·인지 조건·작성 예시·군중 지식 묶음을 저장했다. `node scripts/validate-content.mjs`로 JSON·ID·출처·조건·소유 인물·예시 참조와 군중 비밀 지식 제외를 검사한다. 주디·팬앰의 개발용 로더·정규화·선별을 연결했다. 실제 게임 키·단계 매핑, 원작 장면·한국어 문체 검수, 군중 지식 배분기는 남아 있다. 전체 게임의 모든 원작 자료를 확보한 것으로 기록하지 않는다.

다음 콘텐츠 작업은 군중 원형별 특성 풀·판단 규칙·문체를 작성하고 승인된 직업·지역 지식을 연결하는 것이다. 선택 지식의 첫 생성 추첨과 재접촉 고정, 상식·필수 전문 지식 유지, unknown 조건 차단을 검증한다. 인물별 조사 근거·보류 항목은 [조사 안내](community-npc-catalog.md)에 둔다.

### 캐릭터 정체성 비교

확정된 정체성 구조 1.0의 규격 검사에서는 군중 슬롯별 한 후보·총 3개, 조합 조건·금기·문체 호환성, 유효한 기본 조합, 동일 seed·콘텐츠·생성기 버전의 재현, 재접촉 시 데이터 재사용, 무효화 후 새 등록을 확인한다. 커뮤니티 인물에 무작위 특성이 적용되거나 상황 변화로 고정 가치가 재추첨되면 실패다. 원형·특성·규칙·예시 참조와 승인 상태도 검사한다.

### 대화 평가 수행 계획

점수 축·중대 위반·근거 수준·데이터·합격선의 기준은 [대화 정체성 평가 규격](dialogue-evaluation-specification.md)이다. 이 절은 수행 순서만 정의한다. 현재 카드는 draft이며 출시 원작 충실도 평가에 필요한 장면·한국어 말투 자료는 미완성이다. 평가 자료와 실행기도 아직 구현하지 않았고 AI 평가 요청·유료 생성 시험은 이번 작업에서 수행하지 않았다.

1. 주디·팬앰을 먼저 대상으로 정하고 검수자가 원작 장면·관계·인지 근거를 작성한다. 새 상황의 허용 반응은 authored_approved로 구분한다. 카드 작성자가 자신의 창작 대사를 원작 정답으로 승인하지 않는다.
2. development 세트에서 사례별 적용 축·허용 선택·금지 주장·기억·상태를 고정한다. 초기는 인물당 30개 사례를 목표로 한다. 가치 6, 지식 4, 관계 4, 일상·문체 4, 기억 4, 압력 4, 상황 적응 4개다. 사례는 여러 축을 평가할 수 있다. 2명 총 60개를 각 설정에서 3회 반복하되 다중 턴 사례의 실행 1회는 전체 대화 경로를 뜻한다. 비용 한도 승인 후 실행하며 180개 실행이 180개 독립 장면 근거라는 뜻은 아니다.
3. 카드만 / 관련 지식 추가 / 관련 지식·예시·상기 추가 구성을 비교한다. 생성 모델·입력·게임 상태·콘텐츠·관계·출력 한도를 고정하고 현재 시제품에 기능을 연결한 뒤 실제로 조립된 프롬프트를 보관한다. 한꺼번에 모델·콘텐츠·프롬프트를 바꾼 결과로 원인을 단정하지 않는다.
4. 평가자 보정용 calibration 자료는 별도 장면군에서 만든다. 초기 50개 응답(중대 위반 20, 정상 20, 경계 10)을 목표로 하고 두 사람이 독립 판정한다. 인위적으로 균형을 맞춘 보정 자료의 실패 비율을 실제 서비스 실패율로 보고하지 않는다. 사람 불일치는 근거로 조정하고 AI 평가자의 점수·위반 탐지·편향과 비교한다.
5. AI 채점의 초기 사용 승인 목표는 핵심 축의 선형 가중 kappa 각각 0.6 이상, 확인된 중대 위반 탐지 재현율 95% 이상이다. 프로젝트 보정 목표이지 논문이 보증한 기준이 아니다. 표본 수·오탐·A/B 순서 불일치도 기록한다. 미달하면 AI 점수를 최종 판정에 사용하지 않고 사람 검수를 유지한다. 작은 표본의 목표 충족만으로 신뢰성을 확정하지 않으며 release의 중대 위반·보류는 사람이 확인한다.
6. 세트·루브릭을 고정한 후 분리된 release 장면군으로 지원 후보를 판단한다. 근거·임계값의 변경은 평가 버전을 올리고 같은 구성들을 재평가한다. 실제 결과 전에는 모델별 통과율·지원·학습 필요성을 확정하지 않는다.
7. 두 인물에서 평가가 작동하면 나머지 8명으로 확장한다. 군중은 승인 원형과 추첨된 정체성에 대한 일관성을 평가하고 대표 조합·충돌 경계·기본 조합·재접촉·무효화를 포함한다. 생성 seed와 선택 지식은 고정해서 비교한다.

위 사례 수·반복·보정 목표는 파일럿 계획이다. 자동으로 비용을 사용하는 작업 예약이 아니다. 지연·비용·요청 실패·대체 대사 사용률은 생성 품질과 따로 집계한다. 원작 장면·질문은 예시/학습 자료와 장면군 단위로 분리한다. 조사 근거는 [정체성 벤치마킹 분석 8절](character-identity-benchmark.md#8-대화-평가-연구와-적용-근거)에 둔다.

| 항목 | 검사 |
| --- | --- |
| 콘텐츠 | 중복 ID·누락 참조·잘못된 조건·지식 공개 오류 |
| 요청·응답 | 길이 제한·열거값·허용 행동·중복 실행·늦은 응답 |
| 기억 | 같은 인스턴스 재사용, 다른 NPC·저장 계보에 누출 없음 |
| 모델 | 동일 사례의 인물별 판단·말투·금기·스포일러·형식·비용·지연 |
| 개인정보 | 키·인증 헤더·기본 대화 원문이 로그에 없음 |

모델 품질은 캐릭터 두 명에게 동일 사건을 제시하고 목표·판단·행동 차이를 비교한다. 형식 검사를 통과하는 것만으로 콘텐츠 품질 통과로 처리하지 않는다. 지원 모델 목록은 실제 결과를 기록한 뒤 작성한다.

## 5. 지원 판정과 기록

시험 결과는 게임·프레임워크 버전, 코드 커밋, NPC 레코드·유형, 자산, 장소, 시작 상태, 명령 결과, 중단·복귀 결과를 기록한다. 기본 행동의 제어 반환과 원작 보호가 실패하면 해당 대상은 지원 목록에서 제외한다.

출시 조건은 시험 범위에서 충돌·복구 불가 NPC·퀘스트 진행 변경·무단 행동·기억 누출이 없고 설치·제거 안내와 지원 버전이 존재하는 것이다. 모델·네트워크 성능과 자산 호환성은 미측정 상태를 명시한다.
