# 개발 및 검증 계획

갱신: 2026-10-01. 이 문서에 구현 순서·시험 절차·현재 검증 상태를 모은다. 제품 동작의 기준은 [전체 명세](full-specification.md)와 분야별 규격이다.

## 0. 최신 범위와 과거 기록

2026-10-03에 선택 후속 [플레이어 음성 인식 규격](speech-recognition-specification.md)과 호스트 인터페이스를 추가했다. 첫 게임판 텍스트 입력은 유지한다. 마이크·전사·PTT·브리지는 아직 구현/실측하지 않았으며, 아래 과거 기록의 플레이어 음성 제외는 당시 범위다.

2026-10-01 인터뷰 확정 요구사항을 전체 문서에 반영했다. 현재 웹 시제품·첫 게임판 목표·후속 행동/음성의 기준은 [초기 명세](initial-design.md)다. 아래의 이전 날짜/단계별 검증 기록은 당시 상태이며 최신 범위를 축소하거나 새 기능 구현 완료를 뜻하지 않는다. 이번 변경은 문서와 서버가 읽는 공통 베이스 템플릿의 개정이며 화면·게임 어댑터·저장소 구현 작업은 별도다. 베이스는 서버가 다음에 문서를 읽을 때 적용된다.

## 1. 현재 상태

[API 비용 규격](api-cost-specification.md)의 프로필·토큰 한도·원장과 [프롬프트 명세](prompt-specification.md)의 생활 대사 규칙을 설계했다. 현재 시제품의 `/compare`에서 10명 초안 카드·lived_context·지식·관련 예시·상기를 조립할 수 있다. 실제 게임 키·단계·관계·한국어 말투와 출시 승인 카드, 전체 비용 예산 계산은 미완성이다. 문서의 공식 근거와 대사 예시는 모델 품질 검증 결과가 아니다. 베이스 템플릿 변경은 서버가 문서를 다시 읽을 때 적용된다.

Codex 유지 연결로 전환한 시험에서는 모델 조회 후 같은 실행기에서 생성한 두 요청이 각각 11.5초·9.1초였다. 두 응답 모두 엔진 검사를 통과했다. 앞선 단발 실행 10.4초·10.6초와 비교해 뚜렷한 속도 개선은 확인되지 않았다. 동일 모델·입력·캐시 조건의 반복 비교는 아니므로 원인이나 개선율을 확정하지 않는다. 연결 공유·동시 요청 격리·취소 후 늦은 응답 폐기·프로세스 종료 후 재연결을 포함한 자동 검사 19개가 통과했다. 유지 연결의 실제 취소 경로는 프로토콜 가짜 실행기로 검사했으며, 실제 모델에서 취소 지연은 추가 측정 대상이다.

설계와 공개 자료 분석에 이어 [게임 없는 대화 시제품](dialogue-prototype.md)을 구현했다. 현재 PC에는 게임이 없으며 ANPC의 게임 API·행동·버전 호환성·성능은 검증하지 않았다. 기본값은 설계 정책이며 실측으로 확인된 권장 수치가 아니다. 게임판 HTTP 어댑터·키 저장소·실제 객체 매핑은 구현 시 확정할 항목이다. OpenAI API의 실제 키 호출과 모델 간 품질 비교는 수행하지 않았다.

2026-09-30에 Codex CLI의 실제 ChatGPT 로그인 연결을 확인했다. 배달원 대사 두 건이 응답·행동 검사를 통과했고 직접 실행은 약 10.4초, 로컬 HTTP 경로는 약 10.6초가 걸렸다. 무기를 꺼낸 상황에서는 무기를 내려달라는 대사, 일반 인사에서는 배달 중이라는 대사와 2초간 플레이어를 바라보는 가상 행동이 생성됐다. 단 두 요청이므로 응답 속도·인물 일관성의 일반적인 품질 판정은 아니다. 자동 검사 15개는 모두 통과했으며 실제 자식 프로세스 취소·시간 제한도 확인했다.

2026-10-01에 주디·팬앰 비교 화면과 조건·지식·예시 선별을 연결했다. 브라우저 모의 시험에서 BD 편집 전문 지식은 주디에게만 전달되고 두 대화가 나란히 표시되는 것을 확인했다. 원시/표시 응답과 프롬프트·선별 자료를 볼 수 있으며 수동 검수 의견은 실행 중에만 유지한다. 개인 API/Codex로 두 인물의 실제 대사를 호출하거나 자동 채점을 수행하지 않았다. 모델 품질 시험 전의 기능 검증이다. 기존 19개와 새 조사 비교 7개를 합친 `npm test` 26개, `node scripts/validate-content.mjs`의 콘텐츠 검사가 통과했다. 새 검사는 초안·단계 차단, 인물별 전문 지식 분리, 렐릭의 회피 제한과 내용 제외, 구성별 주입, 기억 격리·무단 행동 차단·취소, 로컬 자료 경로 보호를 포함한다.

2026-10-01에 출신·직업·생활 경험별 지식 깊이를 보완했다. 기본 지식 체크가 팬앰에게 BD 개요를 일괄 부여하던 문제를 수정했다. 10개 카드에 분야별 상한·근거 상태를 작성하고 154개 항목에 분야·요구 깊이를 연결했다. 초안이며 실제 원작 인지 장면을 전부 검수한 결과는 아니다. 자동 검사에 체크 우회 차단, 카드만 구성의 경계 유지, 낮은 깊이에서 전문 예시 제외를 추가했다. 팬앰의 BD 무지를 원작 사실로 확정하지 않는다. 처음에는 전문 예시가 필수 지식 참조 없이 선택되는 검사가 실패했고, 주디 BD 예시의 필수 사실과 분석 별칭을 보완한 뒤 26개 검사가 모두 통과했다. 콘텐츠 검사와 문서 링크 131개도 통과했다. 서버 4174를 재시작해 새 자료를 반영했으나 이번 변경의 브라우저 재확인은 연결 시간 초과로 완료하지 못했다. 실제 모델 품질 평가는 수행하지 않았다.

2026-10-01에 인물 선택·설정 시각화를 추가했다. manifest에서 10명을 로드하고 단독 또는 2명 비교를 선택한다. 신념·목표·두려움·금기·생활 경험·말투, 분야별 깊이·근거 상태와 후보 표를 표시한다. 화면과 생성기가 같은 지식 허용 판정을 사용한다. 자동 검사 29개와 콘텐츠 검사, 신규 브라우저 스크립트 구문 검사가 통과했다. 브라우저에서 팬앰 BD 미확인/미주입 이유, 지식 검색, 빅터 단독 모의 요청 1건과 의료 지식 주입 표시를 확인했다. 실제 모델 호출·인물 품질 판정은 수행하지 않았다.

같은 날 비교 화면을 왼쪽 설정·중앙 채팅·오른쪽 특성의 3열로 단순화했다. 10명 카드의 화면 전용 요약은 원본 정체성·생성 입력을 바꾸지 않는다. 자동 검사 30개·콘텐츠 검사·스크립트 구문 검사·수정 문서 링크 검사가 통과했다. 실제 브라우저에서 3열 배치, 2명 모의 응답, 단독 인물 전환, API 설정 표시와 접힌 요청 상세를 확인했다. 이 변경의 확인에는 유료 모델 호출을 사용하지 않았다.

질문 프리셋 6개와 요청 상태·경과 시간·인물별 입력/출력 토큰 표시를 추가했다. 별도 로컬 테스트 제공자로 대기·완료·취소 및 토큰 표시를 확인했으며 외부 모델은 호출하지 않았다. 제공자가 사용량을 반환하지 않으면 0으로 표시하지 않는다. 공식 게임 소개를 확인해 PLAYER_V를 공통 신원 사실로 추가하고 프리셋·화면 화자·모델 문맥의 이름을 같은 데이터에서 읽도록 했다. 자동 검사 34개, 콘텐츠·구문·문서 링크 검사가 통과했고 브라우저에서 V 표시와 프리셋 불러오기를 확인했다. 이름 V만 맞히는 응답은 대화 기억의 증거가 아니므로 기억 품질 평가는 별도의 대화 내용으로 확인해야 한다.

## 2. 개발 순서

### 단기·장기 기억의 적용 순서

2026-10-01에 [NPC 기억 규격 1.0](memory-specification.md)을 작성했다. 단기 문맥·장기 기록·지식 캐시의 구분, 출처 보존, 비동기 정리, 저장 시점 검사, 용량과 전용 요약 계약을 확정했다. 규격 작성이며 코드·DB·워커·유료 요약을 구현하거나 실행한 상태는 아니다. 기존 시제품은 이전 임시 memory 형식을 사용한다.

이번 문서 변경의 로컬 링크 168개·제목 앵커 14개·JSON 예시 1개와 코드 블록 짝 검사가 통과했다. 기존 시제품 자동 검사 34개도 통과했다. 기억 규격의 새 워커·영구 저장·요약 품질·전경 지연을 검증한 결과는 아니며 외부 유료 모델 호출은 하지 않았다.

같은 날 규격 검토 후 기억 규격을 1.1로 개정했다. 미정리 원문 조회·사건별 부분 반영, 응답 표시 전 인지·공개·관계 버전 검사, 행동 결과 상태의 단일 기준을 반영했다. 저장 복원은 게임 저장별 전체 기억 묶음 교체로 단순화하고 보관 한도를 8배 확대했다. 항목별 과거 버전 이력·분기 그래프는 구현 대상에 추가하지 않는다. 아래 새 시나리오는 후속 구현의 확인 항목이며 현재 코드가 통과한 시험이 아니다.

1.1 문서 변경 후 로컬 링크 183개·제목 앵커 20개·수정 문서의 JSON 예시 3개·코드 블록 짝·한국어 문서의 잘못된 문자 혼입 검사가 통과했다. 기존 시제품 자동 검사 34개도 통과했다. 새 기억 조회·부분 커밋·저장 연동·용량 정책의 실행 코드는 이번 작업에서 변경하지 않았으며 게임 저장 식별·캡처 경계·성능은 미검증이다.

현재 적용 순서는 [세션 기억 정책](memory-specification.md)을 기준으로 다음과 같다. 위 날짜별 기록은 이전 설계의 검증 이력이며 세부 항목·보호 상태·검색 큐를 현재 구현 의무로 적용하지 않는다.

1. 한 세션의 수용된 전체 발화를 종료 시 요약 하나로 기록한다. 현재 세션 최근 발화와 완료된 세션 요약을 구분한다.
2. 인물별 소유 범위·중복 세션 방지·로드/삭제 후 늦은 요약 폐기를 검사한다. 세부 사실 추출·약속 보호·충돌 관리·복장 이력은 구현하지 않는다.
3. 선택 모델 요약의 중심 화제 보존·주장 표현·한 줄 형식과 실패 시 로컬 기록을 확인한다. 의미 품질·비용은 실제 모델 시험에서 별도 평가한다.
4. 실제 게임 대상과 저장 성공 경계를 확인한 후 정확한 저장 건별 전체 기억 복원을 연결한다. 브라우저 모의 슬롯의 통과로 게임 저장 지원을 판정하지 않는다.

| 게임 로드와 비용·호출 제한 | 기억은 복원되지만 이미 사용한 비용·호출 횟수 유지 |
| 확대된 보관량·원문 한도 | 최신 요약만 전송. 현재 원문 한도 초과 시 종료·새 세션 안내 |

요약 품질은 중심 화제 보존·근거 없는 추가·플레이어 주장 승격 여부를 사람 검수 자료와 비교한다. 모든 세부 내용·약속·외형의 보존은 합격 조건이 아니다. 구조 검사만으로 의미적 정확성을 보장했다고 보고하지 않는다. 기억 평가는 사전에 없는 새 대화 내용을 사용하며 공통 사실인 V의 이름을 맞히는 것만으로 통과하지 않는다.

### 비용·콘텐츠 설계의 확인 기준

- 일상·관계·긴 설명 입력의 실제 토큰을 측정해 설정 예산 안에서 정체성·현재 질문·인지 제한이 유지되는지 확인한다.
- 같은 시나리오를 기존/최적화 입력으로 비교해 정상 응답당 비용, 입력/출력/캐시 토큰, 첫 생성 조각·검증 완료 시간, 실패·재시도 비율을 기록한다. 가격표·모델·버전·조건을 함께 고정한다.
- 무기·기업·BD·동료를 버리는 제안·유명세 주장·재접촉·숨은 퀘스트 질문을 여러 카드에 제시한다. 말투뿐 아니라 선택·거절 이유가 달라지는지 확인한다.
- 원작 사실과 창작 생활 설정을 뒤섞거나, 모르는 플레이어를 가족·연인으로 취급하거나, 모든 군중이 유명 인물의 비밀을 아는 응답은 비용이 낮아도 탈락시킨다.
- 예산 차단·미확정 취소 비용·앱 재시작·캐시 미적중·중복 요청에서 추가 호출과 행동 중복이 없는지 확인한다. 실제 유료 시험은 설정된 사용 한도 안에서 수행한다.

### 게임 통합 순서

1. 규격 데이터와 모의 게임 상태로 콘텐츠 로드·요청 조립·응답 검사·기억 분리를 구현한다.
2. 게임 PC에서 대상 조회·NPC 분류·보호 상태·키·비동기 통신 어댑터의 연결 가능성을 확인한다.
3. AI 없이 고정 대사로 군중의 기본 반응→추가 선택지와 커뮤니티 기존 선택지→제어 반환을 구현한다. 실제 대사 자막·멈춤·V 시선·해제와 게임 시간 진행·위험 종료를 확인한다.
4. 표시 복장/텍스트·관찰 가능 조건, 평판 규칙·진행도별 원작 맥락을 매핑한다. API·인물·기본 로컬 정리·단기/장기 조회·군중 재접촉을 연결하고 추가 행동은 선택 전용으로 시험한다.
5. 정확한 저장 건·캡처 경계·고유 인물 기억 묶음 보관/로드 복원을 통합하고 최신 초기 출시 조건을 판정한다. 저장 연동 실패를 완료 기능으로 숨기지 않는다.
6. 기존 게임/모드의 공개 호출·호환·취소·복구를 확인하고 제스처/표정/생활 동작·이동을 execute로 확대한다. NPC 음성은 확정 자막과 함께 별도 단계로 통합한다. 유료 요약·로컬 모델·차량/거래도 독립 지원 조건을 갖춘 뒤 확장한다.

군중 대상 성공을 전용 생성 NPC의 성공으로 대체하지 않는다. 특정 기능 실패 시 제품 범위를 바꾸기 전에 실패 원인과 영향 대상을 기록한다.

## 3. 규격 검사

### 조사 콘텐츠 묶음

`content/cyberpunk2077/`에 인물 10명·사실·인지 조건·작성 예시·군중 지식 묶음을 저장했다. `node scripts/validate-content.mjs`로 JSON·ID·출처·조건·소유 인물·예시 참조와 군중 비밀 지식 제외를 검사한다. 주디·팬앰의 개발용 로더·정규화·선별을 연결했다. 실제 게임 키·단계 매핑, 원작 장면·한국어 문체 검수, 군중 지식 배분기는 남아 있다. 전체 게임의 모든 원작 자료를 확보한 것으로 기록하지 않는다.

다음 콘텐츠 작업은 군중 원형별 Big Five 생성 프로필·판단 규칙·문체를 작성하고 승인된 직업·지역 지식을 연결하는 것이다. 선택 지식의 첫 생성 추첨과 재접촉 고정, 상식·필수 전문 지식 유지, unknown 조건 차단을 검증한다. 인물별 조사 근거·보류 항목은 [조사 안내](community-npc-catalog.md)에 둔다.

### 캐릭터 정체성 비교

전환 전 정체성 구조 1.0의 호환 검사에서는 군중 슬롯별 한 후보·총 3개, 조합 조건·금기·문체 호환성, 유효한 기본 조합, 동일 seed·콘텐츠·생성기 버전의 재현, 재접촉 시 데이터 재사용, 무효화 후 새 등록을 확인한다. 커뮤니티 인물에 무작위 특성이 적용되거나 상황 변화로 고정 가치가 재추첨되면 실패다. 원형·특성·규칙·예시 참조와 승인 상태도 검사한다.

신규 경로에서는 다섯 수준·공통 변환표·군중 가중 조합/기본값·seed 재현을 별도로 검사한다. 기존 세 슬롯을 자동 환산하거나 두 성격 경로를 동시에 주입하지 않는다. 수치 검사의 통과가 원작 인물의 실제 성격 승인이나 목표 반응 빈도 보장을 의미하지 않는다.

### 대화 평가 수행 계획

점수 축·중대 위반·근거 수준·데이터·합격선의 기준은 [대화 정체성 평가 규격](dialogue-evaluation-specification.md)이다. 이 절은 수행 순서만 정의한다. 현재 카드는 draft이며 출시 원작 충실도 평가에 필요한 장면·한국어 말투 자료는 미완성이다. 평가 자료와 실행기도 아직 구현하지 않았고 AI 평가 요청·유료 생성 시험은 이번 작업에서 수행하지 않았다.

1. 주디·팬앰을 먼저 대상으로 정하고 검수자가 원작 장면·관계·인지 근거를 작성한다. 새 상황의 허용 반응은 authored_approved로 구분한다. 카드 작성자가 자신의 창작 대사를 원작 정답으로 승인하지 않는다.
2. development 세트에서 사례별 적용 축·허용 선택·금지 주장·기억·상태를 고정한다. 초기는 인물당 30개 사례를 목표로 한다. 가치 6, 지식 4, 관계 4, 일상·문체 4, 기억 4, 압력 4, 상황 적응 4개다. 사례는 여러 축을 평가할 수 있다. 2명 총 60개를 각 설정에서 3회 반복하되 다중 턴 사례의 실행 1회는 전체 대화 경로를 뜻한다. 비용 한도 승인 후 실행하며 180개 실행이 180개 독립 장면 근거라는 뜻은 아니다.
3. 카드만 / 관련 지식 추가 / 관련 지식·예시·상기 추가 구성을 비교한다. 생성 모델·입력·게임 상태·콘텐츠·관계·출력 한도를 고정하고 현재 시제품에 기능을 연결한 뒤 실제로 조립된 프롬프트를 보관한다. 한꺼번에 모델·콘텐츠·프롬프트를 바꾼 결과로 원인을 단정하지 않는다.
4. 평가자 보정용 calibration 자료는 별도 장면군에서 만든다. 초기 50개 응답(중대 위반 20, 정상 20, 경계 10)을 목표로 하고 두 사람이 독립 판정한다. 인위적으로 균형을 맞춘 보정 자료의 실패 비율을 실제 서비스 실패율로 보고하지 않는다. 사람 불일치는 근거로 조정하고 AI 평가자의 점수·위반 탐지·편향과 비교한다.
5. AI 채점의 초기 사용 승인 목표는 핵심 축의 선형 가중 kappa 각각 0.6 이상, 확인된 중대 위반 탐지 재현율 95% 이상이다. 프로젝트 보정 목표이지 논문이 보증한 기준이 아니다. 표본 수·오탐·A/B 순서 불일치도 기록한다. 미달하면 AI 점수를 최종 판정에 사용하지 않고 사람 검수를 유지한다. 작은 표본의 목표 충족만으로 신뢰성을 확정하지 않으며 release의 중대 위반·보류는 사람이 확인한다.
6. 세트·루브릭을 고정한 후 분리된 release 장면군으로 지원 후보를 판단한다. 근거·임계값의 변경은 평가 버전을 올리고 같은 구성들을 재평가한다. 실제 결과 전에는 모델별 통과율·지원·학습 필요성을 확정하지 않는다.
7. 두 인물에서 평가가 작동하면 나머지 8명으로 확장한다. 군중은 승인 원형과 추첨된 정체성에 대한 일관성을 평가하고 대표 조합·충돌 경계·기본 조합·재접촉·무효화를 포함한다. 생성 seed와 선택 지식은 고정해서 비교한다.

위 사례 수·반복·보정 목표는 파일럿 계획이다. 자동으로 비용을 사용하는 작업 예약이 아니다. 지연·비용·요청 실패·대체 대사 사용률은 생성 품질과 따로 집계한다. 원작 장면·질문은 예시/학습 자료와 장면군 단위로 분리한다. 조사 근거는 [정체성 벤치마킹 분석 8절](character-identity-benchmark.md#8-대화-평가-연구와-적용-근거)에 둔다.

| 항목 | 검사 |
| --- | --- |
| 콘텐츠 | 중복 ID·누락 참조·잘못된 조건·지식 공개 오류 |
| 요청·응답 | 길이 제한·열거값·허용 행동·중복 실행·늦은 응답 |
| 기억 | 같은 인스턴스 재사용, 다른 NPC·저장 계보에 누출 없음 |
| 모델 | 동일 사례의 인물별 판단·말투·금기·스포일러·형식·비용·지연 |
| 개인정보 | 키·인증 헤더·기본 대화 원문이 로그에 없음 |

모델 품질은 캐릭터 두 명에게 동일 사건을 제시하고 목표·판단·행동 차이를 비교한다. 형식 검사를 통과하는 것만으로 콘텐츠 품질 통과로 처리하지 않는다. 지원 모델 목록은 실제 결과를 기록한 뒤 작성한다.

## 5. 지원 판정과 기록

시험 결과는 게임·프레임워크 버전, 코드 커밋, NPC 레코드·유형, 자산, 장소, 시작 상태, 명령 결과, 중단·복귀 결과를 기록한다. 기본 행동의 제어 반환과 원작 보호가 실패하면 해당 대상은 지원 목록에서 제외한다.

출시 조건은 시험 범위에서 충돌·복구 불가 NPC·퀘스트 진행 변경·무단 행동·기억 누출이 없고 설치·제거 안내와 지원 버전이 존재하는 것이다. 모델·네트워크 성능과 자산 호환성은 미측정 상태를 명시한다.

### 6.3. 추가 수용 시험과 미확인 항목

아래는 향후 시험 항목이며 이번 문서 수정으로 통과한 결과가 아니다.

- 군중 기본 반응→선택지→AI와 커뮤니티 원작 선택지→안전한 제어 반환. 취소·거리 이탈·강제 연출 시 원작 선택지/플래그 불변 확인.
- 의상/장비 외형 덮어쓰기·설명 미제공·시야 불명·첫 만남에서 관찰 근거와 모름 처리 확인.
- 옷 A를 본 고유 인물과 군중에 옷 B로 재접촉. 다른 NPC·이전 저장·미래 기억 혼입 차단.
- 원작 관계를 고정한 무례한 대화·재접촉·평판 임계 전후 비교. 기억은 이어지지만 누적 관계 점수 없이 공개 인지 조건만 변경.
- 허용된 일상 이야기의 재질문·요약·로드. 원작 사실/전문 경험/실제 게임 결과 승격 차단.
- 자막 화자/순서/중복·대기 중 게임 시간·위험 중단·멈춤/시선 해제 확인.
- 추가 행동 selection_only와 기본 제어 execute의 혼합. 추가 제스처 실제 명령·성공 기억 없음 확인.
- 후속 외부 모드 미설치·버전 불일치·골격/슬롯 점유·취소 실패·중복 실행·제어 반환 시험.

게임이 없는 현재 환경에서는 선택지 주입·제어 반환, 실제 표시 복장/아이템 설명, 원작 단계·관계·평판 임계, 정확한 저장 건/경계, 게임 자막, 외부 모드 호출/취소·호환성은 미검증이다. 대표 인물의 전체 원작 장면·한국어 말투와 일상 허용 정책도 출시 검수 대상이다. 새로운 연동 모드를 검증 완료나 필수 의존성으로 지정하지 않았다.

### 6.4. 이번 개정의 로컬 검사

2026-10-01 개정 후 프로젝트 Markdown 21개를 검사했다. 로컬 링크 250개·제목 앵커 48개·JSON 예시 4개·코드 블록 짝·요구사항 P01~P18·AGENTS.md의 전체 기준 문서 색인이 통과했다. 첫 검사에서 발견한 행동 연동 제목 앵커 4곳과 요구사항 표 구분 오류 1곳은 수정 후 통과했다. UTF-8 BOM·깨진 문자와 의도하지 않은 다른 언어 문자 혼입은 없었다.

기존 시제품의 `npm test` 34개와 `node scripts/validate-content.mjs` 콘텐츠 검사가 통과했다. 콘텐츠 검사는 출처 35개·인물 10명·사실 53개·지식 154개·예시 20개·묶음 13개를 확인했으며 카드 JSON·승인 상태는 변경하지 않았다. 새로운 게임 기능·저장소·행동 어댑터를 구현하거나 게임/외부 모드에서 시험한 결과가 아니다. 실제 유료 모델 호출과 외부 쓰기는 수행하지 않았다.

규격의 세부 계약은 분야별 기준 문서에 두고 전체/초기 명세와 지침에는 범위·제약·참조를 연결했다. 조사·구현 가능성 문서는 과거 근거를 보존하고 새 요구의 미확인 범위를 표시했다. 남은 구현·자료 검수 항목은 6.3절과 각 적용 순서를 따른다. 정적 문서 검사와 기존 시제품 회귀 검사는 새로운 게임 기능의 구현 검증을 대신하지 않는다.

### 6.5. 인터뷰 요구를 시험하는 웹 시제품 갱신

2026-10-01에 `/compare`를 갱신했다. 추가 대화 버튼의 모의 진입, 복장 이름/외형 입력과 관찰 여부, 인물별 목격 사건, 현재 단계·관계의 canon_context, 공개 이름 인지 플래그, 일상 자기보고 정책, 기본 가상 제어와 추가 제스처 선택 표시를 연결했다. 원작 카드 10명 외에 기존 창작 군중 2명을 시험 대상으로 추가하고 동일 인스턴스 관심사를 표시한다. 이 군중은 기존 풀 예시이며 Big Five 생성·군중 지식 배분의 완성판이 아니다.

모의 슬롯 A/B는 저장 순간의 완료된 고유 인물 원문 사건·상황을 복사한다. 로드 시 미래 사건·대기 응답을 버리고 군중 기억·인스턴스는 승계하지 않는다. 상황과 모델을 바꿔도 완료된 원문 기억은 유지한다. 원문 사건은 인물별 512개 시험 한도이며 최근 발화 6개·최근 복장 관찰 2개만 조회한다. 장기 요약·비동기 워커·영구 저장·게임 저장 연결은 구현하지 않았다. 실제 역할과 제한은 [시제품 안내](dialogue-prototype.md)가 기준이다.

자동 검사 44개가 통과했다. 새 검사는 미관찰 복장·다른 NPC 혼입 차단, 원작 관계와 자기보고의 분리, 선택 행동의 성공 기록 금지·후보/인수 차단, 저장 복사와 미래/대기 응답 폐기, 군중 이름 인지의 비밀/관계 제한, 위험 중단·거리/만료/세계 경계와 직접 입력 한도를 확인한다. 제공자 시험은 가짜 전송기이며 실제 모델을 호출하지 않았다.

브라우저 모의 시험에서 검은 재킷을 본 뒤 빨간 재킷으로 재접촉해 이전 관찰을 참조하는 흐름, 저장 후 파란색 선호 발화를 추가한 다음 로드해 저장 전 빨간색 발화만 회상하는 흐름, 제스처의 ‘선택·실행 안 함’ 표시, 군중의 이름 미인지/공개 인지와 인스턴스 관심사 표시를 확인했다. 전투 버튼의 대화 종료·재진입 차단도 확인했다. 정확한 대기 요청 중단은 자동 검사로 검증했다. 개인 API/Codex 유료 생성·원작 정체성 평가·실게임 연동은 이번 작업의 검증 결과에 포함하지 않는다.

콘텐츠 검사·공개 JavaScript 구문 검사와 Markdown 21개·로컬 링크 253개·JSON 예시 4개·인코딩/코드 블록 검사가 통과했다. 앱 브라우저 폭에서 3열 배치를 확인하고 741~1050px 구간을 조정했다. 더 좁은 화면의 전체 조합은 이번에 새로 시험하지 않았다. [확인한 웹 화면](../prototype/artifacts/scenario-web.jpg)은 모의 응답과 선택 전용 제스처의 예시다.

### 6.6. 테스트 절차 간소화와 핵심 지식 보강

2026-10-02에 기본 화면을 인물 대화 테스트로 통합했다. 대화 인원은 1명/2명 비교에서 명시적으로 고르며 기본은 1명이다. 질문 전송 때 자동 진입하므로 초안 체크와 진입 버튼을 없앴다. 완료 답변·소요 시간·사용량·주입 지식·검수 메모를 요청별로 보관하고 전체 완료/실패/취소/문제 표시/미검수 수를 표시한다. 자동 품질 채점은 하지 않는다. 이전 질문은 접고 당시 답변·프롬프트·선별 자료를 복사해 다음 요청으로 바뀌지 않게 했다. 재접촉은 기억 유지, 새 대화는 선택 인물 기억 삭제, 전체 초기화는 모든 결과·기억·저장 삭제다. 전투와 저장 시험은 접힌 설정에 모았다.

웹 자료에서 10명의 직접 경험·업무·배경 32개를 보강했다. research-0.5는 출처 43개·인물 10명·사실 85개·지식 후보 186개·작성 예시 20개·묶음 13개다. 타로/복싱 분야와 에블린의 BD 기록 실무를 추가했다. 에블린의 편집 실무 후보는 제공 보류로 바꾸었고 일부 개인 배경에 단계 조건을 붙였다. 출처 접근 방식·제약은 [인물 조사](community-npc-catalog.md#2026-10-02-핵심-경험-보강)에 기록했다. 카드·인지·문체는 출시 승인 전 초안을 유지한다.

자동 검사 48개와 콘텐츠·JavaScript 구문 검사가 통과했다. 새 검사는 이전 결과 스냅샷의 불변성, 상태별 검수 요약, 타로/기록 경험의 인물 분리, 에블린 편집 경험 차단과 개인 배경의 단계·인지 조건을 확인한다. 새 지식의 넓은 검색어가 BD 질문에 화물 지식을 섞는 문제와 에블린 분야 상한 변경으로 편집 후보가 열리는 문제를 발견해 수정한 뒤 통과했다.

브라우저 모의 시험에서 1명 자동 시작, 2명 독립 비교, 인원 변경 후 과거 검수 의견 유지, 새 질문에서 이전 질문 접기, 재접촉 후 파란색 선호 회상과 새 대화 뒤 기억 삭제를 확인했다. 주디의 보정/편집과 에블린의 기록/주디 협업 지식이 각각 주입되는 것도 확인했다. 1280px에서 나란한 답변 배치와 가로 넘침 없음을 확인하고 앱의 좁은 화면에서도 세로 비교를 확인했다. 취소·저장·미래 응답 폐기는 자동 검사로 검증했으며 짧은 모의 응답의 브라우저 취소 시도는 완료가 먼저 발생해 대기 중 취소 증거로 사용하지 않는다. 실제 모델 품질·유료 생성·게임 연동은 이번 검증에 포함하지 않는다.

### 6.7. Big Five의 실제 웹 요청 연결

2026-10-02에 베이스·조립기를 0.6, 콘텐츠를 research-0.6으로 갱신했다. 인물 10명에 원작 공식값이 아닌 독립적인 작성 수치·개인 원칙 초안을 추가했다. 기존 identity·구조 1.0은 조사·호환 자료로 보존하며 현재 웹 요청에서는 제외한다. 화면은 다섯 축의 수준과 공통 변환 문구를 표시하고 개인 원칙·현재 목표·말투는 별도로 표시한다. 숫자·변환 버전은 로컬 메타데이터로 보관하며 실제 전송 본문과 구별한다.

공통 25문구와 적용 규칙을 기준 문서와 대조하며, 조립 결과에는 선택 문구 다섯 개만 넣는다. 누락·범위 밖·실수·추가 축·지원하지 않는 표 버전은 context_unavailable로 막는다. 군중 예시 2명에는 작성된 가중치·금지 조합·유효 기본값·생성 버전과 seed 추첨을 연결했다. 같은 인스턴스에서 턴·재접촉으로 수치를 다시 생성하지 않는다. 관심사는 별도 생활 소재이며 핵심 성격의 대체 슬롯이 아니다. 원작/원형 수치 검수·군중 지식 배분·실제 NPC 매핑은 미완료다.

OpenAI의 instructions/input 분리를 유지하고 현재 웹의 Codex app-server는 베이스를 developerInstructions에, 역할별 데이터를 turn/start.input에 나눠 보낸다. 설치된 실행기가 내보낸 로컬 JSON 스키마에서 ThreadStartParams.developerInstructions의 문자열 지원을 확인했다. 가짜 전송기를 통해 두 제공자의 본문·채널 분리와 기존 취소·요청 격리를 검사했다. 실제 모델 생성 호출은 하지 않았다.

자동 검사 53개와 콘텐츠 검사가 통과했다. 브라우저 모의 시험에서 주디의 다섯 수준·문구와 요청 본문의 일치, 기존 identity/수치의 미전송, 군중의 진입 전 미생성 → 진입 후 생성 → 재접촉 시 같은 수준 유지를 확인했다. 게임 상태·원작 관계/과거 사건, 장기 기억 요약·검색, 토큰 예산 절감과 모델 품질은 이번 구현·검증에 포함하지 않는다.

수정된 텍스트 40개를 UTF-8로 읽고 깨진 문자·BOM, JavaScript 구문·JSON 파싱과 로컬 문서 링크 116개를 검사했다. [Big Five가 적용된 웹 화면](../prototype/artifacts/personality-web-review.png)은 앱의 기본 화면 폭에서 확인한 모의 비교 결과다.

### 6.8. 로컬 API 키 자동 참조

2026-10-02에 사용자가 요청한 클립보드의 개인 키를 Git 제외 대상인 루트 .env에 저장했다. 서버 직접 실행과 npm start 모두 시작 시 로컬 파일을 읽으며 기존 환경 변수가 있으면 우선한다. 브라우저에 키 값을 전달하지 않고 설정 여부만 알려주며 입력이 비어 있으면 서버 키를 사용한다. 키 변경은 서버 재시작 후 반영한다. .env.example은 빈 형식만 제공한다.

자동 검사 54개가 통과했다. 가짜 키로 파일 로드·환경 우선순위·파일 누락·빈 입력의 서버 키 사용·응답 미노출·/.env 접근 차단을 확인했다. 실제 서버 재시작 후 저장된 키 인식과 빈 입력의 자동 사용 안내를 확인했다. 키 값 출력·Git 등록·실제 유료 모델 호출은 하지 않았다. [자동 사용 안내 화면](../prototype/artifacts/saved-api-key-status.png)에는 키 값이 없다.

### 6.9. 외부 모드 제스처 조사

2026-10-02에 [외부 모드 제스처·애니메이션 조사](external-animation-research.md)를 추가했다. AMM의 Collab 구조·배포 미러 내부 재생/중단 함수, CyberScript 제작자 페이지에서 연결된 저장소의 동작 실행/중단과 골격별 자원 목록을 확인했다. 두 저장소의 확인 커밋을 고정하고 실제 이름 15개를 원본 목록과 대조했다. 표정 팩·Photo Mode 프레임워크·전역 idle 교체·짝 포즈의 적용 한계도 기록했다.

### 6.10. 저장된 키의 연결 오류 복구

2026-10-02에 키 설정이 있는 서버에서 외부 요청이 EACCES로 차단되는 것을 재현했다. 외부 연결이 허용된 실행 환경에서는 키 없는 조회가 HTTP 401로 도달했고, 저장된 키의 모델 목록 조회는 HTTP 200과 기본 모델 접근을 확인했다. 기존 제한 환경의 서버를 종료하고 외부 연결이 가능한 환경에서 같은 로컬 주소로 재실행했다.

OpenAI 제공자의 연결 권한 거부(EACCES·EPERM)는 network_blocked로 구별하고 웹에서 인증 실패·일반 연결 실패와 다른 한국어 안내를 표시한다. 원문 오류·키 값은 전달하지 않는다. [OpenAI 공식 오류 안내](https://developers.openai.com/api/docs/guides/error-codes)도 참고했다. 자동 검사 55개, JavaScript 구문과 Git 변경 공백 검사가 통과했다.

재실행한 서버의 빈 키 입력 경로로 존재하지 않는 시험 모델을 지정해 제공자의 요청 거부가 반환되는 것을 확인했다. 이는 실제 서버의 외부 연결·저장 키 사용 경로 확인이며 유료 생성 성공 시험은 아니다. 실제 대화 생성·과금·인물 품질 시험은 수행하지 않았다. 서버 재시작 뒤 기존 페이지는 새로고침으로 요청 토큰을 갱신해야 하며 기존 테스트 기록은 새로고침 전에 복사한다.

### 6.11. 복장 변화의 다음 답변 연결과 기억 전달 표시

2026-10-02에 복장 관찰 두 개가 전달되어도 변화를 먼저 언급하는 계약이 없는 문제를 수정했다. 같은 NPC의 이전/현재 관찰을 observations.outfit_change로 제공하고 베이스·조립기 0.7에서 복장을 직접 묻지 않아도 다음 답변에서 짧게 알아차리도록 지시한다. 완료 요청에 전달한 관찰 참조는 로컬 원문 사건에 보관하며 모델에는 보내지 않는다. 같은 변화의 반복 전달을 막고 실패·취소 후에는 다시 전달한다. 실제 답변에서 변화를 언급했는지는 자동 판정하지 않는다.

회귀 검사 세 개로 문제를 먼저 재현한 뒤 수정했고 자동 검사 총 58개가 통과했다. 실제 직렬화된 프롬프트의 이전/현재 복장, 최근 발화·관찰 개수와 화면 진단 값의 일치, 재접촉 후 반복 전달 차단, 실패·취소 후 재전달, 미관찰·다른 NPC·기억 삭제 경계, 같은 이름의 외형 변경과 저장 복원 시 미래 전달 상태 폐기를 확인했다. 콘텐츠 검사와 수정 JavaScript의 구문 검사도 통과했다.

별도 브라우저 탭의 모의 시험에서 검은 재킷으로 대화한 뒤 빨간 재킷으로 바꾸고 ‘요즘 어떻게 지내?’를 보내면 복장 반응과 ‘최근 발화 2개·복장 관찰 2개·이전 복장 → 현재 복장’이 표시됨을 확인했다. 다음 질문에서는 변화가 반복되지 않고 최근 발화 4개로 늘었다. 이전 결과의 당시 변화 표시도 유지됐다. [확인한 모의 화면](../prototype/artifacts/memory-outfit-review.png)을 저장했으며 사용자 탭의 결과는 새로고침하지 않았다.

원문 저장소 전체를 모델에 보내는 구현은 아니다. 최근 발화 6개·복장 관찰 2개를 JSON 맥락에 선별하며 long_term은 비어 있다. 장기 요약·검색·영구 저장과 실제 게임 복장 수집은 미구현이다. 변경만으로 API를 추가 호출하지 않았고 실제 유료 모델의 복장 반응·인물 품질은 이번 검증에 포함하지 않는다. 갱신한 베이스를 반영하도록 서버를 외부 연결이 가능한 환경에서 재시작했다.

### 6.12. 근거 전달 방식으로 변경하고 장기 기억 정책 구체화

사용자의 후속 요구에 따라 2026-10-02에 6.11절의 강제 복장 반응을 제거했다. 베이스·조립기 0.8은 현재 복장과 인물별 최근 관찰을 자료로 전달하며 observations.outfit_change·모의 대사 접두문·반응 소비 참조·변화 결과 행을 사용하지 않는다. 전달한 최근 발화/복장 관찰 개수와 요청별 본문 복사본은 유지한다. 언급하지 않은 답변을 곧바로 기억 실패로 판정하지 않는다.

[기억 규격 1.3](memory-specification.md)에서 요약 대상·원문 보존·조회 우선순위·정정/충돌·이전 외형/복장/무장 관찰·중복 제거와 정책 1.2를 설계했다. [프롬프트 규격 0.8](prompt-specification.md#41-기억-조회부터-전송까지의-목표-조립-과정)은 스냅샷→로컬 검색→필수 근거→중복 제거→예산 계측→전송의 목표 과정을 정의하고, 정적 인물과 현재 목표/관계의 중복을 분리한다. 게임 정보·비용 규격은 각 기준 계약을 참조한다. 설계값은 측정한 절감율·검색 품질을 의미하지 않는다.

수정한 회귀 검사에서 강제 반응/changed 필드 제거를 먼저 재현했고 수정 뒤 전체 자동 검사 58개가 통과했다. 실제 직렬화된 요청의 현재 복장·과거 관찰, 응답 완료 후 기억 유지, 실패/취소·미관찰·다른 NPC·새 대화와 저장 복원의 경계를 확인했다. 콘텐츠 검사는 출처 43개·인물 10명·사실 85개·지식 186개·예시 20개·묶음 13개로 통과했다.

별도 브라우저 탭에서 복장 변경 뒤 일반 질문을 보냈을 때 기억 개수 표시가 유지되고 모의 대사에 복장 문구를 강제로 붙이지 않음을 확인했다. 화면의 실제 전송 본문을 읽어 현재 빨간 재킷·과거 검은/빨간 재킷 관찰과 반응 지침/변화 필드의 부재를 확인했다. [현재 전달 안내 화면](../prototype/artifacts/memory-policy-review.png)을 저장하고 임시 탭을 닫았다. 사용자 탭은 새로고침하지 않았다. 서버는 갱신한 베이스로 재시작했으며 환경 키 설정은 유지했다.

수정 텍스트 12개의 UTF-8·BOM/깨진 문자·다른 언어 혼입, 로컬 링크 93개·제목 앵커 20개·JSON 예시 4개·코드 블록 짝을 검사했다. JavaScript 구문과 Git 변경 공백 검사도 통과했다.

장기 기억 저장·요약 워커·선별기 1.2·기억 뷰 1.3·외형/무장 과거 관찰·최적화 조립기는 이번 작업에서 구현하지 않았다. 현재 웹에는 최근 발화 6개·최근 복장 관찰 2개의 일부 1.2 뷰가 남으며 현재 관찰과의 중복 제거도 목표 구현이다. 유료 대사·요약 호출, 실게임 연동과 실제 모델의 자발적 관찰 언급은 시험하지 않았다.

| 저장 로드/삭제 중 늦게 완료된 요약 | 미래 기억 재삽입 0. 원래 저장 시점/새 세대의 근거만 조회 |
| 같은 스냅샷·질의·버전 반복 및 정리 지연 | 선택 결과 동일. 전경 요청이 워커를 기다리지 않음. 실패해도 원문 유지 |

선별기 검사는 사람이 정한 필수 근거 ID/제외 ID와 실제 선택을 비교한다. 필수 근거의 포함·권한/시점 누출·중복·총 토큰 상한을 각각 검증한다. 작은/최대 저장소에서 조회·조립 지연의 중앙값/상위 지연과 실제 입력 토큰을 기록한다. 정확한 토크나이저가 없으면 추정값으로 표시하고 정확한 절감률을 주장하지 않는다. 필수 근거를 유지한 기존 조립과 최적화 조립을 같은 스냅샷에서 비교하며, 모델 대사의 자연스러운 언급 여부는 별도 수동 품질 시험으로 평가한다.

### 7.3. 실제 음성 및 게임 검증

한국어 문장 30개 이상을 준비한다. 인사·거절·중간 정정·숫자·주디/팬앰 등 고유명사·영어 혼용을 포함한다. 조용한 환경과 게임 소리 환경에서 동일 문장을 각 3회 녹음한다. 수동 정답과 전사문으로 문자 오류율·고유명사 정확도·의미를 바꾸는 오류를 보고한다. 품질 미달 문장은 확인 모드/사용자 수정으로 처리하며 confidence 추정이나 자동 내용 교정으로 감추지 않는다.

PTT 해제부터 최종 전사와 NPC 첫 음성까지 중앙값/p95를 기록한다. 같은 최종 텍스트·대화 문맥·Luna/TTS 설정의 키보드 경로와 비교하며 음성 인식 추가 지연을 분리한다. TTS 미설치 시 자막까지 측정하고 음성 지연으로 표시하지 않는다. 연결 준비 시간·전사 실패율·음성/LLM/TTS 사용량은 별도 기록한다.

기능 수용: 원치 않는 녹음·중복 제출·다른 세션 반영 0건, 텍스트 경로 보존, 모든 종료에서 마이크/연결 해제. 실측 정확도·비용·지연을 사용자 검수 후 지원 프로필로 등록한다. 게임판은 저장/로드·빠른 이동·NPC 소멸·전투·원작 제어·포커스 상실을 각각 시험한다. 웹 통과로 게임판 완료를 판정하지 않는다.

## 세션당 한 줄 기억 정책 검증 (2026-10-04)

사용자 요구에 따라 [세션 기억 규격](memory-specification.md)을 적용했다. 한 세션의 수용된 전체 발화를 종료 때 짧은 요약 하나로 기록한다. 복장 관찰 이력·세부 사실 추출·약속 보호·중요도·충돌·만료 관리 요구를 제거했다. 인물의 정체성·원작 관계·분야별 지식·인지/비밀 공개·퀘스트 조건은 별도 콘텐츠와 진행 정책을 유지하며 대화 요약으로 변경하지 않는다. 위 날짜별 시험의 세부 기억 정책은 현재 구현 요구가 아니다.

웹은 저장 버전 2로 전환하고 최신 요약 64개를 보관하며 다음 요청에는 최근 3개와 현재 세션 최근 6발화만 전달한다. 새 대화는 이전 요약을 유지한다. OpenAI 모드는 전체 세션을 종료 후 한 번 정리하고 로컬 한 줄을 먼저 저장한다. 모의·Codex 모드와 모델 실패 시의 로컬 기록은 처음/마지막 발화를 짧게 묶는 근사 기록이며 의미 요약 품질을 보장하지 않는다. 이전 버전은 세션 경계가 없어 자동 가져오지 않는다.

자동 검사 98개가 통과했다. 전체 세션 입력·종료 전 정리 없음·빈/중복 세션·한 줄 출력 검증·실패 대체·동시 다음 세션·로드/삭제 후 늦은 요약 폐기를 확인했다. 공통 계약 검사(27개 계약·25개 포트·정상 예시 27개·거부 예시 23개), 진행 정책 검사(12명·63개 단계·82개 의미 후보), 콘텐츠 검사(출처 91개·사실 217개·지식 881개)도 통과했다.

브라우저에서 복장 변경만으로 기록이 추가되지 않고 전체 세션의 요약 하나가 남는지, 새 대화의 기억 유지·모의 저장/로드의 미래 기억 제거·새로고침 복원·각 입력/응답의 화면 갱신을 확인했다. 페이지 오류는 없었다. [확인 기록](../prototype/artifacts/session-memory-check.json), [기억·저장 화면](../prototype/artifacts/session-memory.jpg). 이번 검증은 모의 응답만 사용했으며 실제 유료 요약의 의미 품질·실제 게임 연동은 시험하지 않았다.

## 실제 모딩 도구 조사와 게임판 구현 설계 (2026-10-04)

웹검색과 제작자 문서·GitHub 릴리스·공개 소스에서 RED4ext·redscript·CET·Codeware·WolvenKit·Red Hot Tools·RedHttpClient·RedData·RedFileSystem의 역할과 설치 후보를 확인했다. [도구 조사](mod-tooling-research.md)에 릴리스 링크와 확인 소스 커밋을 기록했다. 구형 redscript 문서 경로의 이동, HTTP/파일 도구 README의 옛 저장 경로, wiki/HEAD/릴리스 간 버전 차이는 검증 범위와 구분했다.

[게임 모드 구현 계획](game-mod-implementation-plan.md)은 Lua 정책/UI·redscript 게임 수집/제어/저장·Codeware 수명/HUD·Native WinHTTP/키 어댑터를 선택한다. 원작 선택지 보존과 입력 소유를 네트워크 연결보다 먼저 검증하고, 재키·빅터·군중 원형 하나부터 G0~G7로 진행한다. 선택지 삽입의 실제 이벤트·퀘스트 내부 ID·실제 게임 데이터는 미검증이다.

게임 저장별 ScriptableSystem의 숫자 앵커와 SaveBundle UTF-8 바이트 배열을 첫 저장 실증 후보로 정했다. String 직접 persistence와 전역 ScriptableService 기억은 사용하지 않는다. 저장 직렬화 순서·한글·배열 크기·과거 저장·모드 제거를 게임에서 확인하기 전에는 게임 저장 지원으로 활성화하지 않는다. 기억 정책은 기존 세션당 한 줄이며 세부 정책을 추가하지 않았다.

공통 계약·콘텐츠·퀘스트 정책 검사가 통과했다. 문서의 로컬 링크/제목 앵커·UTF-8·코드 블록·Git 공백도 검사했다. 공통 데이터 형태·실행 코드·고정 생성/요약 베이스는 변경하지 않았다. 따라서 기존 98개 실행 회귀 검사는 이번 문서 변경에서 반복하지 않았다. 모딩 도구 설치·Windows DLL 빌드·redscript 컴파일·게임 실행·유료 API 호출은 수행하지 않았다. 다음 구현 산출물은 실제 Windows 게임 환경에 연결할 G0 로더와 G1 대상/상태 진단기다.
