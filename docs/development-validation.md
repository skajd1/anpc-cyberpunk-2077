## 3. 개발 순서

### 3.1. 단계와 수용 조건

첫 개발 묶음은 재키의 습격 전 자유 구간, 빅터의 진료소 자유 구간, 군중 원형 하나다. 재키 사망 이후 차단, 빅터 상환/렐릭 진단 분리, 군중 소멸/재접촉을 함께 시험한다. 다른 인물은 식별·진행·선택지·제어·콘텐츠 검수 뒤 하나씩 연다.

| 단계 | 산출물 | 게임에서 통과할 조건 |
| --- | --- | --- |
| G0 | 도구 설치·최소 Lua/redscript 로더·버전 표시 | 컴파일 오류 없음, 시작/종료·기존 저장 정상 |
| G1 | 대상/상태 읽기 진단·모의 대사 | 동일 객체·거리·오리지널 장면 차단. 게임 상태 변경 없음 |
| G2 | 기존 선택지 아래 ANPC 항목·군중 기본 반응·입력 소유 | 오리지널 선택 유지, 중복 실행 없음, handoff 후에만 시작 |
| G3 | 정지/시선·자막·종료/취소/위험 정리 | 전투·이탈·장면·소멸·로드 후 제어/위젯 잔류 없음 |
| G4 | 저장별 앵커/바이트 묶음·한 줄 기록 | 수동/빠른/자동 저장·슬롯 덮어쓰기·과거 로드에 미래 기억 없음 |
| G5 | Native HTTPS/키/취소·비용 계측 | 게임 진행 유지, 로그 비노출, 시한·늦은 결과·플러그인 종료 경합 통과 |
| G6 | 승인 카드·퀘스트/인지 매핑·지원 모델 | 재키 사망 차단·빅터 진단 분리·군중 지식 분리·한국어 인물 검수 |
| G7 | ANPC 소유 파일 배포·제거·지원 표 | 새 시험 프로필 설치/제거·누락 의존성 안내·지원 버전 재현 |

G0~G4는 API 키 없이 진행한다. G5는 모의 제공자/실패 응답으로 구조를 먼저 검사한다. 첫 공개 게임판은 G2~G7을 모두 통과한 대상만 포함한다. 핫키 데모·웹 시험·코어 도구 설치만으로 단계 완료를 판정하지 않는다.

현재 G0~G2는 부분 확인, G3는 자막만 확인, G5는 Native 구현·CI 빌드까지다. G0 종료 안정성, G1 자유 구간·전투·거리·대상 교체·로드 시험이 남았다.

### 3.3. 현재 적용 범위와 남은 검증

- UF-36/37/63·SR-15: 캡처 검수 의견을 공통 프롬프트 0.25에 직접 반영한다. 발화 의도에 맞춘 반응을 앞에 두고 공감의 대상을 V에게 맞추며 의견에는 현재 판단·감정을 먼저 표현한다. 농담·칭찬·경험 장난에 자동으로 사실 확인·기억 부재 설명을 붙이는 지침을 정리한다. 새 원작 과거·관계·게임 수행 권한은 유지하고 웹/CET 공통 베이스·생성물 일치와 자동 회귀, 지적된 6개 상황의 내부 API 확인으로 검증한다. 추가 사람 검수표를 요청하지 않는다.

- 2026-10-27 의견 직접 반영: 공통 프롬프트 0.25에서 발화 의도→인물 반응을 앞에 배치하고 공감의 대상을 플레이어로 명시했다. 의견 질문은 감정·호불호를 먼저, 농담·소문·친근한 놀림은 현재 감상·태도로 받아치도록 바꿨다. unknown 및 카드 response_rules의 적용 범위를 사실·전문 지식 설명으로 분명히 해 일상 반응까지 막는 해석을 줄였다. 기억 부재·경험 부정·과거 발언 부정을 자동 대체 답변으로 쓰지 않도록 정리하고 구어체·화제 전환·두 언어의 화자/대상 일치를 보강했다. 웹/CET 공통 베이스를 쓰며 게임 생성 파일을 재생성했다. 카드의 원작 관계·사실·인지 배분·행동 계약은 이번 반영에서 변경하지 않았다.
- 직접 반영 검증: Node 152개 중 151개 통과·Windows 패키징 1개 건너뜀, 콘텐츠·공통 계약·스토리 검사 통과. 설치된 liblua 5.4를 임시 실행기로 호출해 기존 웹/CET 비교도 실행했다. 실제 API는 `feedback-applied-20261027/` 초기 6응답과 `feedback-applied-final-20261027/` 추가 정리 후 4응답이며 요청·구조·음성 문자열 오류는 모두 0, 45자 초과는 각 3/6·2/4다. gpt-6-luna/none의 단발 내부 확인이며 추가 사람 검수표는 만들지 않았다.
- 내부 대사 관찰의 한계: 마지막 확인에서 의견 질문은 감정 평가로 시작했으나 공감은 여전히 주어 없는 불평처럼 들릴 수 있고 레이스 소문은 일부 인지 유보가 남았다. 화물 선곡 답변은 기억 부재 대신 제공되지 않은 선곡 습관을 말하는 후보가 나왔다. 이 실패를 감추거나 새 원작 사실로 등록하지 않는다. 최초/최종 원시 응답과 지침 해시를 각각 보관하며 자연스러움 전체 개선·사실 충실도·실게임/TTS 수용을 자동 검사 통과로 주장하지 않는다. SR-15는 미해결 상태를 유지한다.
- 2026-10-27 동일 질문 재검수: 사용자 요청으로 `feedback-recheck-025-20261027/`에 기존 12개 상황의 0.24/0.25 응답 24개를 모두 새로 생성했다(gpt-6-luna/none). 기존 0.24 저장 요청을 대조군으로 추출하고 현재 0.25와 질문·이력·관계·지식·예시·읽기·출력 스키마가 같음을 확인한 뒤 공통 지침만 비교했다. 평가 입력 해시는 유지했다. 실패·응답 구조·음성 문자열 오류 0, 검수 가능한 쌍 12개, 45자 초과는 전후 각각 4/12다. 입력 토큰 86970/95154·출력 토큰 1144/1214(전/후)이며 각 안 1회로 전체 품질 우세를 판정하지 않는다.
- 새 검수표는 기존 의견을 미리 채우지 않았으며 이전 검수 파일은 보존한다. `ANPC-동일질문-의견반영후-재검수.html`의 JSON 화면 표시·다운로드 차단 시 대체·클립보드 미지원 시 수동 복사·선택/의견 반영·원본 해시·모바일 너비를 Chromium에서 확인했다. 생성물을 고치거나 재시도해 고르지 않았으며 사람 검수는 대기 중이다.
- 검증은 같은 평가 입력의 웹/CET 최종 선별·금지 항목 차단과 전체 자동 회귀로 한다. 실게임·실제 API·음성 청취·원작 승인·전체 콘텐츠 재작성은 별도 판정한다.

### 4.2. Native 빌드

```bash
git submodule update --init --recursive
```

`game/native/`를 CMake·MSVC x64로 빌드한다. 외부 저장소는 RED4ext.SDK(엔진 연결), RedLib(스크립트 노출), nlohmann/json(JSON)이다. 응답 처리 단위 시험은 CTest의 `ANPC.Provider.Tests`, CI는 `.github/workflows/native.yml`이다.

### 4.3. 웹 시제품

Node.js 22 이상, 추가 패키지 없음. 저장소 루트에서 `npm start` 후 http://127.0.0.1:4173 을 연다. 포트는 `ANPC_PORT`로 바꾼다. 개인 키는 Git 제외 대상인 루트 `.env`에 두며 브라우저에 전달하지 않는다. 연결은 모의 응답/OpenAI/Codex 중 고른다. 서버는 [프롬프트 명세](prompt-specification.md)와 [기억 규격](memory-specification.md)의 ```text 블록을 실행 베이스로 읽으므로 그 블록을 바꾸면 서버 재시작 후 적용된다. `npm run game-bridge`는 개발용 파일 브리지이며 제품 경로가 아니다.

### 4.4. 구현 배치

| 공통 포트 | 게임판 구현 |
| --- | --- |
| TargetResolver.resolve·StateCollector.collect | redscript 수집기 → Lua 공통 Envelope |
| IdentityResolver·PersonaProjector·KnowledgeSelector | Lua의 승인 카드·진행/인지 정책 |
| MemoryStore·MemorySelector | Lua 작업 기억 + redscript 저장별 묶음 |
| SessionSummarizer.propose·MemoryStore.commitSession | 세션 한 줄 정리. 선택 모델 실패 시 로컬 기록 |
| PromptAssembler·ReplyValidator | Lua 공통 스키마/인지/행동 검증 |
| Provider.generate | Lua 제공자 변환 → Native HTTPS → ProviderResult |
| ActionCatalog·ActionSelector·ActionAdapter | Lua 후보/권한 검사 + redscript 기본 제어 |

구현 메모:

- 시선 대상 후보는 TargetingSystem.GetLookAtObject. 기본 제어 후보는 AIHoldPositionCommand·LookAtAddEvent/RemoveEvent.
- 선택지 조사 시작점은 InteractionUIBase.OnDialogsData·DialogChoiceHubs다. 확정 삽입 API가 아니다. Real Talk의 선택 목록 비우기 방식은 쓰지 않는다.
- 퀘스트 변화 감지는 JournalManager/QuestTracker 이벤트이며 요청 직전·수용 직전에 다시 수집한다. 일지 등록만으로 장면 진입·완료·인지를 확정하지 않는다.
- Codeware Session/BeforeSave·AfterSave 이벤트에는 슬롯·성공 정보가 없다. 저장 종류별 호출 순서를 실측한다.
- RedHttpClient는 취소 핸들·요청별 timeout이 없고 콜백이 JobQueue에서 실행된다.
- 게임 필드 매핑은 필드마다 API/fact·journal 경로·변환·지원 빌드·전후 저장 증거를 남긴다. 미검증 후보에 값을 추정해 채우지 않는다.

- 일상·관계·긴 설명 입력의 실제 토큰을 재고 예산 안에서 정체성·현재 질문·인지 제한이 유지되는지 본다.

- 오리지널 사실과 창작 설정 혼동, 모르는 플레이어를 가족·연인으로 취급, 모든 군중이 비밀을 아는 응답은 비용이 낮아도 탈락이다.

## 6. 후속 작업 계획

### 6.1. 대화 평가

기준은 [대화 정체성 평가 규격](dialogue-evaluation-specification.md)이다.

1. 주디·팬앰부터 검수자가 오리지널 장면·관계·인지 근거를 작성한다. 새 상황의 허용 반응은 authored_approved로 구분한다.
2. development 세트는 인물당 30사례(가치 6, 지식 4, 관계 4, 일상·문체 4, 기억 4, 압력 4, 상황 적응 4)로 시작한다. 2명 60사례를 설정별 3회 반복하며 비용 한도 승인 후 실행한다.
3. 카드만 / 지식 추가 / 지식·예시·상기 추가를 모델·입력·상태·출력 한도를 고정해 비교한다.
4. 보정 자료는 별도 장면군 50응답(중대 위반 20, 정상 20, 경계 10)을 두 사람이 독립 판정한다.
5. AI 채점 사용 조건: 핵심 축 선형 가중 kappa 각 0.6 이상, 중대 위반 탐지 재현율 95% 이상. 미달하면 사람 검수를 유지한다.
6. 세트·루브릭을 고정한 뒤 분리된 release 장면군으로 지원 후보를 판단한다. 두 인물에서 작동하면 나머지 인물·군중으로 넓힌다.

### 6.3. 플레이어 음성 입력

기준은 [음성 인식 규격](speech-recognition-specification.md)이다. 규격만 작성했고 구현·실측은 하지 않았다.

| 순서 | 구현 | 완료 판정 |

| 1 | 기존 제출을 submitPlayerText로 추출·입력 세대/잠금 추가 | 키보드 요청 의미 보존, 음성 미설치에서도 기존 동작 |
| 2 | SpeechInput 수명과 가짜 마이크/전사 어댑터 | 모의 수용 시험 통과 |

### 6.4. NPC 음성

기준은 [음성 출력 규격](npc-voice-output-specification.md), 모델 학습은 [파인튜닝 작업 절차](voice-model-finetuning-guide.md)다.

- 직접 API(`gpt-6-luna`·`none`)의 완료 지연 p50/p95를 speech_text 포함/제외로 비교하고, 기본 출력 한도 512토큰이 충분한지 확인한다.
- FPS 상한을 둔 설정(60·144)과 실제 대화 중 짧은 합성에서 FPS 영향을 다시 잰다. 상한 없는 CPU 한계 상태의 연속 합성 실측은 8.2.
- 파인튜닝 v1이 학습에 없던 군중 참조를 기본 모델만큼 따라가는지 군중 참조를 늘려 다시 청취한다.
- Genie 출력 끝 음절 잘림(v1 일부 출력이 소리 도중 끝남)과 EQ 보정 결과를 청취로 확인한다.
- 스트리밍 조각 경계 잡음, 버퍼링 시작 조건(4.2)의 실제 끊김 합계를 Native 구현에서 다시 잰다.
- 인물별 참조 음성을 다시 고른다. 기존 참조는 대사 내용만으로 감정을 붙여 부적합한 경우가 있었다. 참조 풀(3~10초 원작 대사)을 들리는 말투 기준으로 감정·적합성(잡음·다른 목소리·필터·과장·자막 불일치) 수작업 라벨링하고, 감정별 후보 3개 이하를 청취 승인한다.
- 음성 활성 시 대사 45자 안내(프롬프트 0.18~)가 실제 대화 품질을 해치지 않는지 확인한다. 출력 순서는 비교 결과(8.3)에 따라 일본어 우선으로 바꿨다. speech_text 선행 합성은 효과·위험 때문에 보류한다(8.2).

#### 6.4.1. 게임 안 3D 재생 설계안

게임 NPC처럼 화자 위치에서 들리게 하는 두 안이다. A는 개발 배포(DEP-20261008015427·DEP-20261008020223·DEP-20261008021503)로 실게임 3D 재생을 확인했다. Audioware가 없으면 보조 프로세스 2D 재생(DEP-20261008011224)으로 대체한다. 출시 경로를 정해 음성 출력 규격 4~6절과 DIST에 반영하는 일이 남았다. 공통: 합성·버퍼링 규칙(규격 4.2), 자막은 첫 음성 재생과 함께 표시(4.3), 립싱크와 delivery 속도 변경은 범위 밖.

## 8. 실측 기록

### 8.1. NPC 음성 TTS 로컬 실측 (2026-10-06)

조건: GPT-SoVITS 48b1a016 v2ProPlus 제로샷, Ryzen 5 7500F, 게임 끔, 배경 CPU 7~20%. 참조는 빅터 q115의 같은 대사(stringId 0x17a4d484fe4e1000)를 언어별 원본에서 뽑고 게임 자막을 대본으로 썼다. 언어별 3문장, 예열 1회 제외. 실험 폴더는 저장소 밖이다.

| 엔진 | 스레드 | RTF | 첫 음성(문장 분할) | CPU (논리 12스레드 기준) | 최대 메모리 | 모델 로드 |
| --- | --- | --- | --- | --- | --- | --- |
| PyTorch | 4 | 1.18~1.34 | 2.1~3.2초 | 약 32% | 4.0~4.3GB | 15.7~17.4초 |
| PyTorch | 6 | 1.04~1.16 | 1.8~2.7초 | 약 48% | 4.0~4.3GB | 15.7~17.4초 |
| Genie | 4 | 0.66~0.76 | 1.0~1.8초 | 약 33% | 4.6~5.1GB | 7.2~7.9초 |
| Genie | 6 | 0.62~0.66 | 1.1~1.4초 | 약 49% | 4.6~5.1GB | 7.2~7.9초 |

- 엔진·스레드가 같으면 RTF는 언어에 거의 무관(±5%). 청취 비교에서 일본어가 한국어보다 나았다.
- 오독: 일본어 「金」을 キン으로 읽음(가나로 해결). Genie는 영어 "V"를 "five"로 읽음.
- Genie 출력은 앞뒤 무음 0~0.06초라 끝 음절이 잘렸을 수 있다. 결과는 실행마다 달라진다. Genie 2.0.2에는 한국어 발음 변환이 없다.
- 예열하지 않으면 첫 줄이 3.4초 늘어난 사례가 있다.
- "얇은 목소리": 클론은 원본보다 1~8kHz가 1~6dB 적고 125Hz 부근이 3~6dB 많으며 음량이 2.3~3.9LU 작다. F0 차이는 반음 미만.
- 후처리 보정(선형 위상 FIR 511탭·32kHz·지연 약 8ms EQ, 고정 이득 +2.3~+6dB, 피크 -1dBFS): 1/3옥타브 음색 차이(RMS)가 같은 문장 2.0~2.5dB → 0.85~1.15dB, 새 대사 14개 평균 2.61dB → 1.86dB. 파일당 약 13ms. 청취·치찰음 확인은 남았다.
- 설치 크기: Genie 런타임 약 200MB, ONNX 모델 약 230MB, GenieData 약 410MB.

예상 지연 구성(Enter → 첫 음성): 입력 처리 약 0.05초 + LLM 응답 1.5~4초(추정) + 음성 대사 추가 출력 0.2~1.0초(추정) + 검증 0.1초 미만 + TTS 첫 음성 1.0~1.8초(실측) + 게임 중 CPU 경쟁 0.3~0.7초(추정) = 약 3~7.5초.

### 8.2. NPC 음성 파인튜닝 v1·게임 중 실측 (2026-10-07~08)

조건: 파인튜닝 v1(SoVITS 10·GPT 15 epoch, [학습 기록](voice-model-finetuning-guide.md#5-학습-기록)), Genie 2.0.2, Ryzen 5 7500F, 빅터 참조. "게임 중"은 사이버펑크 2077 실행 상태로 게임 혼자 약 7.9코어(시스템 75%)를 쓴다.

| 조건 | 스레드 | RTF(한 번에) | 첫 음성 | 비고 |
| --- | --- | --- | --- | --- |
| 게임 끔, v1 fp32 | 4 | 0.73~0.77 | 문장 분할 0.7~1.8초 | 기본 모델 0.74~0.76과 같음. 로드 7.4초, 최대 메모리 5.1GB |
| 게임 중, v1 fp32 | 4 | 1.32~1.40 | 한 번에 3.7~13.8초, 문장 분할 1.0~2.3초 | 합성 중 시스템 CPU 평균 89%, 최대 97% |
